<objective>
Enrich settled payments with the provider's *actual* fee and settlement figures, off the request path,
idempotently, and flag a visible exception when actual disagrees with expected — without ever
rewriting a historical Order or touching the single paid-writer invariant.

Purpose: D-14 splits expected from actual precisely because the real gateway deduction is not known at
checkout time. This plan is the machinery that closes that gap, and it is also where 07-RESEARCH.md's
confirmed infrastructure drift lands: the `worker/` + pg-boss target the source plan named no longer
exists, so the job runs as a Netlify Scheduled Function over a pure task factory.
Output: an idempotent reconciliation service, its scheduled runner, and the exception path Finance reads.
</objective>

The sweep selects SUCCEEDED `PaymentAttempt` rows whose `reconciledAt` is null, ordered oldest first,
limited to `batchLimit`. For each, it resolves the provider's actual figures through an injected
lookup — Paystack's Verify Transaction response (`fees`, `fees_split`, the settled subaccount amount)

Paystack type crosses out of its adapter directory; the service consumes only a small provider-neutral
`ActualSettlement = { gatewayFeeActualMinor, schoolSettlementActualMinor, platformGrossActualMinor }`
shape, and derives `platformNetActualMinor = platformGrossActualMinor - gatewayFeeActualMinor` itself
in integer arithmetic.

Idempotency rules, all of which the Task 1 cases pin:
- The update is conditional on `reconciledAt` still being null, so a concurrent or repeated invocation
  cannot double-write or double-audit.
- A failed lookup leaves the row untouched — do not set `reconciledAt` on failure, because a Netlify
  Scheduled Function has no retry queue and the next invocation is the retry.
- The batch's return value is `{ reconciled, failed }`.

Variance handling: compare `schoolSettlementActualMinor` against the Order's
`schoolSettlementExpectedMinor` and `gatewayFeeActualMinor` against `gatewayFeeEstimateMinor`, with
the schedule's own rounding rule as the tolerance. On a mismatch beyond tolerance, write an
`exceptionNote` naming both figures and both sides, and emit a domain event and an audit row. Never
update the Order's commercial columns — D-13's immutability is the reason those columns exist, and
"reconcile by rewriting history" is the exact failure this design exists to prevent.

This service must never write a paid status and never call `applyEnrolmentActivation`. Add a header
comment saying so and naming `assertSinglePaidOrderWriter` as the gate that enforces it.
