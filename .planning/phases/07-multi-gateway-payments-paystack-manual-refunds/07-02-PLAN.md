## Pluralization signal: single Cohort price -> dual currency price, single provider -> dual provider

**Noun now primary:** a Cohort's price model becomes two independent, explicitly named currency
fields (`priceNgnMinor`, `priceUsdMinor`), not a generalized array, map, or `CohortPrice[]` child
table keyed by currency code. Likewise `selectedProvider` stays a two-plus-MANUAL enum rather than
becoming a registry of pluggable provider records.

**Decision: `add-alongside`** — NOT promote-to-generic.

**Rationale:** D-01 and D-07 fix this system at exactly two online rails, permanently: `NGN ->
PAYSTACK`, `USD -> STRIPE`, no FX, no learner-selected gateway, one school per deployment.
CONTEXT.md's Deferred Ideas explicitly close the set ("Automatic NGN/USD foreign-exchange
conversion", "Learner-selected gateway independent of currency", "Multi-school tenant management" are
all out of scope). A generic n-many price/provider model would be speculative generality against an
explicitly closed set, and would cost every downstream read a lookup-and-narrow that two named
columns make impossible to get wrong.

**Accepted debt: none.** This is add-alongside-as-correct-fit for a closed two-rail domain, not
add-alongside-as-shortcut. The legacy `priceMinor`/`currency` pair that sits alongside the new fields
*is* transitional, and 07-11 removes it once every read has migrated.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application code -> database | Money values written by any service cross into durable storage here; a calculation bug becomes a permanent wrong number without a constraint |
| migration -> existing production rows | The backfill rewrites commercial data on every pre-existing Cohort |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-07 | Tampering | new monetary columns on Cohort/Order/PaymentAttempt/Refund | medium | mitigate | Named CHECK constraints in `prisma/sql/004_payment_split_integrity.sql`, pasted into the migration and proven by Testcontainers cases that insert a negative value and expect rejection |
| T-07-16 | Tampering | `GatewayFeeSchedule` in-place edit | medium | mitigate | `@@unique([provider, currency, version])` plus a documented immutability rule: a rate change is a new version row, so a snapshotted schedule id/version always resolves to the rule the Order was priced under (PAY-16) |
| T-07-17 | Repudiation | legacy-price backfill | low | mitigate | The backfill is a single, idempotent, guarded `UPDATE ... WHERE ... IS NULL` recorded in a checked-in migration file, so what it did is reconstructable from source rather than from an ad-hoc console session |
| T-07-18 | Information Disclosure | `prisma/seed.ts` fee-schedule rows | low | accept | Fee schedules are non-secret commercial configuration; no provider credential or account identifier is seeded (those live only in `settlement-config.ts`, 07-01) |
