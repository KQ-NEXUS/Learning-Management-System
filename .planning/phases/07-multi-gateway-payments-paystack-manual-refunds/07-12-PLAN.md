Before presenting this checkpoint, Claude has already run `npm run lint`, `npm test` and

  </what-built>
  <how-to-verify>
Run these eight scenarios against real provider test mode. Each is PASS with provider-dashboard or
API evidence attached, or COULDN'T TEST with the reason — nothing in between, and nothing inferred
from a passing unit test. Claude records each result in a new `07-UAT.md` as you report it.

1. **NGN end to end (COH-02, PAY-08, PAY-15, PAY-16, PAY-17, D-25).** A Cohort with an NGN base price
   of 45,000,000 kobo produces a learner total of 45,875,000 kobo. Pay it in Paystack test mode.
   Confirm in the Paystack dashboard: the school subaccount receives NGN 450,000, KQ NEXUS is
   allocated NGN 8,750 gross, Paystack deducts NGN 2,000 from KQ's allocation, KQ nets NGN 6,750.
2. **USD end to end (PAY-08, PAY-17, D-04).** An administrator-entered USD base price produces a
   Stripe Checkout total including the 1.5% fee and the configured estimate; the destination transfer
   equals the base price; the webhook activates the enrolment exactly once. Confirm the fund flow in
   the Stripe dashboard.
3. **Crossed-rail rejection (PAY-08, D-07).** Manipulate a request to pair NGN with Stripe and USD
   with Paystack. Both are refused server-side with no order and no payment attempt created.
4. **Provider event edge cases (PAY-07, PAY-11).** For each provider: a decline, a cancel, a retry, a
   duplicate delivery and a delayed delivery. None produces a duplicate enrolment, a duplicate
   receipt or a duplicate financial effect; ambiguous cases appear as visible exceptions.
5. **Currency change (D-09).** Start an NGN order, then start a USD order for the same cohort. The
   first is superseded, not duplicated: one seat, one live hold, at most one paid result.
6. **Fail closed (D-05).** With the school settlement identifier absent or the provider reporting the
   account cannot receive the intended settlement, checkout fails closed with a support route and no
   unpayable order is created.
7. **Refunds (PAY-05, PAY-13, D-22, D-23).** A full and a partial refund on each provider. Component
   allocation and the provider's actual reported outcome are both recorded; no fee return is assumed.
   Confirm in each dashboard what actually happened to the school's settled portion — this is the
   evidence 07-01's Decision B pointed at.
8. **Receipt immutability (D-13, D-18).** Edit the Cohort's price and the active fee schedule after a
   paid order. The receipt's four lines are unchanged.
