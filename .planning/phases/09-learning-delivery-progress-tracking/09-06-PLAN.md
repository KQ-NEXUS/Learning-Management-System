<objective>
Build the write side of progress tracking: a learner marking or undoing a lesson, the video
watch-position write that auto-completes at 90%, and the staff override with its mandatory reason.

Purpose: LRN-04 requires progress to be idempotent, attributable, timestamped, recalculable and NOT
advanceable by unauthorized requests. LRN-05 constrains manual completion to the permitted lesson,
the enrolled learner, and a valid access window. This is the one module where all of that is
enforced.
Output: `lesson-progress-service.ts` and its unit tests.
</objective>

<planner_rulings>
- **DD-15:** the learner-facing exports (`markLessonComplete`, `undoLessonComplete`,
  `recordWatchProgress`) are ownership-scoped and MUST NOT be wrapped in `withPermission`.
  `overrideLessonProgress` (D-14) IS staff RBAC and MUST be wrapped, on `"enrolments.manage"` with
  `enrolmentCohortScope`. Because this single file then imports the permission choke point at module
  scope, the ownership exports must not be imported by anything on a worker or webhook import
  closure — they are only ever called from Server Actions. State this in the header, citing
  `enrolment-transitions.ts`'s explanation of why ES module imports are whole-file.
- **DD-16 (resolves D-08/Pitfall 2's coupling trap):** manual completion is gated on
  `lesson.allowManualComplete === true` ALONE, regardless of `type`. Auto-video completion is gated
  on `lesson.type === "VIDEO"` ALONE, regardless of `allowManualComplete`. Both may be true for the
  same lesson; the `@@unique` constraint makes either source idempotent.
- **DD-17:** the video completion threshold is 90 percent of `durationSeconds`, evaluated
  SERVER-SIDE from the stored `LessonWatchProgress` row, never from a client-supplied "complete"
  flag. The constant lives here as an exported `VIDEO_COMPLETION_PCT = 90` so the client island can
  import the same number for its caption logic without redefining it.
</planner_rulings>

Otherwise the undo would be undone by the next throttled tick.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server Action entry → progress write | The lesson id, enrolment id and watch position are all caller-supplied; identity must be re-derived from the session |
| staff console → another user's progress record | A cross-user mutation requiring both RBAC scope and a recorded reason |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-02 | Tampering | `markLessonComplete`, `recordWatchProgress` | mitigate | Every write path calls `loadLearnerPath` + `assertLessonOpenable`, re-deriving the enrolment from `actor.userId` and re-checking lock and access window server-side; no client-supplied "unlocked" flag exists in any input type |
| T-09-05 | Tampering | Forged watch percent | accept (documented) | `percentWatched` is computed server-side from clamped `secondsWatched`/`durationSeconds`; the input type carries no percent or completion field. Client-reported POSITION remains trusted at the same level as mainstream LMS video tracking — recorded as a known, accepted v1 limitation per RESEARCH's Security Domain table, not silently ignored |
| T-09-06 | Elevation of Privilege | `overrideLessonProgress` | mitigate | `withPermission("enrolments.manage", enrolmentCohortScope)` — the only wrapped export; a learner reaching it for their own enrolment still receives `AuthorizationError` |
| T-09-07 | Repudiation | Progress mutations | mitigate | Audit rows on mark, unmark and override with actor, before/after and (for overrides) a mandatory non-empty reason |
| T-09-08 | Denial of Service | Watch-progress write volume | mitigate | Upsert on a composite unique means one row per (enrolment, lesson) regardless of write count; the client throttle in 09-12 bounds dispatch rate, and Next.js Server Actions dispatch sequentially per client so a runaway loop self-limits |
| T-09-28 | Tampering | Undo reversed by a stale in-flight write | mitigate | Re-completion requires `percentWatched` to advance beyond the stored high-water mark, so a throttled tick landing after a D-15 undo cannot silently re-complete |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages this phase |
</threat_model>
