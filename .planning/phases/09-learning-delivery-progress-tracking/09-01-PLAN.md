<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| learner browser → app server | Every access-window decision must be made server-side from stored Enrolment/Cohort rows, never from a client-supplied date or flag |
| app server → database | The new `LessonWatchProgress` row is learner-writable data; its identity columns must never come from request input unvalidated (enforced in 09-06, declared here) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-10 | Tampering | `computeAccessWindow` | mitigate | `now` is an explicit input so callers pass a server clock; the module has zero imports and therefore no way to read a client-controlled value |
| T-09-11 | Elevation of Privilege | `LessonWatchProgress` | mitigate | Composite `@@unique([enrolmentId, lessonId])` makes one row per (enrolment, lesson) the only representable shape; the write path (09-06) derives `enrolmentId` from the session actor, never from the request body |
| T-09-12 | Denial of Service | `LessonWatchProgress` growth | accept | One row per (enrolment, lesson) with `@@unique` — bounded by catalogue size, not by write frequency; repeated writes update in place |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | This phase installs ZERO new packages (09-RESEARCH.md "Package Legitimacy Audit": not applicable). No install task exists in any Phase 9 plan; if one becomes necessary, the legitimacy gate must run first |
