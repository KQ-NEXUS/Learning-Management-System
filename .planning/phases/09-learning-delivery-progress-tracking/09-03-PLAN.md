<objective>
Build `learner-access.ts`: the one place this phase resolves "is this enrolment mine, is it usable
right now, and what course structure and completion obligations does it carry".

Purpose: `ResourceScope` (Global/Programme/Course/Cohort) has no user dimension, so every
learner-facing read in this phase is an ownership comparison, not a permission check. This module is
that comparison, written once, so the dashboard, the lesson list, the reading page, the sessions
page and the download route cannot each invent their own slightly different version.
Output: one ownership-scoped service module plus its unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| learner browser → `/learn/[enrolmentId]` | `enrolmentId` is caller-supplied and must be resolved against `actor.userId`, never trusted |
| live catalogue rows → learner obligations | An authoring edit must not retroactively change an enrolled learner's obligations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Information Disclosure | `getOwnActiveEnrolment` | mitigate | Not-found, not-mine and not-ACTIVE all return the identical `null`; a guessed enrolment id cannot confirm another learner's enrolment exists (the T-06-13 rule applied to Enrolment) |
| T-09-02 | Elevation of Privilege | `assertLessonOpenable` | mitigate | Server-side lock + access-window gate that every read and write path must call; `isLessonUnlocked` defaults an unknown lesson id to locked |
| T-09-09 | Tampering | `loadPinnedCompletionRuleSource` | mitigate | Reads `completionRule`/`completionRuleVersion` only from the pinned publication payload with a runtime type guard; a live `Course.completionRule` edit cannot change an enrolled learner's obligations |
| T-09-17 | Information Disclosure | Returned enrolment snapshot | mitigate | `userId` is destructured out of every returned shape, so no consumer can echo the owner id |
| T-09-18 | Elevation of Privilege | Module import graph | mitigate | `learner-access.ts` never imports `withPermission`; a future contributor cannot accidentally satisfy an ownership check with an RBAC grant |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages this phase |
</threat_model>
