<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored `completionRule` JSON → evaluation engine | Untyped `Json?` column contents cross into rule evaluation; an unrecognised shape must fail loudly, not be partially honoured |
| UI lock rendering → server lock enforcement | These are two callers of one function; divergence is the vulnerability |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-13 | Tampering | `evaluateLessonSequencing` | mitigate | One function, two call sites (render + server gate). `isLessonUnlocked` returns `false` for an unknown lesson id, so a crafted lesson id can never default-open |
| T-09-14 | Tampering | `parseCompletionRule` | mitigate | Unknown `version` and unknown rule keys both throw; a Phase-10 assessment criterion injected into a v1 rule cannot be silently dropped to manufacture a pass |
| T-09-15 | Spoofing | Completion evidence | mitigate | The engine takes `completedLessonIds` and a pre-computed `AttendanceComponent` as inputs and has no data access of its own — it cannot be pointed at another learner's evidence; the caller (09-04) owns that scoping |
| T-09-16 | Information Disclosure | Verdict `detail` strings | accept | Details carry only counts and percentages for the learner's own record; no other learner's data is representable in the input type |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages this phase (09-RESEARCH.md Package Legitimacy Audit: not applicable) |
</threat_model>
