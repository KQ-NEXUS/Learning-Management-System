<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → publish/cancel Server Actions | Cohort id, publish token and reason are caller-controlled |
| rendered detail page → unauthorized viewer | The page reveals a cohort's existence, code, seat counts and roster |
| readiness panel → publish decision | If the panel and the gate disagree, staff act on a lie |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-99 | Elevation of Privilege | Treating the disabled publish button as the gate and publishing an unready cohort by direct POST (COH-04) | mitigate | `publishCohortAction` delegates to `publishCohort`, which runs `blockingFailures(evaluateCohortReadiness(...))` server-side and refuses; the button state is documented in-code as a courtesy echo; grep gate proves the action does not evaluate readiness itself |
| T-05-100 | Elevation of Privilege | Publishing with only `cohorts.manage`, or cancelling outside the caller's scope | mitigate | The services are gated on `cohorts.publish` and `cohorts.manage` with a DB-resolved cohort scope; hidden buttons are courtesy only |
| T-05-101 | Information Disclosure | A denial page revealing that a cohort exists — its code, title or seat count | mitigate | `AuthorizationError` calls `notFound()`, identical to a missing record (RBAC-06), matching the Phase-4 course detail behaviour |
| T-05-102 | Tampering | A lost update: publishing or cancelling over another staff member's concurrent edit | mitigate | `expectedUpdatedAt` carried with millisecond precision; the service performs the conditional `updateMany`; `StaleOrderError` maps to the specified reload copy |
| T-05-103 | Tampering | A second copy of the readiness rules in the page or the action drifting from the evaluator, so the panel shows PASS while the gate FAILs (or worse, the reverse) | mitigate | Exactly one `evaluateCohortReadiness` call in the page feeding the panel, and none in the action; the service performs its own evaluation for the gate; both call the same pure function |
| T-05-104 | Repudiation | Cancelling a cohort without the operator understanding the blast radius | mitigate | `ConfirmModal` with `tone="danger"`, a 10-character mandatory reason, and a description stating the live count of active enrolments to be withdrawn (D-31) |
| T-05-105 | Denial of Service | One failing tab query taking the whole record down, hiding the rest of the cohort from staff mid-incident | mitigate | `DetailSection.error` used per tab so a section fails alone, which is why the primitive puts `error` on the section |
| T-05-106 | Information Disclosure | A nav link promising a route that does not exist, or exposing a section a caller cannot use | accept | Both new routes exist by this wave and each performs its own authorization; the nav is presentation only |
</threat_model>
