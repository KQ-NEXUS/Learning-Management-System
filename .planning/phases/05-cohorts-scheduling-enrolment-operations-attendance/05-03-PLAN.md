## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| readiness evaluation → publish decision | The evaluator's output is the gate; a divergent second copy would leave the real gate unenforced |
| pinned catalogue snapshot → live catalogue record | A pin can point at a record that was later unpublished |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-11 | Tampering | A cohort published against a draft or unpublished Course/Programme sells obligations that are not frozen | mitigate | New `catalogue` slot, `blocking: true`, FAIL unless `pin.publicationId` is set AND `pin.targetStatus === "PUBLISHED"` (D-29); asserted in `tests/cohort-readiness.test.ts` |
| T-05-12 | Tampering | An overselling cohort published while `seatsTaken > capacity` | mitigate | `capacity` slot FAILs when `capacity < seatsTaken`, `blocking: true` |
| T-05-13 | Repudiation | A silently-assumed PASS on a category this phase does not evaluate, hiding a real gap | mitigate | Every cohort slot is a real check; no `NOT_YET_CHECKED` in the cohort evaluator; grep gate proves `deferredTo: "Phase 5"` is gone |
| T-05-14 | Tampering | Readiness rules duplicated inside a server action would drift from the panel, making the on-screen state a lie | mitigate | Pure evaluator with zero imports (grep gate); plan 05-15's action calls `blockingFailures(evaluateCohortReadiness(...))`, never its own rules |
| T-05-15 | Information Disclosure | A `detail` string leaking data a scoped user should not see | accept | Details name only the cohort's own fields (capacity, seat count, delivery mode) — the caller already holds `cohorts.view` on that cohort |
