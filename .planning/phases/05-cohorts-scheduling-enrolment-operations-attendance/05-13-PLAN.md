Build the Sessions tab (list, add, repeat-weekly, soft-cancel) and the per-session attendance marking
screen with its commit-once save and post-window correction flow.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → attendance Server Action | The whole entry payload, including learner ids and states, is caller-controlled |
| browser → session Server Action | Times, meeting URL and an optional course id are caller-controlled |
| rendered session list → viewer | The meeting link is a join capability |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-83 | Tampering / IDOR | A crafted POST to `saveAttendanceAction` carrying an enrolment id from another cohort (ATT-01, D-10) | mitigate | The action performs no roster resolution of its own and delegates to `saveSessionAttendance`, which derives the roster from the session's own `cohortId` and refuses the whole batch on any foreign id; grep gate proves no timing/roster logic in the action |
| T-05-84 | Tampering | Bypassing the disabled pre-start controls with a direct POST of `PRESENT` (D-09) | mitigate | `PreMarkingStateError` is raised server-side; the disabled radios are documented as a courtesy echo; the action maps the error to the specified copy |
| T-05-85 | Repudiation | Editing attendance after the window through the bulk path, avoiding the correction reason (ATT-03) | mitigate | Post-window changes are routed to `correctAttendanceAction` per change with a `minReasonLength: 10` modal; the service enforces the reason regardless of which action is called, and the DB CHECK backs it |
| T-05-86 | Information Disclosure | The Sessions tab or list payload leaking `meetingUrl` to a viewer outside the visibility window (D-25) | mitigate | `listSessionsForCohort` omits the field; the Mode/link column shows presence only; grep gate proves no `meetingUrl` in `SessionsTab.tsx` |
| T-05-87 | Information Disclosure | `LearnerNotOnRosterError` echoing the offending enrolment id back to the client, confirming an id from another cohort exists | mitigate | The action maps it to a generic "This register changed. Reload and try again." without the id |
| T-05-88 | Elevation of Privilege | Relying on the staff layout guard rather than the action's own permission check | mitigate | Every action delegates to a `withPermission`-gated service (`attendance.manage`, `cohorts.manage`) with a DB-resolved session scope |
| T-05-89 | Tampering | A client-computed UTC instant for a session time, drifting from the cohort's declared zone | mitigate | The client submits date and time strings; conversion happens server-side with the cohort's `timezone`; every input is labelled with the zone |
| T-05-90 | Denial of Service | An unbounded `occurrences` value on repeat-weekly | mitigate | Bounded 1–52 in both the action schema and the service |
</threat_model>
