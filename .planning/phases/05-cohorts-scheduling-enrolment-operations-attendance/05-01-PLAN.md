<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application → database | Application code may hold a stale or buggy invariant; the database is the last line |
| developer shell → live database | `prisma migrate dev` can offer a destructive reset |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | `prisma/sql/003_cohort_operations.sql` never applied → invariants exist only in the companion file while production has none (RESEARCH Pitfall 2, the documented 001 failure) | mitigate | Paste into the generated `migration.sql` (Task 2) AND assert each constraint name against the joined migration text in `tests/schema-cohort.test.ts` (Task 3) |
| T-05-02 | Tampering | Seat-held ambiguity: `holdExpiresAt` left set on a non-`PENDING_PAYMENT` row would make the seat predicate lie and drift `seatsTaken` | mitigate | `enrolment_hold_expiry_only_when_pending` CHECK; enrolment service must null the column on every exit from `PENDING_PAYMENT` (plan 05-07) |
| T-05-03 | Repudiation | Attendance corrected with no reason — ATT-03's audit trail loses its "why" | mitigate | `attendance_correction_has_reason` CHECK enforces the reason below the application layer |
| T-05-04 | Denial of Service | Interactive `migrate dev` reset destroys Phase-4 seed/publication data the cohorts pin to | mitigate | `--create-only` then apply; explicit instruction to stop and surface any drift prompt rather than answer it; plan is `autonomous: false` |
| T-05-05 | Tampering | Re-creating an already-applied constraint (`enrolment_one_active_per_learner_cohort` etc.) makes the migration fail or duplicates an invariant | mitigate | Task 1 acceptance criterion greps that no existing constraint name is redeclared in 003 |
</threat_model>
