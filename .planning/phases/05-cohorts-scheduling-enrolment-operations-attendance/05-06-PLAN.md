<objective>
Build the scheduled-session service: authorized CRUD, timezone-correct creation, the "repeat weekly ×N"
row-inserter, soft-cancel, optional member-course tagging, and the meeting-link visibility gate.

Purpose: COH-03 is the delivery calendar. Two things here are easy to get wrong and expensive later —
storing a wall-clock or fixed-offset time instead of a UTC instant (`Africa/Lagos` has no DST, so a naive
`+01:00` passes today's tests and breaks for any other zone), and returning `meetingUrl` in a list payload
where an unenrolled or too-early caller can read it.

Note: the existing `src/server/services/session-service.ts` is the AUTH session resolver. This is a
different concern and must be a new file named `scheduled-session-service.ts`.
Output: `scheduled-session-service.ts` and its unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → session create/edit action | Untrusted title, date/time strings, meeting URL, facilitator id, course id |
| learner/staff read → meeting link | The link is a capability: anyone holding it can join the session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-31 | Information Disclosure | `meetingUrl` disclosed to an unenrolled user or before the visibility window (D-25) | mitigate | `isMeetingLinkVisible` enforced server-side in `readSessionForViewer`; `listSessionsForCohort` omits `meetingUrl` from its select entirely; grep gate + unit tests on the boundary instants |
| T-05-32 | Elevation of Privilege | An Instructor creating or cancelling a session on a cohort they do not teach | mitigate | `withPermission("cohorts.manage", sessionCohortScope / cohortResourceScope)` on every mutation; scope resolved from the row |
| T-05-33 | Tampering | Tagging a session to a Course that is not a member of the cohort's Programme, attributing attendance to the wrong obligation (D-24) | mitigate | `SessionCourseNotInCohortError` validated against the cohort's own `courseId` or its `CohortCourse` rows; unit-tested |
| T-05-34 | Tampering | A session time stored with a fixed offset or host-local time, drifting for any non-`Africa/Lagos` cohort | mitigate | `wallTimeToUtc` with the cohort's own `timezone`; grep gate proves no `+01:00` and no `getTimezoneOffset`; exact-instant assertion in the test |
| T-05-35 | Repudiation | Hard-deleting a session, destroying the attendance history attached to it | mitigate | `cancelSession` soft-cancels with a mandatory reason and preserves `AttendanceRecord` rows (D-26); grep gate proves no `delete(` |
| T-05-36 | Input Validation / DoS | An unbounded `occurrences` value inserting a runaway number of rows | mitigate | `occurrences` validated to the inclusive range 1–52 before the transaction opens |
| T-05-37 | Tampering | A partially-applied repeat-weekly batch leaving a broken calendar | mitigate | All N inserts in one `prisma.$transaction`; unit test asserts zero rows on a mid-loop failure |
</threat_model>
