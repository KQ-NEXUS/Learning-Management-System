<objective>
Build the two transaction-level primitives the whole phase depends on: the shared seat-accounting helper
(D-04) and the transactional domain-event outbox — and prove the seat helper against real Postgres.

Purpose: capacity under concurrency is the highest-risk mechanism in Phase 5 (D-05) and the one Phase 6
checkout will call rather than re-implement. Counting enrolments then inserting loses the race; the
`cohort_capacity_not_exceeded` CHECK is a backstop that must never be the thing that fires. The outbox
exists because pg-boss enqueue is not transactional on Prisma 6.19.3, so a bare enqueue can commit a
state change whose event is lost.
Output: `seat-accounting.ts`, `domain-event-service.ts`, a unit test and a Testcontainers integration test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| concurrent requests → shared Cohort row | Two checkouts racing for the last seat |
| request process ↔ worker process | The same seat primitive is called from both; only one has a session |
| application state change → downstream event consumers | An event lost after commit is an obligation nobody fulfils |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-16 | Tampering / business DoS | `takeSeat` overselling a cohort under concurrency (COH-06) | mitigate | `SELECT "seatsTaken","capacity" … FOR UPDATE` on the Cohort row inside `$transaction`, refusal before insert; `cohort_capacity_not_exceeded` retained as backstop; proven by the `Promise.allSettled` capacity-1 test with an explicit assertion that the CHECK never fires (D-05) |
| T-05-17 | Tampering | Duplicate active enrolment on request replay | mitigate | The pre-existing partial unique index is the guard; `takeSeat` translates P2002 to `AlreadyEnrolledError` (D-15); no application pre-check, which would itself be a race |
| T-05-18 | Tampering | SQL injection through the raw lock query | mitigate | Parameterised tagged-template `$queryRaw`/`$executeRaw` only, copying `reorder-service.ts:272`; grep gate proves no `*RawUnsafe` |
| T-05-19 | Elevation of Privilege | `seat-accounting.ts` pulling `@/server/permissions` onto the worker closure, or a synthetic god-actor being minted to satisfy an authorization wrapper | mitigate | Authorization deliberately excluded and documented; grep gate + `tests/boundary.test.ts` in acceptance criteria; the worker path in plan 05-09 audits as `actorType: "SYSTEM"` instead |
