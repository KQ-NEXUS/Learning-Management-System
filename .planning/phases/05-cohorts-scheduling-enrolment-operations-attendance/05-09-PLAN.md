<objective>
Close the COH-06 loop: a scheduled pg-boss job that sweeps expired seat holds, cancels them, and returns
the seats — reusing the Phase-4 worker service and Docker stack.

Purpose: COH-06 requires that "released or expired reservations become available per policy". A
`PENDING_PAYMENT` enrolment holds a real seat (D-01), so without the sweep an abandoned checkout takes a
seat forever and the cohort falsely reads full. The job runs with no request, no cookie and no actor,
which is exactly why it is a named, filter-less, deliberately unauthorized module rather than a synthetic
GLOBAL actor.
Output: the queue constant, the worker-only system service, the handler, the worker wiring, and a
Testcontainers proof.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker process → database | The worker has no session, no actor and no authorization context by design |
| scheduled job → cohort seat counts | A wrong sweep silently frees seats that are legitimately held |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-05-55 | Elevation of Privilege | The hold-sweep runs unauthorized by design (D-03) — a synthetic GLOBAL actor, or a caller-steerable filter, would turn it into a general-purpose write primitive | mitigate | Named `…AsSystem`, no caller-supplied filter of any kind (acceptance criterion), work set resolved internally from `status` + `holdExpiresAt`, audits as `actorId: null` / `actorType: "SYSTEM"` with its own action name; this is safe because it takes no user input and can only perform one transition |
| T-05-56 | Elevation of Privilege | The new job dragging `@/server/permissions` or `next/headers` onto the worker import closure | mitigate | grep gate on the system service; `tests/boundary.test.ts` re-run in two tasks' acceptance criteria; the file imports only `@/server/db`, `seat-accounting.ts`, `domain-event-service.ts` and `audit-service.ts` |
| T-05-57 | Tampering | Sweeping a hold-less `PENDING_PAYMENT` enrolment and wrongly decrementing `seatsTaken` below true occupancy | mitigate | Work-set predicate requires a non-null `holdExpiresAt`; integration case 3 asserts the untouched behaviour; `releaseSeat` floors at 0 |
| T-05-58 | Tampering | A non-idempotent sweep double-releasing a seat on a retried job | mitigate | Convergent work set re-read each run; per-row transaction with a `FOR UPDATE` lock inside `releaseSeat`; integration case 5 asserts a zero-effect second run |

| T-05-60 | Repudiation | A system-performed cancellation indistinguishable from a staff action in the audit trail | mitigate | `actorType: "SYSTEM"` with a distinct `enrolment.hold_expired` action name and the reason `"hold expired"`; asserted in integration case 7 |
</threat_model>
