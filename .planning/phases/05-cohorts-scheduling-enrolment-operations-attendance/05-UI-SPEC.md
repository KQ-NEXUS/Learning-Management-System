# Phase 5 — UI Design Contract

> Visual and interaction contract for Cohorts, Scheduling, Enrolment Operations & Attendance.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase adds no new visual language.** It wires new staff screens onto the
> established "Claude Design primitive spec sheet" system proved across Phases 1–4
> (`src/app/globals.css`, `src/components/primitives/*`, `src/components/catalogue/*`).
> Every token below is *detected from the existing codebase*, not invented here.

## Spacing Scale

Base unit **4px**. Tailwind v4 default step scale; the console is compact so small steps
dominate. Declared values for Phase 5 screens:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/glyph-to-text gap, tight inline stacks (`gap-1`) |
| sm | 8px | Button padding-y, control gaps, badge rows (`gap-2`, `py-2`) |
| md | 12px | Table cell padding-x, filter bar gaps, chip padding (`px-3`, `gap-3`) |
| lg | 16px | Card/panel padding, form field gaps, section gaps (`p-4`, `gap-4`) |
| xl | 20px | Page gutter, detail-page section rhythm (`px-5 py-5`, `gap-5`) |
| 2xl | 24px | Major section breaks inside a record (`gap-6`) |
| 3xl | 40px | Empty / denied / error panel vertical padding (`py-10`) |
| 4xl | 64px | Reserved — page-level separation on wide layouts (unused today) |

**Exceptions (carried from existing primitives — do not expand, but match when extending them):**
- `2px` (`gap-0.5`) and `6px` (`gap-1.5`) micro-gaps for label→value and eyebrow→title stacks inside `DetailLayout`, `ResourceForm`, `ConfirmModal`.
- Sidebar fixed width `224px` (`sm:w-56`) in `src/app/staff/layout.tsx`.
- `10px` / `11px` micro-label font sizes (see Typography exceptions) carry their own `tracking` not spacing.

## Typography

| Role | Size | Weight | Line Height | Applied to |
|------|------|--------|-------------|------------|
| Display (page H1) | 18px (`text-lg`) | 600 | 1.3 | `DetailLayout` record title — cohort detail, enrolment detail |
| Heading (section H2 / table title / dialog title) | 16px (`text-base`) | 600 | 1.35 | `ResourceTable` title, `DetailLayout` `<h1>` fallback, `ConfirmModal` / `PublishDialog` title |
| Body | 14px (`text-sm`) | 400 | 1.5 | Table cell text, form inputs, descriptions, dialog body copy |
| Label / meta | 12px (`text-xs`) | 400 (hints, counts) | 1.4 | Filter labels, hints, secondary counts, breadcrumb, nav |

**Weights — contract is two:** `400` regular and `600` semibold.
**Documented existing exception:** `500` medium is retained *only* on interactive chrome already
using it — button labels, active tab label, `StatusPill`, nav items, table column links. Do not
introduce `500` on body or heading text.

**Micro-label exception (from primitives, match when extending):** `11px` and `10px` uppercase
labels at `font-semibold` with `tracking-wide` / `tracking-[0.12em]` — used for field labels,
readiness category headings, section eyebrows, `DetailFacts` `<dt>`. These are a deliberate
"spec-sheet" device, not a fifth type size for prose.

**Numeric / code content** renders in Geist Mono with `tabular-nums`: cohort codes, seat counts
(`seatsTaken / capacity`), prices (integer minor units → formatted), session date-times, timezone
label, enrolment IDs, reason-length counters, audit timestamps.

## Color

Tokens from `src/app/globals.css` `:root`. Neutrals are Tailwind `zinc-*` used directly.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--background`) | Page background, table body, cards, form surfaces, dialog surface |
| Secondary (30%) | `#fafafa` (`zinc-50` / `zinc-50/60`) + `#e4e4e7` (`zinc-200`) borders + `zinc-500/600` text | Sidebar, table header row, filter bar, empty/denied/error panels, hairline dividers, secondary/meta text |
| Accent (10%) | `#1c4ed8` (`--accent`) / text `#ffffff` (`--accent-contrast`) | see reserved list |
| Destructive | `#b42318` (`--danger`) on `#fdf3f2` (`--danger-surface`) | see reserved list |

**Semantic signal colours (text + glyph + dot only — never fill, never colour-alone):**
- `--success #15803d` — readiness PASS (`✓`), attendance PRESENT dot, `StatusPill tone="success"`.
- `--warning #b45309` — readiness WARN (`!`), attendance LATE, at-risk exception flag, session-outside-cohort-dates.
- `--danger #b42318` — readiness FAIL (`✗`), attendance ABSENT, disputed/corrected exception flag, blocking text.
- `zinc-500` — the genuine third state `NOT_YET_CHECKED` / "not tracked yet · Phase N" (`•`), never a grey tick or grey cross.

**Accent reserved for (exhaustive — never "all interactive elements"):**
1. The single primary button per screen or dialog (`bg-accent`): **Create cohort**, **Save attendance**, **Publish cohort**, **Add enrolment**, **Add session**.
2. `:focus-visible` outline (2px, global).
3. Active tab underline in `DetailLayout` (`border-accent`).
4. Selected-row / bulk-action band (`bg-accent/5`, `border-accent/30`, count text) and checkbox tint (`accent-accent`).
5. The one "Clear all" filters text link in `ResourceTable`.

**Not accent:** row-title links (zinc-900 + underline-on-hover), secondary buttons (zinc border on white),
status, readiness state, attendance state, tab labels themselves.

**Destructive reserved for:** reason-required integrity actions rendered through `ConfirmModal tone="danger"`
— Cancel cohort, Withdraw enrolment, Cancel enrolment, Cancel session, Correct attendance (post-window) —
plus form/dialog error summaries and the FAIL readiness state. **Publish is NOT destructive** (accent, confirm, no reason unless a cohort is migrated).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Create cohort** (Cohorts list header + empty state). Secondary primaries: **Add session**, **Add enrolment**, **Save attendance**, **Publish cohort** |
| Empty state heading | Cohorts: "No cohorts yet" · filtered: "No cohorts match these filters" |
| Empty state body | "Create a cohort to schedule sessions and open enrolment." |
| Error state | "Could not load cohorts. Your filters and sort are kept in the URL, so retrying returns to exactly this view." |
| Destructive confirmation | see per-action table below (all via `ConfirmModal`, `minReasonLength: 10`, tone `danger`) |

**Per-screen empty states:**

| Screen | Heading | Body (+ next step) |
|--------|---------|--------------------|
| Cohorts list | No cohorts yet | Create a cohort to schedule sessions and open enrolment. |
| Sessions tab | No sessions scheduled | Add a session, or set delivery mode to self-paced if this cohort has no live meetings. |
| Roster tab | No one is enrolled yet | Add an enrolment for a comped or corporate learner, or publish the cohort so learners can register. |
| Attendance (per session) | Nothing to mark yet | Attendance opens when the session starts. Before then you can only mark excused or not-recorded. |
| Attendance exceptions | No attendance exceptions | Every past session has a complete register and no learner is below the attendance threshold. |
| Enrolments (global) | No enrolments yet | Enrolments appear here once cohorts are published and learners register. |

**Error / blocked-path copy (specific, with the recovery path):**

| Condition | Copy |
|-----------|------|
| Capacity reached mid-action | "This cohort is full. It reached capacity while you were working. Raise capacity or withdraw an enrolment, then try again." |
| Duplicate active enrolment (P2002 → clean result, not 500) | "This learner already has an active enrolment in this cohort. Open that enrolment to transfer or withdraw it." |
| Publish blocked by readiness | "This cohort has {n} check(s) that must pass before it can be published. See Publication readiness below." |
| Stale edit (optimistic-concurrency `StaleOrderError`) | "Someone else changed this cohort while you had it open. Reload to see their version, then reapply your changes." |
| Attendance marking window closed | "The marking window for this session closed on {date}. Changes now need a reason and are recorded as corrections in the audit history." |
| Pre-marking a live-only state before session start | "You can only mark excused or not-recorded before the session starts. Present, absent and late need the session to have begun." |
| Offer target locked (enrolments exist) | "The course/programme this cohort delivers is locked because it has enrolments. Changing it needs an approved migration." |
| Meeting link hidden (learner-facing groundwork) | "The meeting link appears {n} minutes before the session starts." |

**Destructive / reason-required confirmations (`ConfirmModal`):**

| Action | Title | Description | Confirm label |
|--------|-------|-------------|---------------|
| Cancel cohort | Cancel cohort {code}? | Withdraws all {n} active enrolments with the reason below and cancels every scheduled session. The cohort is kept as cancelled, never deleted. | Cancel cohort |
| Withdraw enrolment | Withdraw {learner}? | Access ends now and the seat is released. Attendance and progress stay on this enrolment. | Withdraw |
| Cancel enrolment | Cancel {learner}'s enrolment? | Use before access starts, or to void an enrolment made in error. The seat is released. | Cancel enrolment |
| Transfer enrolment | Transfer {learner} to {target code}? | A new active enrolment is created in {target code} and this one is marked transferred. Attendance and progress do not move. | Transfer |
| Approve enrolment | Approve {learner}? | Moves this pending enrolment to active with no payment recorded. The reason is audited. | Approve |
| Cancel session | Cancel {session title}? | Enrolled learners see it as cancelled. It is not deleted, and any attendance already recorded is kept. | Cancel session |
| Correct attendance (post-window) | Change {learner}'s attendance for {session}? | From {old state} to {new state}. The marking window has closed, so this is stored as a correction in the audit history. | Save correction |
| Publish cohort (accent, not danger; reason only if migrating) | Publish cohort {code}? | Learners can find and enrol once it is published. All blocking readiness checks pass. | Publish |

## Phase 5 Screen Inventory & Interaction Contracts

Consumed by gsd-planner (task breakdown) and gsd-executor (source of truth). All screens live
under `src/app/staff/` and are built from existing primitives — **no new primitive is authorised.**

| Route | Primitive | Notes |
|-------|-----------|-------|
| `/staff/cohorts` | `ResourceTable` | noun "cohorts"; columns: Code (mono, links), Offer (Course XOR Programme, subtitle), Delivery mode (`StatusPill`), Window (enrol open→close, mono dates + tz), Seats (`{seatsTaken}/{capacity}` mono), Status (`StatusPill`). Filters: search (code/title), status select, delivery-mode select. `onCreate` → "Create cohort". |
| `/staff/cohorts/new` | `ResourceForm` | fields: offer target (Course XOR Programme — cross-field error in summary per `ResourceForm` contract), title/code, enrol window, start/end dates, timezone (select from `Intl.supportedValuesOf`), capacity (int), price (minor units) + currency, delivery mode, seat-hold minutes (hint: "default 30 · 0 or blank = seat taken only on activation"). |
| `/staff/cohorts/[id]` | `DetailLayout` mode `tabbed` | header: title, code (mono identifier), status + delivery-mode badges; actions: Edit, Publish. Tabs: **Overview** (`DetailFacts` + `ReadinessPanel`), **Sessions**, **Roster**, **Exceptions**. |
| Cohort → Overview | `ReadinessPanel` (shared, D-27) | renders server-evaluated `ReadinessItem[]`; category order gains **Catalogue** (see below). Panel never evaluates. |
| Cohort → Sessions | `ResourceTable` + `ResourceForm` | columns: Title, Starts (mono, cohort tz shown), Duration, Facilitator, Mode/link, Attendance expected, Status. "Add session" + "Repeat weekly ×N" (N inserts N rows). Soft-cancel via `ConfirmModal`. |
| Cohort → Roster | `ResourceTable` | columns: Learner, Enrolment status (`StatusPill`) + "history" link (reads `AuditEvent`), Access window (mono), Attendance `{earned}% / {required}%` (mono; `•` third state if no threshold), Instructor. **Progress / Assessment / Completion columns render the distinct third state** — pill reading "not tracked yet · Phase 9 / · Phase 10 / · Phase 11", `zinc-500`, never `0%`, never blank. Row → learner detail scoped to this cohort only (D-21). |
| Cohort → Exceptions | `ResourceTable` + bounded CSV button | categories: missing registers, at-risk, disputed/corrected. Filter set must match CSV output exactly (ATT-04 testable contract). CSV is synchronous, one cohort. |
| Attendance marking (per session) | full-screen roster list, one state control per learner, single **Save attendance** commit | mirrors the Phase-4 arrange-board "rearrange freely, commit once" pattern. States: present / absent / late / excused / not-recorded. Pre-start: only excused / not-recorded selectable; others disabled with the hint copy above. Post-window edits route each change through `ConfirmModal` (mandatory reason). Bulk actions never touch out-of-scope learners. |
| `/staff/enrolments` | `ResourceTable` | global scoped list; row → cohort roster context. Actions (Add / Approve / Transfer / Withdraw / Cancel) all reason-captured via `ConfirmModal`. |
| Publish cohort | `PublishDialog` (shared) or a `ConfirmModal`-shaped dialog reusing `ReadinessSummary` | Publish button disabled while any blocking readiness item FAILs (courtesy echo of the server gate, not the gate). |

**Nav:** wire `src/app/staff/layout.tsx` `NAV` — `Cohorts` → `/staff/cohorts`, `Enrolments` → `/staff/enrolments` (currently `href: null` placeholders).

**Readiness categories (extends `ReadinessPanel` `CATEGORY_ORDER`):**
`Catalogue → Schedule → Price → Capacity → Instructors → Completion`. Each heading always renders
(a missing heading reads as "not applicable" when the truth is "not yet checked"). Blocking, FAIL-capable:
Catalogue, Schedule, Capacity, Instructors. Price is effectively always PASS. Completion is WARN-only.

**Six render states** are mandatory on every screen and are baked into the primitives:
loading · empty (distinguishes "none" vs "none match filters") · populated · validation error
(previous rows/values stay visible) · permission denied (identical copy regardless of record
existence — no counts/titles/IDs leak, RBAC-06) · recoverable failure (retry, filters kept in URL).

**Timezone display contract (D-23):** session times are stored UTC, entered and displayed in the
cohort's `timezone`. Every session date-time in the UI is accompanied by the explicit zone label
in mono (e.g. `Africa/Lagos`), matching the existing `src/app/staff/layout.tsx` header treatment.

**Accessibility (NFR-09, WCAG 2.2 AA):** keyboard paths for tabs (roving tabindex — in `DetailLayout`),
dialog focus trap + restore (in `ConfirmModal`), error summary receives focus after failed submit
(in `ResourceForm`), `aria-live` on reason counters and row-count announcements, visible focus ring
everywhere, cards-below-640px with no horizontal scroll (in `ResourceTable`). No state discoverable
by colour alone — every signal colour is paired with a glyph and a text label.
