<objective>
Make the four shared modules the checkout path depends on able to express it — before the tracer tries
to and hits a compile error or an authorization dead end.

Purpose: each of these is a small additive edit to an existing, deliberately-constrained module, and
each one blocks the tracer in a different way. `DomainEventType` is a closed union that rejects
`"order.paid"` at compile time by design. `POLICY_TYPE` has no refund/cancellation entry because Phase 3
explicitly deferred it here (03-CONTEXT.md D-06). `approveEnrolment` contains exactly the
PENDING_PAYMENT -> ACTIVE transition the webhook needs but is sealed inside a `withPermission` closure
that resolves its actor from a session cookie a Stripe POST does not carry. And `PublicCohort` exposes
three date fields and nothing else — no id to link an Enroll button to, no price, no mode, no
availability. None of these is a design decision to make; all four are mechanical, pattern-following
edits that the codebase already shows how to do.
Output: four shared modules that can express a checkout, with the staff enrolment path provably unchanged.
</objective>
