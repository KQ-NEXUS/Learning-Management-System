<objective>
Land the one new dependency this phase needs — the `stripe` SDK — behind the two human gates that must
close before any Stripe code is written: a package-legitimacy confirmation, and a real test-mode proof
that this deployment's Stripe account will accept a Checkout Session in the currency every seeded cohort
is actually priced in.

Purpose: `src/server/payments/providers/` is an empty `.gitkeep` placeholder and no payment SDK exists in
`package.json`. Two facts make this a gate rather than a plain install. First, the automated
package-legitimacy check returns **SUS** for `stripe` on a "too-new" heuristic — the same false positive
Phase 3 hit for `@getbrevo/brevo` — and project discipline is to never override an automated verdict
silently (Phase 04.1 did the same for `lucide-react` and `@tiptap/extensions`). Second, `Cohort.currency`
defaults to `"NGN"` and every seeded cohort is NGN-priced, while Stripe's NGN presentment support is
account-and-country dependent. D-07 forbids a currency override, so if this account rejects NGN the entire
checkout path is blocked for all current data — a fact that must surface now, not at the first end-to-end
test after the service layer is already written.
Output: `stripe` pinned in `package.json`, the single SDK singleton, env-var placeholders, and a recorded
NGN verdict that plan 06-03's tracer depends on.
</objective>

Existing external-client module shape to mirror (`src/server/email/brevo-client.ts`): a module that
