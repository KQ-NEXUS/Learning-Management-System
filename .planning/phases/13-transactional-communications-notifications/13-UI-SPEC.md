# Phase 13 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 13-CONTEXT.md (D-13..D-22 locked), `src/app/globals.css` tokens, `src/components/primitives/controls.ts`. Values marked (default) were chosen by the researcher because no upstream artifact fixed them.

Surfaces in this phase: (1) bell + right-side slide-over notification drawer in the learner and staff headers, with an email-preferences panel (learner only); (2) staff email delivery log page with audited Resend; (3) the shared branded transactional email layout (HTML + text). Approved drawer mockup: https://claude.ai/artifact/9ttR5SBAFnxvFmgxShLdBH (D-18).

## Spacing Scale

Declared values (multiples of 4), matching Tailwind's 4px base already in use:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner padding |
| sm | 8px | Gap between title and meta, dot-to-text |
| md | 16px | Drawer row padding, drawer header/footer horizontal padding |
| lg | 24px | Drawer section spacing, preferences group gaps |
| xl | 32px | Delivery-log page section gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: bell button hit target 44x44px (touch target, accessibility); drawer width 400px on >=640px viewports and 100vw below; unread dot 8px (icon-scale glyph, not layout spacing); badge min-width 24px / height 24px (lg step, fits a 14px numeral plus 4px padding, "99+" grows the pill horizontally). Drawer header 64px (3xl step) and row min-height 48px (2xl step). The 44px bell/close/switch targets are the only off-scale values, justified by the touch-target minimum. Email layout uses a 600px max-width container, 24px content padding, 16px paragraph gaps.

## Typography

App base is `body` 14.5px / 1.5 in `globals.css`. On every surface in this phase (drawer, preferences, delivery log) the 14px sizes below explicitly override that 14.5px base via the Tailwind `text-sm` utility; the 14.5px value is not used anywhere in this phase. Exactly four sizes in total (14, 16, 20, 24) and two weights (400, 600) are declared; no other size appears anywhere in this spec.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (row detail, meta, table cells) | 14px | 400 | 1.5 |
| Label (row title, switch labels, buttons, badge count) | 14px | 600 | 1.5 |
| Email body (email only) | 16px | 400 | 1.5 |
| Heading (drawer title, section titles) | 20px | 600 | 1.2 |
| Display (email H1 only) | 24px | 600 | 1.2 |

That is four sizes: 14 (in-app body/label), 16 (email body and email button label at 600), 20 (heading), 24 (email H1).

Notes: unread row title uses weight 600, read row title weight 400 (D-18 "bolder title"). Group headings "Today"/"Earlier" and timestamps use 14px 400 in `text-muted-foreground`. Badge count is a 14px/600 numeral inside a 24px pill (see Spacing). Existing h1-h3 letter-spacing rules from `globals.css` apply. Delivery-log recipient/reference/correlation values use `font-mono` at 14px 400. Email font stack: `'Schibsted Grotesk', 'Segoe UI', Arial, sans-serif` at 16px body / 1.5 (email clients do not load the web font reliably; Arial fallback is expected).

## Color

Mapped to existing tokens (60/30/10):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--surface` #ffffff | Drawer panel, delivery-log page, email body card |
| Secondary (30%) | `--surface-2` #f3f5f9, navy frame `--sidebar-bg` #0a1024 | Read-row hover, page canvas, header band the bell sits on, email outer background |
| Accent (10%) | `--accent` #2d4bff (on navy: `--accent-light` #8fa0ff) | See reserved list |
| Destructive | `--danger` #b4231a / `--danger-surface` #fdf3f1 | FAILED status and failed-send errors only; no destructive actions exist in this phase |

Accent reserved for: unread dot on a notification row; unread-row tint (`--accent-wash` #eef1ff); unread badge fill on the bell (`bg-accent` with `text-accent-contrast`; on the navy header the bell icon is `text-sidebar-fg`, badge stays `bg-accent`); "Mark all read" and "Load older" text links; the checked state of preference switches; email primary button and its link colour; focus ring (existing `:focus-visible`).

Semantic supporting colours: greyed stale item uses `text-muted-foreground` with the title un-bolded and `--surface-2` background; "Always emailed" locked list uses `text-muted-foreground` with a `Lock` icon; delivery-log statuses map to StatusPill tones: SENT green, QUEUED blue, FAILED red, SKIPPED grey (retrying attempts show QUEUED with "attempt n of 5" meta, amber when next-attempt-at is set).

Email (literal hex, copied from primitives into one constants module): page background #f3f5f9, card #ffffff, heading/text #0f1730, secondary text #5b6478, button background #2d4bff with #ffffff text, hairline #e3e7f1, header band #0a1024 with brand name in #ffffff. Minimum contrast preserved (button 5.9:1, secondary text 5.9:1).

| Drawer title | Notifications |
| Drawer empty heading | You're all caught up |
| Drawer empty body | New updates about your enrolments, results and support tickets will appear here. |

| Load older | Load older |

| Preferences title | Email preferences |
| Preferences intro | Choose which updates we also send by email. In-product notifications always stay on. |
| Preference switches | Ticket replies and updates; Result release notices; Session change notices; Enrolment status changes |
| Always-emailed heading | Always emailed |
| Always-emailed items | Payment and enrolment confirmations; Ticket received confirmations; Certificates issued, revoked or reissued; Session cancellations; Account verification and password reset |
| Preferences saved | Preferences saved. |
| Preferences error | Preferences not saved. Try again. |
| Bell aria-label | Notifications, {n} unread (or "Notifications" when zero); badge caps at "99+" |
| Delivery log empty heading | No emails sent yet |
| Delivery log empty body | Transactional emails appear here once lifecycle events are processed. |
| Delivery log error | Couldn't load the delivery log. Reload the page; if it persists, contact an administrator. |
| Resend dialog title | Resend this email? |
| Resend dialog body | This sends the same message again to {recipient}. Your name and reason are recorded in the audit log. |
| Resend reason label | Reason for resending |
| Destructive confirmation | None destructive. Resend uses ConfirmModal (tone default, eyebrow "Audited action", `minReasonLength` 10) because it is an audited action; failure copy: "Email not resent. Try again." |
| Staff failed-email alert | An email to {recipient reference} could not be delivered. (no email body or address detail beyond a reference) |

Notification item text is rendered from type + safe fields only (D-17): never reasons, message bodies or filenames. Item templates are sentence case, one line title plus one optional 14px meta line (course/reference). Examples: "Your enrolment is confirmed", "Session updated: {course}", "Results released for {assessment}", "Certificate issued", "Support ticket {ref} has a reply", "New ticket {ref}", "Payment exception on order {ref}".

Email copy rules: subject is sentence case, no emoji, includes reference where one exists; footer always shows the brand name and the support contact from `src/server/support-contact.ts`; certificate-revoked and ticket emails carry references only (D-07); verification/reset emails state link expiry.

## UI Considerations

Applicable state considerations resolved: 8 covered, 3 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | notification drawer list | ✅ covered | Zero notifications render the "You're all caught up" heading/body from the Copywriting Contract; "Mark all read" is disabled |
| loading | drawer list on open, delivery log | ✅ covered | Drawer shows 4 skeleton rows (no spinner-only); delivery log uses route `loading.tsx` with the existing table skeleton; bell keeps last known count while polling |
| error | drawer fetch, mark-read, preferences save, resend | ✅ covered | Inline error with retry using the documented copy; a failed poll is silent and keeps the previous count; failed mark-read reverts the optimistic read state |
| populated | drawer grouped Today / Earlier | ✅ covered | Unread rows tinted `--accent-wash` with dot and 600-weight title; read rows plain; group headings shown only when the group has items |
| partial | stale/inaccessible item | ✅ covered | On click the drawer checks access; if denied or gone, the row is marked read, greyed and shows "No longer available" inline with no navigation and no distinction between deleted vs forbidden (identical-404 parity, D-21) |
| zero-one-many | unread badge | ✅ covered | 0 hides the badge; 1-99 shows the number; 100+ shows "99+"; aria-label carries the exact count |
| overflow | drawer list length | ✅ covered | List scrolls inside the drawer (header and footer fixed); cursor-paged with "Load older" (page size 20 default); "Load older" hidden when no more pages |
| long-text | notification titles/meta, delivery-log recipient and error | 🧪 backstop | Titles clamp to 2 lines, meta to 1 line with ellipsis; delivery-log error text truncates with full text in the row detail; needs a visual/held-out UI-state test with a 200-character course name |
| keyboard/focus | drawer | 🧪 backstop | Opens with focus on the drawer heading, traps focus, Escape closes and returns focus to the bell, backdrop click closes, body scroll locked; verify with an interaction test |
| reduced-motion | drawer slide | 🧪 backstop | 200ms slide-in (transform) disabled under `prefers-reduced-motion` (the global rule already collapses durations); verify that no motion is required to understand state |
| permission variance | gear icon, preferences panel | ✅ covered | Gear and preferences panel render for the learner shell only; the staff drawer has no gear and no preferences route |
| concurrency | multi-tab / poll while open | ⚠ unresolved | Poll (~60 s, visible tab only, D-22) refreshing while the drawer is open could reorder rows under the cursor; default: while open, poll updates the badge only and new items are prepended after the next open. Planner treats as an assumption |

## Layout and Interaction Detail

Bell: 44x44 button in the header right slot (learner `LearnerShell rightSlot`, staff `StaffShell` header band), `Bell` lucide icon 20px, `text-sidebar-fg` on navy, hover `bg-sidebar-hover`, `aria-haspopup="dialog"`, `aria-expanded`. Badge positioned top-right, `bg-accent text-accent-contrast`, 24px min circle, 14px/600 numeral.

Focal points: in the drawer the primary focal point is the unread rows (`--accent-wash` tint, accent dot, 600-weight title), reinforced on the page by the accent bell badge that leads the user there; "Mark all read" is secondary. In the delivery log the focal point is the Status column, with FAILED rows (red StatusPill on `--danger-surface` row tint) drawing the eye first; the Resend action sits beside them.

Drawer: right-anchored `role="dialog"` `aria-modal="true"` labelled by its heading, 400px wide, full height, `bg-surface`, `shadow-card`, scrim `bg-foreground/40` (matches `DIALOG_SCRIM` token). Header (64px): title "Notifications" 20px/600, gear icon button (learner only, `Settings` icon, aria-label "Email preferences"), close `X` button 44px target. Sub-header row: "Mark all read" link on the right. Body: grouped list. Footer: "Load older" (secondary button style `BTN`, full width) when more pages exist.

Row: 16px padding, 8px gap; leading dot slot 8px (accent when unread, empty when read); title 14px; meta 14px muted; relative timestamp right-aligned (muted). Row is a single link/button (min 48px tall) that on activation runs the access check then navigates. Opening the drawer marks nothing; only opening a link or "Mark all read" changes read state (D-19).

Preferences panel: replaces the list in the same drawer; header shows back arrow (`ArrowLeft`, aria-label "Back to notifications") and title "Email preferences". Four switches (`role="switch"`, 44px row targets, label + switch), then "Always emailed" locked list with `Lock` icons, then "Save preferences" (`BTN_PRIMARY`). A muted category still yields in-product notifications; the intro copy says so.

Delivery log page (`/staff/...` admin area, gated by an existing global-scope admin permission chosen by the planner, D-06): `PageHeader` + `ResourceTable`. Columns: Template, Recipient (reference, mono), Status (StatusPill), Attempts ("n of 5"), Next attempt, Last error (truncated, plain-language classification only, never provider payloads), Created, action. Filters: Status, Template. Row action "Resend" (`BTN`, 44px min height on touch) shown only for FAILED and SENT rows per policy; opens ConfirmModal. Result shown with `NOTE_SUCCESS` / `NOTE_DANGER`.

Email layout (D-13): 600px table-based layout, navy header band with brand name (white), white card, H1 (24px/600), body 16px, one primary button (bulletproof table button, min 44px tall, 16px/600, radius 6px), footer with support contact and "You are receiving this because of activity on your account." A plain-text alternative mirrors headings, body and the raw link on its own line. No images required; all links absolute from the configured public base URL (D-15).
