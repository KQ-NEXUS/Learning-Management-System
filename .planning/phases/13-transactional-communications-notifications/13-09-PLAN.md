<objective>
Map the enrolment-status, session-change and cohort-cancellation events to learner mail and notifications, with the D-12 coalescing rule and the cohort-cancel precedence rule.

Purpose: COM-01 lists enrolment and session change among the events that must email the right person exactly once. A cohort cancellation emits one event per enrolment plus one for the cohort, and session changes can repeat, so without explicit precedence a learner would be mailed many times or told the wrong thing.
Output: the enrolment-session mapper group and unit plus real-Postgres tests, including a run against the real cohort cancellation service.
</objective>

<assumptions>
- A-01: session.updated has no producer (scheduled-session-service exposes only create, repeat and cancel); the mapper, template and coalescing are built and tested with synthetic events, and no session-edit mutation is added. This should be surfaced to the user as a scope question.
- A-09: cohort-cancel precedence identifies the per-enrolment events of one cancellation as the withdrawn or cancelled events with the same cohortId, actorId and reason recorded within 60 seconds before the cohort.cancelled event; those emit SKIPPED superseded rows and cohort.cancelled mails the affected learners.
- A-10: cohort-cancelled and session-cancelled are in the always-sent category; enrolment-withdrawn, enrolment-cancelled and enrolment-transferred are the mutable ENROLMENT_STATUS category; session-updated is SESSION_CHANGES.
- Coalescing is per drain run: a later update processed in a later run mails again; only updates pending together collapse (D-12 "within one drain run").
- Suppressed events leave SKIPPED rows per recipient so the decision is auditable, at the cost of extra rows for large cohorts.
- Notifications for withdrawn, cancelled and cohort-cancelled link to the learner dashboard because the enrolment page needs an ACTIVE enrolment (A-18).
</assumptions>
