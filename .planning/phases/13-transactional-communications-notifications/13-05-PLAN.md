<objective>
Make notification links fail safely: verify the destination's own authorization before navigating, return one indistinguishable "unavailable" outcome, and add the scheduled 90-day archive.

Purpose: COM-03 requires stale or inaccessible links to fail safely, and D-21 forbids a 403/404 split that would turn the bell into an existence oracle. Centralising link building in one validated module also removes path-injection and drift between email links and notification links.
Output: `links.ts`, the access service with eight target resolvers, `openNotificationAction`, `archiveReadOlderThan`, the cleanup task and its Netlify wrapper, and unit plus real-Postgres tests.
</objective>

<assumptions>
- A-18: certificate, withdrawn, cancelled and cohort-cancelled notifications link to the learner dashboard (the enrolment page needs an ACTIVE enrolment); order, results and sessions notifications link to /orders/{reference}, /learn/{enrolmentId}/results and /learn/{enrolmentId}/sessions.
- A-28: "older than 90 days" for retention is measured from readAt, so an item that stayed unread for months is not archived the moment it is finally read; unread rows are never archived.
- Each resolver must read the destination page or its service first and reuse the same call (for example loadLearnerPath), so the check and the page cannot drift; this is verified by parity tests and by reading the pages in read_first.
- The access service is request-scoped (it may use the permission layer); it is imported only by the server action and never by a scheduled task.
</assumptions>
