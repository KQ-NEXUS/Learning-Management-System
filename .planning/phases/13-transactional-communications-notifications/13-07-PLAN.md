<objective>
Build the outbox drain: a scheduled two-pass engine that turns unprocessed DomainEvents into deduplicated EmailDispatch and Notification rows exactly once, then sends the queued mail, and prove it end to end on one event type.

Purpose: COM-02 needs a structural guarantee that retries and replays never duplicate a message, and COM-01 needs every event type routed through one mapper table. Plans 08 to 11 add the per-event mappers; this plan proves the spine and the failure semantics (poison events, recipient state, mute preferences).
Output: the drain service, the mapper composition seam with the first mapper, the scheduled task and Netlify wrapper, and unit plus real-Postgres tests.
</objective>

<assumptions>
- A-21: batch sizes are 25 events and 25 sends per run; cadence is every minute; the Netlify 30-second and 1-minute limits are unverified (research A1), so both passes are bounded and resumable.
- A-22: a failed event is excluded for the remainder of the run, so it reaches its third failed attempt across three runs; the audit entry is written when the third attempt fails and carries the event id, type and attempt count only.
- A-20: a Notification is created for an ACTIVE recipient even when the email is skipped or muted; a deactivated or pending user gets none.
- D-01 is rated reversible: the task body is transport-agnostic and only the Netlify wrapper would change.
- On-demand invocation is the exported runDrainDomainEventsTask; no HTTP trigger endpoint or shared secret is added.
- Event types with no D-07 or D-08 outcome (enrolment.created, enrolment.hold_expired, order.created, order.paid, attendance.changed, cohort.published, session.created, lesson.completed, course.completed, programme.completed, attempt.submitted, certificate.review_flagged, payment.reconciled) map to zero intents and are marked processed silently (A-25).
- Payload values are server-written but still validated by the mappers (requireString and friends); a malformed payload is a mapping failure, not a crash.
</assumptions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| outbox row to mapper | Payloads are server-written but a malformed or unknown row must not crash or poison the run |
| mapper output to database rows | Fields copied into templateParams and Notification params become persisted and visible |
| overlapping scheduled invocations | Two runs may see the same rows |
