<objective>
Build the notification read side and the preference store as ownership-scoped services with three JSON endpoints and two server actions, so the bell and drawer (Plan 06) and the access check (Plan 05) have a safe backend.

Purpose: COM-03 needs users to see unread and current state. Every query is scoped to the authenticated user, text is built only from safe fields, and read state changes only on explicit actions, so the UI can never leak or flip another user's state.
Output: notification service, preference service, notification text renderer and DTO shaper, three route handlers, two server actions, and unit plus real-Postgres tests.
</objective>

<assumptions>
- A-08: the preference store is the EmailPreference table (Plan 01) keyed (userId, category); saving replaces all four mutable rows by upsert.
- A-07: the list endpoint is fetched when the drawer opens and on "Load older"; the poll endpoint returns the count only, so an open drawer never reorders under the cursor.
- The list DTO carries a server-computed `group` of "today" or "earlier" using the app timezone helpers in src/lib/timezone.ts, so the client does no timezone maths.
- The preferences endpoint is available to any authenticated user; only the learner shell renders the gear (Plan 06).
</assumptions>
