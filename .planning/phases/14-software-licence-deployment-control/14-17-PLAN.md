<objective>
Prove with a permanent static test that no database write path in the service layer is left unguarded, and tag the three call sites whose permission spans both blocked and continuity operations.

Purpose: D-09 requires "a boundary test must prove no write path is left unguarded" and that system paths get an explicit guard or documented exemption. Because ESLint confines `@prisma/client` to `src/server/services/**` and `src/server/db.ts`, the service-file set is complete, so a service-file registry is the right unit. Tracer: the scanner classifies `checkout-service.ts` and `registration-service.ts` as guard files that contain their registered operations.

Output: `registry.ts`, the scan helper, the boundary test and three one-line call-site tags.

Interface contract (do not rename): `RegistryEntry = { file: string; kind: "withPermission" | "guard" | "continuity" | "system" | "licence" | "not-a-db-write"; reason: string; guardOperations?: readonly string[]; readFrontedWrites?: string }` with `file` relative to the repository root using forward slashes; `CONTINUITY_TAG_SNAPSHOT: ReadonlyArray<{ file: string; permission: string; reason: string }>`; `DYNAMIC_PERMISSION_FILES: ReadonlyArray<{ file: string; reason: string }>`; `scanServiceFiles(): Array<{ file; writes: boolean; permissionCalls: Array<{ permission: string | null; override: "read" | "write" | "continuity" | null; reason: string | null; line: number }>; guardOperations: string[]; importsPermissionLayer: boolean }>`.
</objective>
