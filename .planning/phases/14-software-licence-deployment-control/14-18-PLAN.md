<objective>
Make the 22 blocked-class staff server actions and lesson-resource routes surface the licence refusal message instead of a role-denial message.

Purpose: LIC-05 requires restriction to be enforced "server-side and in the UI" with a clear, non-sensitive refusal; the UI-SPEC says a server refusal must never reuse "Your role does not permit this action". Tracer: a refused cohort create and a refused course create return the refusal message through their own result shapes.

Output: the gate and behaviour test, and one-line message wraps in the 22 listed files. No action's result type changes.

Interface contract (existing from plan 14-11): `refusalMessage(error: unknown, deniedMessage: string): string` and `isLicenceRestricted(error): error is LicenceRestrictedError`, both exported from `@/server/permissions`; `LICENCE_REFUSAL_MESSAGE` from `@/server/licence/policy`.

Method for the file edits: for each file use Grep with `-n -C 8` for `AuthorizationError` to see the existing branch, then Edit only that branch; do not read whole files. Where a file defines a module-level constant such as DENIED_MESSAGE and uses it in several branches, wrap at each use. Where a file maps the error to a different shape (for example `{ ok: false, errors: [], message }`), keep that shape.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff action or route to browser | The message returned for a refusal is user-visible and must be accurate and non-sensitive |
| refusal vs denial responses | Differences between them could reveal licence state to someone who is not authorized |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-14-18-01 | Information disclosure | refusal reveals licence state to an unauthorized caller | medium | mitigate | The guard runs only after authorization (plan 14-11), so only authorized callers can receive the refusal; routes keep the identical 404 for every genuine denial; tests assert both |
| T-14-18-02 | Information disclosure | refusal message leaks detail | low | mitigate | Fixed constant, no permission, state or date in the text; test compares to the constant |
| T-14-18-03 | Elevation of privilege | an action file ignores the refusal and crashes into the error boundary | low | mitigate | LicenceRestrictedError extends AuthorizationError so existing branches still catch it; the file-level gate requires the helper in all 22 blocked files |
| T-14-18-04 | Tampering | new action file added without classification | medium | mitigate | Exhaustive classification test fails for any unclassified file that mentions AuthorizationError |
</threat_model>
