# Phase 14 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 14-CONTEXT.md (D-06, D-09, D-14, D-15 locked), 14-RESEARCH.md (Patterns 8, 11, 12), `src/app/globals.css` tokens, `src/components/primitives/*`, `src/app/staff/StaffShell.tsx`, 13-UI-SPEC.md (house format and notification/email conventions). Values marked (default) were chosen by the researcher because no upstream artifact fixed them.

Surfaces in this phase:
1. **Licence & System Status** screen at `/staff/licence` (Administration nav group, `licence.view`), including the two-step licence activation flow (`licence.activate`) and the diagnostic report download.
2. **Persistent Administrator banner** in the staff shell (`licence.view` holders only).
3. **Restricted-state UI mirror** for staff screens: disabled controls with a visible reason, and a distinct "licence refusal" message for server denials.
4. **Learner-facing neutral refusal** for blocked checkout and registration (no licence wording).
5. **Licence notices** through the Phase 13 pipeline: in-product notification rows and staff emails.

The provider-side issuer CLI has no UI and is out of scope for this contract.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not initialized; not initialized this phase, consistent with Phase 13) |
| Preset | not applicable |
| Component library | none: hand-built components on Tailwind CSS v4 (`@import "tailwindcss"`, `@theme inline` in `src/app/globals.css`) |
| Icon library | lucide-react 1.41.0 (resolved from `node_modules/lucide-react/package.json`) |
| Font | Schibsted Grotesk (`--font-sans`), JetBrains Mono (`--font-mono`, reserved for ids, instants and licence text) |

Styling rule (existing, unchanged): components consume only semantic, pill and sidebar tokens through Tailwind utilities (`bg-surface`, `text-muted-foreground`, `border-border`, `bg-accent`, `text-pill-amber-ink`...). No raw hex outside `globals.css`. **This phase adds no tokens and no CSS.** The banner reuses the existing `.on-navy [data-tone]` rules.

Dark mode: `globals.css` defines no dark tokens. Build only from semantic tokens so a future dark theme re-skins the screen; this phase does not introduce one.

Terminology (D-06, hard rule for every string in this contract, in code and in tests): the post-grace state is **"Restricted continuity mode"**, never "read-only". One constant, `RESTRICTED_CONTINUITY_LABEL`, owns the phrase; every UI string, notification text and email template imports it. States stay separately named and are never merged: **not activated, active, expiring soon, expired (grace period), restricted continuity mode, invalid, check pending**.

### Date format rule

Every instant is shown as `{d MMM yyyy}, {HH:mm} {zone abbreviation}` in the licence's signed IANA zone (fallback `Africa/Lagos`), 24-hour clock, with the exact UTC instant beside it in mono: `30 Nov 2026, 23:59 WAT` and `2026-11-30T22:59:59Z`. Built with `Intl.DateTimeFormat` using explicit `timeZone` and `timeZoneName: "short"`, locale `en-GB`, so server and browser renders are byte-identical (no hydration mismatch). The zone name is shown once under the first date (`Africa/Lagos` in muted 14px).

### Days-remaining rule

Display figure and caption by state (pure function of the derived state and `now`):

| Situation | Figure | Caption |
|-----------|--------|---------|
| More than 1 day to expiry | {n} | days remaining |
| 24 hours or fewer, not yet expired | Under 24 hours | until the licence expires |
| Exactly 1 day | 1 | day remaining |
| In grace | {n} (days to grace end) | days until restricted continuity mode begins; same "under 24 hours" and "1 day" rules |
| Restricted or invalid | none (figure omitted) | "Restricted since {date}" or "Invalid since {date}" |
| Not activated | none | none |

### Plain-language state summaries (one sentence under the figure)

| State | Summary |
|-------|---------|
| Active | The licence is valid. Everything works normally. |
| Expiring soon | The licence expires on {expiry}. Everything works normally until then, and for {graceDays} days after. |
| Grace | The licence expired on {expiry}. Everything still works until {graceEnd}. After that, restricted continuity mode begins. |
| Restricted | Restricted continuity mode is active. New commercial activity is blocked; learners, grading, certificates, refunds and exports continue. |
| Invalid | The installed licence could not be verified: {reason sentence}. Restricted continuity mode is active until a valid licence is activated. |
| Check pending | The licence check could not complete. The last known state is kept until {attentionSince + 24 h}; after that restricted continuity mode begins. |
| Not activated | No licence is installed. The deployment works normally until the first licence is activated. |

`{graceDays}` is computed from the signed `graceEndsAt - expiresAt`, never hard-coded. State copy is rendered from one constants module (`policy.ts`) so UI, notifications, email and tests cannot drift.

### What works and what is blocked (default lists, rendered from the same registry the enforcement uses)

Heading "What works" (icon `CircleCheck`), heading "What is blocked" (icon `Lock`). In restricted or invalid state:

| What works | What is blocked |
|------------|-----------------|
| Learners continue coursework, quizzes, assignments and progress | New enrolments and new checkout sessions |
| Grading and certificate issuance | Publishing and content changes |
| Sign-in, password reset and security administration | Staff, role and permission changes |
| Payment webhooks, refunds and reversals; payments started before the restriction still complete | Settings changes and other administrative edits |
| Data exports and licence activation | New learner registration (assumption A12, confirm with the user) |
| Email and in-product notifications | |

In active, expiring and grace states "What is blocked" shows "Nothing is blocked right now." and a "What happens after {graceEnd}" sub-list repeats the blocked items. The preserved-data statement sits under both lists in every state. The final list contents must come from `LICENCE_SERVICE_REGISTRY`; the strings above are defaults for the planner to reconcile, not a separate source of truth.

### Words that must never appear in licence UI, notices or emails

"read-only" (any casing), "extend", "generate", "create licence", "edit licence", "unlock", "reactivate", "bypass", "signing key" values, "private key", contract clauses, gateway secrets, stack traces. The wording test (14-RESEARCH Pitfall 12) enforces the first; the planner adds the rest to the same test.

No signing, contract, key or file content, and no deployment ID in the email body.

## Layout and Interaction Detail

### Licence & System Status page (`/staff/licence`)

`DetailLayout` in `mode="stacked"`. `title` "Licence & System Status"; `badges` holds one `StatusPill` for the current state (tone and label from the Color table); `subtitle` shows the renewal contact only when one exists. Page-level states use `DetailLayout state` (`loading`, `error`, `denied`) and a route `loading.tsx` that renders the loading state.

Main column (left), in this order:

1. **Licence status** (section label "Status"). The 28px/600 display figure with its caption (Days-remaining rule), then the 16px summary sentence. Below, a plain `NOTE_WARNING` appears only when the clock-rollback flag is set: "The server clock moved backwards on {date}. Check the server's time settings." The figure and summary are the focal point of the page.
2. **Licence details** (`DetailFacts`, label column 210px): State (StatusPill), Licence ID (mono), Registered client, Deployment ID (mono, with a "Copy" icon button, 44px target, aria-label "Copy deployment ID"), Expires (local date, zone name muted, UTC mono on the next line), Grace ends (same), Last verification (StatusPill: Passed / Failed / Could not complete / Not checked yet, plus the timestamp). Rows with no value (never activated) show "Not available" in muted text, never a blank.
3. **What works and what is blocked.** Two lists side by side from `md` (2 columns, `gap-8`), stacked below. Each list is a `ul` with the heading above it, icon (16px) plus text per item, `surface-2` panel with a hairline border. The preserved-data statement follows as a `NOTE`.

Right rail (`aside: true`, from `lg`, 400px):

4. **Renewal and support.** Renewal email, support email (both `mailto:` links in accent text), phone and hours only when present in the signed payload. Never-activated fallback: "Use the support contact on your agreement."
5. **Activate a licence** (holders of `licence.activate`; others see the one-line permission note). See activation flow.
6. **Data and diagnostics.** "Download diagnostic report" (`BTN`, `Download` icon) hits `GET /api/staff/licence/diagnostic`; downloaded filename `licence-diagnostic-{licenceId or "not-activated"}-{YYYYMMDD}.json`. Helper text: "Contains no signing material, secrets or personal data." "Open data exports" (accent text link to `/staff/reports`, shown only when the viewer holds `reports.view`) with helper "Exports stay available in restricted continuity mode." Neither control is ever disabled by licence state.

The screen offers no control that creates, extends, edits, replaces a signature on, or self-reactivates a licence (LIC-03). The only write is activating a provider-issued file.

### Activation flow (two steps, `licence.activate`)

1. **Choose.** One panel: a `FIELD` "Licence file" with a file input (button label "Choose file", the chosen file name shown in mono), and a `FIELD` "Or paste the licence text" with a `TEXTAREA` (mono 14px, `min-h-24`). Whichever is set last wins and the other clears. "Check licence" (`BTN`, `FileCheck` icon) is disabled until there is input. Helper: "Use the file exactly as provided." Input is size-checked before reading (8 KiB) and trimmed; no text is echoed back unless the signature verified.
2. **Check (pending).** Button reads "Checking…", `aria-busy` on the panel. Never a spinner-only state.
3. **Verified preview.** A `surface-2` panel with a hairline border: heading "Verified" with `CircleCheck`, then `DetailFacts`-style rows (Licence ID, Client, Deployment with "Matches this deployment", Issued, Starts, Expires, Grace ends; when replacing, a row "Replaces" with the current licence ID and its expiry). Shown only after signature verification passed. Buttons: "Activate licence" (`BTN_PRIMARY`) and "Choose a different file" (text link, resets the panel).
4. **Confirm.** `ConfirmModal` as specified in Copywriting. Focus moves into the dialog, returns to "Activate licence" on cancel, ESC cancels unless pending (all existing primitive behaviour).
5. **Result.** Success: `NOTE_SUCCESS` with `role="status"` and programmatic focus, the page revalidates (`revalidatePath("/staff", "layout")`) so the banner, pill and lists update, and the input panel resets. Rejection at step 2: `NOTE_DANGER` under the field with the fixed sentence for the code (`role="alert"`), the input is kept so the user can correct it, "Nothing was changed." appended. Rejection at step 4: shown in the modal as "action not applied" (existing `ConfirmModal` error slot).
6. The server re-verifies the submitted text at step 4 and never trusts the preview (14-RESEARCH Pattern 12).

### Persistent banner (shell)

Rendered by `staff/layout.tsx` for holders of `licence.view` only and passed to `StaffShell` as `banner`. Placement: a full-width strip between the navy `<header>` and `<main>`, inside the navy frame, so `PageHeader` still pulls up as the first child of `<main>` (no change to `PageHeader` or `main`). Strip: `min-h-12`, `px-6 lg:px-8`, `py-2`, `flex flex-wrap items-center gap-x-4 gap-y-2`, `role="status"`, stable `id="licence-restriction-notice"`. The state label and icon are one tone element (`data-tone`); the message is 14px white; the link is 14px/600 white, underlined, 44px minimum hit area on touch. Not dismissible, no animation (the `.alert-dot` pulse is intentionally not used). Learner shells render no licence text at all.

Staleness: layouts do not re-render on soft navigation, so the banner reflects the last full render; activation revalidates it, and the server denial message stays authoritative.

### Restricted-state UI mirror (staff screens, courtesy only, the server is the gate)

- A write control (`ResourceForm` submit, `ConfirmModal` confirm, a row action, a primary page action) is `disabled` when restricted, unless the screen marks it `licenceEffect="continuity"` (grading, certificate issuance, attendance, refunds, exports, tickets) or it is a read.
- A disabled write control is always paired with a visible reason line directly after it: `Lock` icon 16px plus the "Restricted control reason" copy, 14px/400 `text-muted-foreground`, linked by `aria-describedby`. A tooltip alone is not acceptable.
- Tables with row-level write actions show the reason once as a `NOTE_WARNING` above the table; each disabled row action references it with `aria-describedby`. Do not repeat the sentence per row.
- Which copy variant is shown depends on whether the viewer holds `licence.view` (see Copywriting). Disabled state must be understandable without colour.
- A server refusal (`LicenceRestrictedError`) renders through `LicenceRefusalNote`: `border-l-2 border-warning bg-warning-surface px-4 py-2 text-sm text-foreground`, `Lock` icon, `role="status"`, text "Server refusal" from the Copywriting table. It must never reuse the "Your role does not permit this action" message and never use `NOTE_DANGER` (the user did nothing wrong).
- Learner screens: a refused checkout or registration shows the neutral learner refusal inside the existing `CheckoutNotice` style (`border-l-2 border-warning bg-warning-surface`, `role="status"`).

### Keyboard, focus and motion

All controls are native `button`, `a`, `input`, `textarea`; tab order follows DOM order (file, textarea, Check licence, Activate licence). Focus ring is the existing 2px accent outline. The success note and the rejection note receive programmatic focus once. Nothing on this screen animates; the global `prefers-reduced-motion` rule already applies.
