<objective>
Build the pure signed-licence contract: the compact envelope, the strict payload schema, the Ed25519 verifier and the versioned trust set, with fixtures and committed golden vectors.

Purpose: LIC-01 requires altered, wrong-client, wrong-deployment and otherwise invalid licences to be rejected, using only embedded public key material (D-01, D-02). This plan is the phase tracer: one licence minted by a test fixture is verified through every layer of the contract.

Output: `src/server/licence/{constants,errors,format,trust-set,verify}.ts`, `tests/support/licence-fixtures.ts`, golden vectors, and the format, verify and purity tests.

Reversibility gate: the one-way door implemented by Task 1 is gated by the blocking-human `checkpoint:decision` in Task 1 of plan 14-01, which this plan depends on (depends_on [01]); Task 1's precondition re-asserts that the recorded answer exists before any code is written.

Interface contract for later plans (do not rename):
- `verifyLicence(raw: string, ctx: { trustSet: TrustSet; deploymentId: string; registeredClientId: string | null; now: Date; mode: "activate" | "runtime" }): { ok: true; licence: VerifiedLicence } | { ok: false; code: LicenceRejectionCode }`.
- `VerifiedLicence`: `{ raw, keyId, schemaVersion, licenceId, clientId, clientName, deploymentId, issuedAt: Date, notBefore: Date, expiresAt: Date, graceEndsAt: Date, timeZone, support: { renewalEmail, supportEmail, phone?, hours? } }`.
- `TrustedKey = { kid: string; x: string; status: "active" | "retired" | "revoked" }`, `TrustSet = ReadonlyMap<string, TrustedKey>`.
- `LicenceUnavailableError` (infrastructure failure only) and `LicenceWriteBlockedError` (explicit-guard refusal) in errors.ts.

Edge coverage disposition (fallback report, LIC-01 unclassified, flagged assumption): the probe could not classify LIC-01 ("review manually"); this plan assumes the acceptance outcome "a modified payload or invalid signature cannot activate the LMS" is fully covered by the closed 11-code rejection matrix, the golden vectors and the activation integration tests in plan 14-07. No further boundary, precision or concurrency category is claimed for LIC-01.
</objective>
