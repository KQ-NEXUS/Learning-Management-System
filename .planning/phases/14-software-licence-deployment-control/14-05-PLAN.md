## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider workstation to repository | The signing key must never cross into source control or the client build |
| provider tool to client deployment | Only signed licence files and public key material cross |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-14-05-01 | Information disclosure | private signing key in repo or image | high | mitigate | assertOutsideRepo on keygen output and key load; no overwrite; never print or return the key; .dockerignore excludes provider-tools; tests assert the PEM marker is absent from provider-tools and that src and netlify never import it |
| T-14-05-02 | Elevation of privilege | forged licence from a leaked dev key | medium | mitigate | CLI signs only with a caller-supplied key file; dev keys live only in the test trust set and are excluded in production by loadTrustSet (plan 14-02) |
| T-14-05-03 | Tampering | grace or date mistakes in issued files | medium | mitigate | payload validated with licencePayloadSchema before signing; grace computed in UTC from an explicit input; runbook states the rule |
| T-14-05-04 | Repudiation | issued licence cannot be traced | low | accept | The provider keeps its own register outside the LMS (PRD 18.4 provider licence register); this repo stores nothing |
| T-14-05-SC | Tampering | npm package installs | high | accept | No package installs; node:util parseArgs and tsx are already present |
