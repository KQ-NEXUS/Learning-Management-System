<objective>
Add the evaluation half of the licence service: the per-write gate, the restriction cutoff, exactly-once state transitions with alerts' notice keys, clock-anomaly handling and the diagnostic report.

Purpose: LIC-04 requires checks before high-impact mutations and bounded behaviour on local failure; LIC-05 requires restriction to take effect server-side without a scheduler; LIC-06 requires every transition, outcome and enforcement to be audited. Tracer: a stored licence is allowed one millisecond before graceEndsAt and blocked at graceEndsAt through the real database path.

Output: the five methods on the object returned by `createLicenceService` (and the `licenceService` singleton) plus three test files.

Interface contract for later plans (do not rename):
- `checkWriteGate(input: { operation: string; actorId: string | null }): Promise<{ allowed: true } | { allowed: false; state: LicenceStateName; reasonCode: string | null }>`.
- `assertWriteAllowed(input: { operation: string; actorId?: string | null }): Promise<void>` throws `LicenceWriteBlockedError` when blocked.
- `getRestrictionCutoff(): Promise<{ restricted: boolean; restrictedAt: Date | null }>`.
- `evaluateAndRecord(options: { source: "SCHEDULED" | "STARTUP" | "REQUEST"; correlationId?: string }): Promise<{ snapshot: LicenceStatusSnapshot; transitions: Array<{ from: LicenceStateName; to: LicenceStateName; won: boolean }>; rollbackDetected: boolean; verificationChanged: boolean; noticeKeys: string[] }>`.
- `buildDiagnosticReport(): Promise<DiagnosticReport>` with the allow-listed field set above.

Edge coverage: LIC-06 (unclassified, flagged assumption): the probe returned "review manually"; this plan assumes the acceptance outcome "licence events can be reviewed by restricted audit users" is met by writing every licence event through the existing append-only audit service with targetType LICENCE and action names starting `licence.`, reviewable on the existing audit screen under audit.view (licence permissions do not grant audit access, PRD 18.4); no new audit surface is built in this phase and plan 14-21 proves the rows exist.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| request path to licence state | Every guarded write reads shared state; stale or cached decisions create bypass or outage |
| concurrent instances to singleton row | Races could double-audit or lose transitions |
| diagnostic report to administrator download | Report content leaves the application boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-14-09-01 | Tampering | stale per-process decision allows a restricted write | high | mitigate | No allow-path cache; gate re-reads and re-verifies each call; tests with separate service instances over one database |
| T-14-09-02 | Tampering | TOCTOU between check and mutation | medium | mitigate | Check runs inside the same request after authorization (plan 14-11); restriction is monotonic in time; payment cutoff has 10-minute tolerance (plan 14-13) |
| T-14-09-03 | Denial of service | transient read failure becomes an outage or a permanent allow | high | mitigate | Last-known-good for exactly 24 hours then block; boundary tests; first failure with no history allows (the write itself needs the same database) |
| T-14-09-04 | Denial of service | audit flooding from a hammering client or every cold start | medium | mitigate | Enforcement audit coalesced per actor per minute; verification audit only on outcome change; REQUEST source writes only on change |
| T-14-09-05 | Tampering | clock rollback used to extend use | medium | accept | Offline clock tampering is unsolvable (D-12); detected, audited and alerted, never locked out; documented residual risk |
| T-14-09-06 | Information disclosure | diagnostic report leaks secrets or raw licence | high | mitigate | Field-by-field allow-list built in code; test asserts serialized output excludes raw text, signature, env values and stack markers |
| T-14-09-07 | Repudiation | state change without evidence | medium | mitigate | CAS winner writes licence.state_changed in the same transaction; actorType SYSTEM and correlation id recorded |
</threat_model>
