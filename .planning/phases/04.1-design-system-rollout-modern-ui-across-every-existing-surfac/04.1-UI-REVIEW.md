# Phase 04.1 — UI Review

**Audited:** 2026-09-06  
**Baseline:** approved `04.1-UI-SPEC.md`, locked `04.1-CONTEXT.md` decisions, and `04.1-MOCKUP-ANNOTATIONS.md`  
**Screenshots:** not captured — no Playwright MCP was exposed; the listener on port 5173 was not treated as verified project visual evidence  
**Verdict:** **BLOCKER — 11/24.** The structural redesign is present, but task-completion, keyboard, responsive, typography, and spacing defects prevent this implementation from satisfying the approved contract.

The earlier code and security reviews were used as leads, then checked against current source. Findings below are included only where they materially affect the UI or interaction contract. Security's high-severity gate is clear, but its open lesson/course-boundary advisory and unaccepted low-severity risks remain relevant to release review.

---

## Top 3 Priority Fixes

1. **Restore task completion on staff workflows** — remove or wire the four inert course controls, preserve bulk selection on mobile cards, expose programme outcomes in the form, and make audit history readable at 360px. These defects currently make promised tasks impossible.
2. **Unify keyboard and error-state behavior** — reuse one proven modal focus lifecycle for `AssignmentDrawer` and `PublishDialog`, make the closed staff drawer inert, label every table filter, retain form-level assignment errors, and associate rich-body errors with the editor.
3. **Make the implementation obey the visual contract mechanically** — replace blank logo tiles with the approved inline SVG mark, consolidate typography into the declared fixed scales, and eliminate half-step/off-grid spacing utilities. Add lint/test gates so the drift cannot reappear.

## Detailed Findings

### Pillar 1: Copywriting (2/4)

- **WARNING — binding 404 recovery copy was not shipped.** `src/app/(public)/not-found.tsx:23-39` renders “Page not found”, generic removal copy, and separate “Browse courses” / “Browse programmes” actions. UI-SPEC §6.2 requires “We can't find that page”, the archived/out-of-date explanation, and “Back to the catalogue”. `src/app/not-found.tsx:24-32` diverges again with “Go to the home page”, even though `/` immediately redirects.
- **Pass evidence:** auth shell copy at `src/app/(auth)/layout.tsx:36-47`, account headings/subcopy at `src/app/account/page.tsx:18-23` and `ProfileForm.tsx:68-70,126-129,198-201`, and primitive error/confirmation language preserve the contract's direct, outcome-oriented voice.
- **WARNING — some visible labels promise behavior that does not exist.** “Publish”, “Archive…”, “Export CSV”, and “New course” at `src/app/staff/courses/CoursesTable.tsx:177-191` are presented as actionable copy but have no operative destination or handler. This is primarily an experience defect, but the copy itself misrepresents availability.

### Pillar 2: Visuals (2/4)

- **WARNING — the approved brand mark is missing in all three shells.** The contract requires a reusable gradient tile containing the bespoke two-stroke inline SVG. `src/app/staff/StaffShell.tsx:123-130`, `src/components/shell/LearnerShell.tsx:78-85`, and `src/app/(auth)/layout.tsx:24-30` render empty gradient rectangles instead. The principal brand asset therefore reads as a colored blank.
- **Pass evidence:** source establishes the intended hierarchy: 228px staff sidebar (`StaffShell.tsx:114-119`), 44% auth split (`(auth)/layout.tsx:21-51`), 1080px learner shell (`LearnerShell.tsx:73-157`), `rounded-xl` sparse cards, `shadow-xs` dense tables, and `shadow-card` dialogs/cards.
- **WARNING — hierarchy cannot receive a passing visual judgment from code alone.** Whether depth remains clean rather than muddy, the primary action is the unique focal point, card grids align, and the short-height auth composition remains balanced are browser-rendered properties.
- `needs_human_review: true` — compare all shells and representative list/detail/form/dialog screens with the approved mockup at desktop, tablet, and mobile widths.

### Pillar 3: Color (3/4)

- **Pass evidence:** `src/app/globals.css:13-158` implements the semantic primitive/pill/sidebar chain, the approved blue/teal/amber/green/red values, distinct input and decorative borders, five tinted pill triples, and named depth tokens. Current source contains no `zinc-*`, `font-medium`, or component-level hex literal.
- **Pass evidence:** the code scan found no interactive `teal-*` utility. Blue remains the action/link/focus color, consistent with D-08/D-09. Contrast verification is backed by the phase's 43 contrast tests and the UI-SPEC's white/paper pair table.
- **WARNING — component-level raw color still bypasses the chain.** `src/app/account/ProfileForm.tsx:225` uses `bg-white` and `shadow-[0_1px_2px_rgba(16,24,40,0.15)]` instead of semantic surface and a named shadow token. This evades the stated “component code consumes only semantic/pill/sidebar tiers” rule.
- **WARNING — the 60/30/10 distribution is unverified.** Static counts show extensive semantic usage (`text-muted-foreground` 194, `text-foreground` 149, `bg-surface` 128, `bg-surface-2` 90, `text-accent` 56, `bg-accent` 24), but occurrence counts cannot establish rendered area or whether accent is visually constrained to ~10%.
- `needs_human_review: true` — verify computed color and the 60/30/10 balance on representative staff, auth, public, and account screens, including Windows High Contrast focus visibility.

### Pillar 4: Typography (2/4)

- **Pass evidence:** `src/app/layout.tsx:2-17` loads Plus Jakarta Sans and IBM Plex Mono; `src/app/globals.css:156-174` wires the two faces and global heading tracking. Only `font-normal` and `font-semibold` are active (10 and 225 occurrences respectively), satisfying the two-weight rule.
- **WARNING — the fixed size contract is widely violated.** The UI scale allows only 25/16/14/11px and the display scale only 42/33/28/22px. The shipped frontend contains 159 `text-xs` uses (12px), 13 `text-[10px]`, one `text-[12.5px]`, and one `text-xl` (20px), in addition to the permitted values. Examples include filter labels and controls at `ResourceTable.tsx:270-322`, staff breadcrumb text at `StaffShell.tsx:227`, and numerous buttons declared as `text-xs`.
- **WARNING — role sizing is inconsistent.** UI-SPEC §4.3 assigns body/control and button labels 14px, yet primary actions repeatedly use `text-xs`, including `ResourceTable.tsx:123`, `ResourceForm.tsx:47`, `CoursesTable.tsx:189`, and `PublishDialog.tsx:245`.
- `needs_human_review: true` — verify actual computed font family/weight and wrapping for long headings, breadcrumbs, labels, and error text; source conformance alone does not prove font files load successfully in-browser.

### Pillar 5: Spacing (1/4)

- **BLOCKER — the declared grid is not the implemented grid.** UI-SPEC §3.1 permits only 4, 8, 16, 24, 32, 48, and 64px with “no half-steps”. Source uses off-contract spacing pervasively: `py-1.5` 80 times, `px-2.5` 54, `gap-1.5` 51, `gap-3` 33, `gap-2.5` 9, `gap-5` 8, plus `px-[18px]` and `pt-[18px]` in `StaffShell.tsx:122`.
- **WARNING — named role consistency is therefore not auditable.** For example, card bodies mix `px-5 py-5` (`ProfileForm.tsx:25,197`), primitives use `px-6 py-10` (`ResourceForm.tsx:77-135`), and controls commonly use 6px/10px/14px half-step padding despite the locked role table.
- **Pass evidence:** the macro shell dimensions themselves are recognizable: 228px staff rail, 44% auth panel, 1080px learner container, and 32/24/48 learner body padding.
- `needs_human_review: true` — after token cleanup, sweep 1440px through 360px for rhythm, wrapping, action reachability, and horizontal overflow.

### Pillar 6: Experience Design (1/4)

- **BLOCKER — four visible course actions do nothing.** `src/app/staff/courses/CoursesTable.tsx:177-191` contains two empty callbacks and two buttons without handlers or links.
- **BLOCKER — mobile cards lose bulk selection.** Desktop checkboxes exist at `ResourceTable.tsx:626-640`; the mobile representation at `ResourceTable.tsx:700-765` renders none, so a core table capability disappears below 640px.
- **BLOCKER — table filters lack accessible names.** In `ResourceTable.tsx:268-329`, the visible label is a sibling span; the search label contains only an aria-hidden icon, and the long-option select has no `aria-label`/`aria-labelledby`. The segmented path alone is named.
- **BLOCKER — closed staff navigation remains interactive off-screen.** `StaffShell.tsx:114-119` changes only transform. The aside and its links remain mounted, exposed, and tabbable when closed; focus is not moved into the opened drawer.
- **BLOCKER — modal semantics are asserted without modal behavior.** `AssignmentDrawer.tsx:78-95` focuses and handles Escape but has no Tab loop/inert background; `PublishDialog.tsx:94-100` has no initial focus, trap, Escape handling, or focus restoration. Both claim `aria-modal`.
- **BLOCKER — assignment failures can disappear.** `AssignmentDrawer.tsx:133-160` removes every `form` error, including authorization and non-field failures, leaving users without feedback.
- **BLOCKER — audit evidence is clipped on narrow screens.** `AuditTable.tsx:239-340` places a four-column table in `overflow-hidden` with no mobile representation or local scrolling surface.
- **BLOCKER — programme outcomes cannot be authored.** `ProgrammeForm.tsx:14-20` accepts `outcomes`, but the rendered fields at lines 58-109 omit it entirely.
- **BLOCKER — media captions are only a false affordance.** `LessonMediaPlayer.tsx:41-46` renders a captions track without `src`, so prerecorded video has no usable captions.
- **BLOCKER — transient scan failures strand pending resources.** `UploadPanel.tsx:108-130` does not schedule another poll after rejection.
- **WARNING — pending and async error paths remain incomplete.** `PublishDialog.tsx:169-223` leaves cohort checkboxes and reason editing enabled after submission; imperative action handlers identified in `04.1-REVIEW.md` can remain busy after rejected promises; rich-body error text is not associated with the editor.
- **Security overlap, not duplicated as a separate visual defect:** `src/app/staff/courses/[id]/preview/lessons/[lessonId]/page.tsx:35-56` permits a lesson from another course tree. This matches security advisory T-04.1-26 and breaks route/context integrity; it must be fixed before UAT can treat preview navigation as trustworthy.
- **Pass evidence:** the four primitives cover loading/empty/error/denied states, `ConfirmModal` has a robust focus loop and pending suppression, auth/account forms expose pending labels, public indexes have deliberate empty states, and denial copy has regression coverage.
