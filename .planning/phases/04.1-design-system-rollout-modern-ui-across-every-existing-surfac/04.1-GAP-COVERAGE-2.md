## Verification discipline for this wave

- Every new regression file is created **inside** its owning repair task and must reproduce the
  reported failure before the repair is applied; both the failing and passing runs are recorded in
  the plan's SUMMARY.
- No verify command in plans 32–35 uses a `-t <group>` filter against `design-contract.test.ts`. The
  vacuous-filter pattern is the root cause of G-RV-02 and is banned for this wave.
- No plan may mark NFR-09, `04.1-UAT.md` or phase 04.1 complete. Each plan's `<success_criteria>`
  states this explicitly.
- No plan may add a locked exception to silence a design-contract violation, remove a capability,
  hide working video, fabricate captions, or claim a human/visual result from a source or jsdom run.
