# Phase 04.1: Code Review Report

**Reviewed:** 2026-09-06T01:30:59Z
**Depth:** standard
**Files Reviewed:** 74
**Status:** issues_found

## Summary

The complete source scope declared by all fourteen Phase 04.1 summaries was reviewed against the current working tree, the UI contract, and the bundled Next.js 16 guidance. The rollout contains shipping blockers: visible controls that do nothing, responsive behavior loss, inaccessible modal/drawer/navigation states, a programme field silently dropped by its form, incorrect cross-course preview routing, and upload polling that permanently stops after a transient failure. Async failure paths and field-error wiring also need hardening.

## Narrative Findings (AI reviewer)

## Critical Issues

### CR-01: [BLOCKER] Four course-management controls are visible no-ops

**File:** `src/app/staff/courses/CoursesTable.tsx:177-191`

**Issue:** The selection actions “Publish” and “Archive…” have empty callbacks, while “Export CSV” and “New course” are buttons with no handler or link. Users can invoke apparently available management actions and receive no result or feedback. This is incorrect behavior, not a decorative placeholder.

**Fix:** Wire each control to its real action/navigation (including confirmation and authorization for destructive operations), or remove/disable it with an explicit unavailable explanation until the behavior exists. Add interaction tests that assert each visible control produces its promised outcome.

### CR-02: [BLOCKER] Search and select filters have no accessible names

**File:** `src/components/primitives/ResourceTable.tsx:268-329`

**Issue:** The visible filter title is a sibling `<span>`, not a `<label>`. The search field’s wrapping label contains only an aria-hidden icon, and the non-segmented `<select>` has neither `aria-label` nor `aria-labelledby`. Screen readers announce generic edit/combo controls without their purpose on every table using these filter variants.

**Fix:** Generate a stable ID per filter and use `<label htmlFor={id}>`, or connect the visible text with `aria-labelledby`. Add an accessible-name assertion for both search and long-option select filters.

### CR-03: [BLOCKER] Bulk selection disappears on mobile cards

**File:** `src/components/primitives/ResourceTable.tsx:700-768`

**Issue:** Selection checkboxes are rendered in desktop rows at lines 626-640 but are completely absent from the card representation below 640px. Mobile users cannot select, deselect, or initiate bulk actions, so the responsive mode does not preserve table behavior.

**Fix:** Render a labelled checkbox in each mobile card using the same `selectedIds` and `selection.onChange` logic, and cover mobile selection and bulk-action activation in tests.

### CR-04: [BLOCKER] Closed mobile staff navigation remains keyboard-focusable off-screen

**File:** `src/app/staff/StaffShell.tsx:114-160`

**Issue:** Closing the sidebar only applies `translate-x-full`. The `<aside>`, navigation links, and sign-out control remain mounted, visible to accessibility APIs, and in the tab order. Keyboard users encounter invisible controls before reaching the page content.

**Fix:** Make the closed mobile drawer truly non-interactive (`inert` plus appropriate `aria-hidden`, or conditional/mobile-specific rendering) while keeping the desktop sidebar active at `lg`. Move focus into the opened drawer and restore it to the menu trigger when closed.

### CR-05: [BLOCKER] Assignment authorization and form errors are deliberately discarded

**File:** `src/app/staff/users/AssignmentDrawer.tsx:133-160`

**Issue:** The drawer filters every error named `form` and renders only the remainder. The assignment action uses `form` for authorization and other non-field failures, so a denied/failed save can leave the drawer open with no explanation to the user.

**Fix:** Render `form` errors in a visible `role="alert"` banner and pass only genuinely field-addressable errors to field-level UI. Add a test for the action’s authorization-error result.

### CR-06: [BLOCKER] Assignment drawer claims modal semantics without trapping focus

**File:** `src/app/staff/users/AssignmentDrawer.tsx:78-95`

**Issue:** The component sets `aria-modal="true"`, but its effect only focuses the heading and handles Escape. Tab and Shift+Tab can move into the obscured page behind the drawer, violating the modal contract and making keyboard operation unreliable.

**Fix:** Reuse the focus-management implementation from `ConfirmModal`: enumerate focusable descendants, wrap forward/backward Tab, suppress Escape while pending, and return focus to the opener on close. Mark the background inert while open.

### CR-07: [BLOCKER] Publish dialog has no keyboard focus management

**File:** `src/components/catalogue/PublishDialog.tsx:94-100`

**Issue:** The publish confirmation is an `aria-modal` dialog but has no initial focus, focus trap, Escape behavior, or focus restoration. Focus remains on the obscured trigger and keyboard users can navigate the background during a high-consequence publish operation.

**Fix:** Implement the same complete dialog focus lifecycle as `ConfirmModal` (initial focus, Tab loop, Escape when not pending, and opener restoration), preferably by extracting and sharing one modal primitive.

### CR-08: [BLOCKER] A transient scan-poll failure permanently stops polling

**File:** `src/components/catalogue/UploadPanel.tsx:108-130`

**Issue:** The polling effect schedules one timer and only runs again when a dependency such as `resources` changes. The rejection path sets a message but leaves all dependencies unchanged, so no next timer is scheduled. A single network/server failure leaves pending uploads stuck at “Scanning” until a reload.

**Fix:** Run a bounded recursive timer/loop that schedules the next attempt from `finally` while pending resources and poll budget remain. Preserve abort/unmount cleanup, expose exhaustion separately, and test a rejection followed by a successful poll.

### CR-09: [BLOCKER] Programme outcomes are accepted by the action but omitted from the form

**File:** `src/app/staff/programmes/ProgrammeForm.tsx:14-20,84-109`

**Issue:** `Values` includes `outcomes`, the server action parses it, and public programme pages display it, yet the create/edit form renders no `outcomes` control. Staff cannot create or update this public content, and existing outcome text passed into the form is silently ignored.

**Fix:** Add a labelled multiline `FormField` named `outcomes` with the action’s 4,000-character constraint, default value, error association, and create/edit tests proving round-trip preservation.

### CR-10: [BLOCKER] Lesson preview permits a lesson from a different course URL

**File:** `src/app/staff/courses/[id]/preview/lessons/[lessonId]/page.tsx:35-56`

**Issue:** The route independently authorizes/loads the course and lesson, then explicitly renders even when the lesson is absent from that course’s tree. A crafted URL can combine Course A navigation/context with Course B lesson content and resources. Even where both scopes are authorized, this is misleading and breaks route integrity; it also makes future scope changes risky.

**Fix:** Resolve the lesson’s parent course and require it to equal `params.id`, or require `index >= 0`; otherwise call `notFound()` before loading/rendering resources. Add a cross-course route test.

### CR-11: [BLOCKER] Video lessons expose a captions track with no captions source

**File:** `src/components/catalogue/LessonMediaPlayer.tsx:36-47`

**Issue:** The video player renders `<track kind="captions">` without a `src`. It supplies no captions at all while presenting a captions track in markup, so prerecorded video lessons fail the phase’s WCAG accessibility requirement.

**Fix:** Provide a real, authorized WebVTT source and default/language metadata, or do not ship video lessons until captions are available. Add media accessibility coverage that rejects a video track with an empty/missing source.

### CR-12: [BLOCKER] Audit history is clipped instead of adapting at narrow widths

**File:** `src/app/staff/audit/AuditTable.tsx:239-340`

**Issue:** Unlike the phase’s responsive resource tables, the four-column audit table has no mobile/card representation or horizontal scroll region, and its container forces `overflow-hidden`. Intrinsic non-wrapping date/action content is clipped at narrow widths, making audit evidence inaccessible on the required 360px surface.

**Fix:** Add a semantic mobile card/list representation below `sm` (or an explicitly labelled local horizontal scroll region if the UI contract permits it) and never clip cells with `overflow-hidden`. Verify the route at 360px with long actor/action values.

## Warnings

### WR-01: [WARNING] Publish request leaves mutable controls enabled in-flight

**File:** `src/components/catalogue/PublishDialog.tsx:169-223`

**Issue:** Pending state disables Publish and Cancel but not cohort checkboxes or the reason textarea. Users can change the displayed selection/reason after the immutable request payload has already been submitted, creating ambiguity over what was actually published.

**Fix:** Disable all mutable dialog controls while pending and guard `toggle`; preserve and display the submitted payload until completion.

### WR-02: [WARNING] Error-summary links can target nonexistent fields

**File:** `src/components/primitives/ResourceForm.tsx:145-167`

**Issue:** Every error is rendered as `href="#field-${error.name}"`, including cross-field/form errors for which no element exists. Activating those links does nothing, despite the UI contract requiring the summary to link to each offending field.

**Fix:** Separate form-level errors into non-link alert text, and only render anchors when a matching field target exists. Support an explicit target ID in the error model for cross-field cases.

### WR-03: [WARNING] Rich lesson body errors are not associated with the editor

**File:** `src/components/catalogue/LessonFormFields.tsx:28-50`

**Issue:** `BodyEditor` renders the rich editor and error text without the `field-body` ID or `aria-describedby`/`aria-invalid` relationship used by normal `FormField` controls. A server `body` error therefore has a broken summary target and is not announced when the editor receives focus.

**Fix:** Extend `RichTextEditor` to accept the field ID and accessibility error attributes, give the error a stable ID, and connect both. Add a validation-error accessibility test for every lesson type.

### WR-04: [WARNING] Module failures discard the user’s edits and misplace the error

**File:** `src/app/staff/courses/[id]/arrange/ModuleComposer.tsx:75-82,104-133`

**Issue:** Rename closes immediately and add clears its input before either async operation succeeds. A failed rename loses the attempted text, while the shared server error is displayed under the unrelated “Module title” add field; a failed add also loses the entered title.

**Fix:** Make callbacks return a success result, await them, and only close/clear on success. Keep operation-specific error state beside the rename/add control that caused it.

### WR-05: [WARNING] Scope searches contain unhandled promise rejections

**File:** `src/app/staff/users/StaffAccountForm.tsx:50-60`

**File:** `src/app/staff/users/AssignmentDrawer.tsx:115-125`

**Issue:** Both scope-target searches call `.then(...)` without rejection handling. A network/server failure produces an unhandled rejection and leaves stale results or an empty-state message that falsely implies a successful search.

**Fix:** Add `catch` and `finally`, clear stale results on failure, render a retryable alert, and protect against late responses overwriting a newer query.

### WR-06: [WARNING] Imperative server-action handlers can strand the UI in busy state

**File:** `src/components/catalogue/CourseDetailActions.tsx:104-170`

**File:** `src/app/staff/programmes/[id]/ProgrammeDetailClient.tsx:83-138`

**File:** `src/app/staff/roles/RoleDetailPanels.tsx:69-157`

**File:** `src/app/staff/users/AssignmentsPanel.tsx:63-116`

**Issue:** These event handlers set local busy/pending state, await server actions, and clear state only on the normal resolved path. Transport failures and unexpected server exceptions reject out of the handler, bypass user feedback, and can leave controls disabled for the rest of the mounted session. Next.js error boundaries do not catch errors from event handlers.

**Fix:** Wrap imperative awaits in `try/catch/finally`, show a generic retryable error for unexpected failures, and clear the busy key in `finally`. Consolidate the repeated pattern in a small action runner or use action state where appropriate.
