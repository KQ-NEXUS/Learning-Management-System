## Amber fill contrast

**Notes:** Before asking, Claude inspected the mockup's pill constants and found pills are drawn as
tint-background + deep-ink-text + mid-tone dot, not as neutral pills with a coloured dot. That reframed
the question: the 2.36:1 amber fill is not used in pills at all, so the WCAG 1.4.11 bordered-pill
exemption UI-SPEC §5.4 proposed is unnecessary.

| Option | Description | Selected |
|--------|-------------|----------|
| Adopt the mockup's tinted pill | Three tones per colour; dissolves the contrast problem | ✓ |
| Keep the neutral pill, repalette the dot | Preserve today's structure, change the hex | |
| Tinted pill, but keep the neutral label | Maximum contrast safety, weaker signal | |

**User's choice:** Adopt the tinted pill.

| Option | Description | Selected |
|--------|-------------|----------|
| #b45309 — the roadmap's locked value | Already --warning today; no document contradiction | ✓ |
| #b54708 — the mockup's value | Exact match; requires amending the roadmap | |

**User's choice:** #b45309.

| Option | Description | Selected |
|--------|-------------|----------|

| Replace #e09b34 with #f79009 throughout | One amber fill from the mockup | ✓ |
| You decide during UI-SPEC regeneration | Claude's discretion | |

**User's choice:** Replace with #f79009.
**Notes:** Flagged at the time and recorded in CONTEXT.md — this amends ROADMAP criterion 2, which
names #e09b34 explicitly. The roadmap line needs correcting.

## Claude's Discretion

Four items, all consequences of the system-faithful decision rather than open questions, handed to the
regenerated UI-SPEC:

- The segmented filter control the mockup draws on staff lists vs `ResourceTable`'s select-and-chip filters.
- Responsive/narrow-viewport behaviour — the mockup is 1280px only.
- Dark mode — not drawn anywhere.
- The exact darkened input-border value satisfying the 3:1 requirement (`#667085` assumed).

## Deferred Ideas

- `RichTextEditor` loading affordance — pre-existing; a behaviour change beyond a restyle.

- Visual regression tooling — worth introducing after this phase lands, when baselines would protect
  future work.
- Dark mode — not in this phase's criteria.
- A fifth primitive for slide-over drawers — extract if a second drawer appears in Phase 5.
