## Trust Boundaries

|---|---|
| Client island → existing Server Action | The repair must not weaken, bypass or re-order any server-side authorization or optimistic-concurrency check |
| Rejected action → rendered feedback | An error surface must not leak server internals, and must never imply a mutation succeeded (or failed) when the outcome is unknown |
