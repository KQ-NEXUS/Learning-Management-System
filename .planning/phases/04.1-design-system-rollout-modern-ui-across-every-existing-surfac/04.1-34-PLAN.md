Close the **WR-02** and **WR-03** halves of **G-RV-03** from `04.1-VERIFICATION.md` (both raised in
`04.1-REVIEW.md`):

- **WR-02** — `LessonEditorClient`'s withdraw trigger (l.150) and the modal's `onCancel` (l.168)
  never reset `withdrawError`. `ConfirmModal` unmounts its body when closed, so on the next open the
  fresh dialog immediately renders the previous "The lesson was not withdrawn." alert before the
  user has done anything. `CourseDetailActions.openModal` clears its error for exactly this reason.
- **WR-03** — in `src/app/staff/courses/[id]/arrange/page.tsx` the `for` loop calling
  `listWithdrawnLessons` (l.47-56) sits outside the `try/catch` that maps `AuthorizationError` to
  `notFound()`. A denial there renders a 500 instead of the existence-hiding 404 the rest of the
  route is careful to return — an information-bearing difference between "you may not see this
  course" and "this course does not exist" (RBAC-06 denial parity).

Purpose: restore honest error state (NFR-09 error identification) and denial parity on the staff
catalogue-authoring routes.
Output: two localized repairs with committed regressions.

Scope discipline: no new route, data model, permission, service, dependency or capability; no class
or copy changes. The approved CONTEXT (D-01–D-26) governs.
