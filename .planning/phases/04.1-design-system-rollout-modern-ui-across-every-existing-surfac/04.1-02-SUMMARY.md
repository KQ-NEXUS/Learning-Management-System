The fix is minimal and scoped: one `useEffect`, no change to the component's props or contract.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical Functionality] Added error-summary focus management to `ResourceForm.tsx`**
- **Found during:** Task 2 (ResourceForm error-summary focus test)
- **Issue:** `ResourceForm.tsx`'s own JSDoc states "An error summary at the top links to each offending field, and receives focus after a failed submit (WCAG 2.2 AA, PRD NFR-09)," and this plan's must_haves list the same requirement. The code created a `summaryRef` and attached it to the summary `<div>` but never called `.focus()` on it anywhere — the behavior did not exist. Writing a test against unmodified source would have made the test red, not green, contradicting D-26's "these tests are written against the current, pre-migration implementations, so they are green before a single class changes."
- **Fix:** Added `useEffect(() => { if (errors.length > 0) summaryRef.current?.focus(); }, [errors]);` immediately after the existing ref declarations. `tabIndex={-1}` was already present on the summary div, making it a valid focus target without adding it to the tab order.
- **Files modified:** `src/components/primitives/ResourceForm.tsx`
- **Verification:** `tests/components/resource-form.test.tsx`'s error-summary test drives a real `fireEvent.submit`, awaits the summary appearing, and asserts `document.activeElement` is the summary element — passes. Full `components` project (89/89) still green afterward, confirming no other primitive/consumer regressed.

## Issues Encountered

- jsdom renders the desktop `<table>` and the mobile `<ul>` card list simultaneously (no CSS media-query enforcement), so unscoped `screen.getByText` queries for row content returned "multiple elements found" errors in three tests. Resolved by scoping to `within(container.querySelector("table"))`.
- A single overly-broad regex (`/\d{2,}/`) in the denial-parity test failed because the `denied` branch's fixed "403" eyebrow is itself a two-digit sequence, unrelated to any record-count leak. Resolved by asserting the absence of the specific fixture values (`"128"`, row titles, row codes) instead of a generic digit-count check.
- `fireEvent.click` on a `<form action={fn}>`'s submit button does not invoke the function action in jsdom under React 19 (confirmed via a throwaway repro test, not committed); `fireEvent.submit(formElement)` does. Documented as a pattern above for future test authors in this codebase.
