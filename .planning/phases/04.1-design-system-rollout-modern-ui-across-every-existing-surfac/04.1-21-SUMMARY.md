# Phase 04.1 Plan 21: Programme outcomes form parity Summary

The staff programme form now exposes the model's existing `outcomes` field as a labelled multiline control, so programme outcomes can be authored on create and edited without being silently dropped. Entered text survives unrelated field edits and rejected saves.

## What changed

- **`src/app/staff/programmes/ProgrammeForm.tsx`**
  - Added an `Outcomes` `FormField` rendering a `<textarea>` (`rows=4`, `maxLength=4000`) between Summary and Audience, with the primitive's aria wiring (`id`, `aria-invalid`, `aria-describedby`) and server-error association via the existing `errorFor("outcomes")` path.
  - The textarea is controlled from `useState(values.outcomes ?? "")`. This is required because React 19 automatically resets an uncontrolled form after a form action completes — including a failed one — which would discard the user's entered outcomes. Controlled state keeps the attempted text on screen after a rejected submit (CR-09, and the ResourceForm contract "a failed save never clears the entered values").
  - `createProgrammeAction` / `updateProgrammeAction`, the summary / slug / audience / sequential fields, and the `useActionState` result handling are unchanged. The field travels in `FormData` under the key `outcomes`, which the existing action already zod-validates (`z.string().trim().max(4000).optional()`).

- **`tests/components/programme-form.test.tsx`** (new, `components` project)
  - Create: submits multiline outcomes verbatim (newlines preserved); empty optional value is still sent as `""`; a server validation error for `outcomes` sets `aria-invalid` and a resolvable `aria-describedby` message.
  - Edit: stored outcomes render as the default; editing Title/Audience does not erase outcomes; a failed save keeps the attempted text and shows no "Saved." message; the control caps at `maxlength=4000` and an edited value round-trips through `FormData`.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 - Bug] Attempted outcomes text discarded on failed save**
- **Found during:** Task 2
- **Issue:** React 19 automatically resets a function-action form after the action settles, including on failure. A plain uncontrolled `<textarea defaultValue={...}>` therefore lost the user's entered outcomes after a rejected submit, violating the plan behaviour ("retain attempted outcomes after failed action results") and the ResourceForm contract.
- **Fix:** Made the outcomes textarea controlled (`useState`), so the entered value is re-applied from React state after the reset. Scope limited to the outcomes field; sibling fields were not touched.
- **Files modified:** `src/app/staff/programmes/ProgrammeForm.tsx`
