## Decisions Made

- **Icon-chip count resolved to exactly two screens, not three.** The codebase has three distinct "invalid or expired token" renders (verify, reset-password, confirm-email-change's own invalid branch), but the plan's acceptance criteria and UI-SPEC 8.5 both specify exactly two icon-bearing screens total (one expired-link state + confirm-email-change's success state). Verify's invalid branch was chosen to carry the alert chip; reset-password's structurally-identical invalid branch was left chip-free to hold the literal count. This is a judgment call on an unresolved mapping between the mockup's 28 screens and this codebase's finer-grained state count — flagged here per the plan's own instruction to "note the conflict in the plan summary rather than silently picking one."
- **Register/forgot-password heading ownership crossed the task boundary.** Task 2's file list was the six `page.tsx` files, and its action described replacing "each page's hand-rolled heading block with AuthTitle" — but `register/page.tsx` and `forgot-password/page.tsx` render no heading directly; it lives in `RegisterForm.tsx`/`ForgotPasswordForm.tsx` (task 3's file list). Handled the `AuthTitle` adoption for those two screens as part of task 3's edit to the form components, since both files were already in the plan's `files_modified` frontmatter.
- **No new raw-hex tokens for the auth panel's exact mockup colors.** The mockup specifies `#f7f8fa` (headline), `#9CA3AF` (subcopy), `#4B5563` (locale footer) for the left panel — none map onto an existing semantic or sidebar token. Used `text-sidebar-fg` for the headline and `text-sidebar-muted` for the subcopy and footer instead of introducing three new primitive-tier hex values, preserving the "zero raw hex outside globals.css" invariant (ROADMAP criterion 1) at the cost of an exact color match — consistent with D-04 (system-faithful, not pixel-faithful).
- **Brand tile has no inner SVG glyph.** Matched `StaffShell.tsx`'s established convention (plan 04.1-05: a plain gradient square, no bespoke logo SVG) rather than copying the mockup's inline SVG mark, for shell-to-shell visual consistency across the phase.
