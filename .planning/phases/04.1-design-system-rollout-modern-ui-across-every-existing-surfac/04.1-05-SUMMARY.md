# Phase 04.1 Plan 05: Staff Workspace Shell Rebuild Summary

**Rebuilt `staff/layout.tsx` + new `staff/StaffShell.tsx` client component: 228px navy sidebar (five real routes, no disabled placeholders), footer identity chip with email-derived-initials degradation, 48px header bar with a section-level locator trail, and an off-canvas collapse below 1024px — auth guard byte-for-byte preserved.**

## Accomplishments
- `staff/layout.tsx` stays a plain async Server Component: the actor lookup and its two ordered redirects (`/signin`, then `LEARNER_LANDING_PATH`) run before anything else, with the original explanatory comment intact, then delegates all chrome to a new client `StaffShell`.
- `NAV` cut from ten entries (five real, five `href: null` disabled placeholders) to exactly five real routes — Courses, Programmes, Users, Roles, Audit — and the `aria-disabled`/"Not built yet" render branch deleted entirely, so there is no code path left that promises a page the product cannot open (D-20).
- New `StaffShell.tsx`: 228px `bg-sidebar-bg` sidebar with a 140°-gradient brand tile, a non-interactive `aria-hidden` search chip (no `tabIndex`/`onClick`/`href`/form-control), a five-item nav with `aria-current="page"` on the active link (fill + weight + a 6px `bg-pill-blue-dot` dot together, never colour alone), and a footer identity chip that derives initials from the email local-part when no display name exists and omits the (nonexistent) role line entirely rather than reserving its height.
- 48px white header bar: a section-level locator trail derived from `usePathname()` (deliberately never a record-level breadcrumb — `DetailLayout` already owns that), the mono "Africa/Lagos" timezone, and the sign-out form slot passed in from the server layout.
- Content pane on `bg-surface-2` with `min-w-0` + 24/24/32px padding; sidebar, header bar and identity chip are rendered outside `children`, so a loading or erroring child route only ever swaps the content pane.
- Off-canvas collapse below 1024px: a real `<button>` with an accessible name, `aria-expanded`, and `aria-controls`; Escape closes the drawer and returns focus to the button; the button is `lg:hidden` (removed from the accessibility tree and tab order, not just visually hidden) at 1024px and above.
- Full neutral-ramp sweep of both files: zero `zinc-*`, zero `font-medium` (folded to `font-semibold`/`font-normal`), zero raw hex outside `globals.css`.

## Decisions Made
- `StaffIdentity` narrowed to `{ name, email } | null` rather than the full `ProfileSnapshot`, so the client component's props carry nothing beyond what the chip renders.
- Sign-out control restyled with header-bar tokens (`text-muted-foreground`/`text-foreground`) rather than sidebar tokens, since Task 2 moved it into the white header bar.
- Search-chip background and the inactive nav dot use opacity-modified existing tokens (`bg-sidebar-accent/10`, `bg-sidebar-muted/50`) rather than the mockup's two uncatalogued raw hexes (`#191c22`, `#374151`) — no token exists for either literal, and the zero-raw-hex invariant is a phase-wide gate that takes precedence over exact mockup-hex fidelity for these two cosmetic, non-text surfaces.
- The 1024px off-canvas toggle button is hidden via `lg:hidden` (CSS `display:none` at the breakpoint) rather than a JS/`matchMedia` conditional render — functionally equivalent for "not reachable by keyboard at 1024px+" (the acceptance criterion's real concern), while avoiding an SSR/hydration mismatch a stateful viewport check would introduce.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Route-change drawer reset rewritten to avoid two ESLint compiler-rule violations**
- **Found during:** Task 3 (off-canvas collapse)
- **Issue:** The natural implementation — closing the drawer in a `useEffect` keyed on `pathname` — tripped this repo's `react-hooks/set-state-in-effect` rule (`npx eslint src/app/staff` failed). Reworking it as a ref-based "previous value" comparison read/written during render then tripped a second, stricter rule, `react-hooks/refs` ("Cannot access/update ref value during render").
- **Fix:** Replaced the ref with `useState` for the previous-pathname comparison, applying React's documented "adjust state during render" pattern with state instead of a ref — `eslint` now passes clean, and the behavior (drawer closes exactly once per route change) is unchanged.
- **Files modified:** `src/app/staff/StaffShell.tsx`
- **Verification:** `npx eslint src/app/staff` exits 0; `npx tsc --noEmit` exits 0; `npx next build` exits 0; `npx vitest run --project components --no-file-parallelism` 89/89 pass.
