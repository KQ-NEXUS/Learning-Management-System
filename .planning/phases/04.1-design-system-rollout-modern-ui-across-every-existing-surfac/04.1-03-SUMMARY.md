# Phase 04.1 Plan 3: ResourceTable Restyle — Tinted Pills, Card Shell, Segmented Filters Summary

**`ResourceTable.tsx` restyled end-to-end to the approved system — tinted five-tone `StatusPill`, a 16px-radius/shadow-xs card table shell with a per-row initials tile, and a segmented filter control (auto-selected for <=4-option select filters) wired with named `lucide-react` icons — with zero remaining Tailwind `zinc-*` utilities, zero raw hex, and all 8 pre-existing state/parity tests still green.**

## Accomplishments

- **Task 1 — `StatusPill` + class constants:** `StatusPill` rewritten to the mockup's tinted pill (`bg-pill-{tone}-bg`/`text-pill-{tone}-ink` background+label, `bg-pill-{tone}-dot` dot, `rounded-full`, no border) across all five tone values, with the exported prop signature (`label`, `tone?`) byte-identical to before. `CELL`/`HEAD`/`BTN`/`BTN_PRIMARY` and `Panel` rewritten to consume semantic tokens: `HEAD` now resolves through `text-muted-foreground`; `BTN` gained `border-input-border`/`rounded-md`/`hover:bg-surface-2`; `BTN_PRIMARY` gained `rounded-md` and the brand glow via `shadow-[0_6px_18px_var(--accent-glow)]`; `Panel` became the shared card shape (`rounded-xl`/`border-border`/`bg-surface`/`shadow-xs`). Every weight-500 utility folded to `font-semibold`.
- **Task 2 — Table shell, state panels, footer:** The `ready` branch's table gained a card container (`rounded-xl`/`border-border`/`bg-surface`/`shadow-xs`, table clipped to the same radius); header row moved to `bg-surface-2`; row dividers/hover moved to `border-border`/`hover:bg-surface-2`; a new 34px `rounded-md` per-row initials tile (deterministic tone + initials, `aria-hidden`) was added ahead of the primary column in both the desktop table and the mobile card list, without disturbing the leading checkbox column's position. The denied/empty/error panels and the mobile card list all moved onto the shared `Panel`/card treatment; the denied branch's text content is unchanged word-for-word (only `className` values moved, confirmed by the still-passing denial-parity-by-diff test). Every remaining `zinc-*` utility in the file (loading skeletons, footer/selection bar, row/card borders, hover states, sort glyph color, mobile card meta text) was replaced with its semantic-token equivalent, and the table's `overflow-x-auto` was removed (the table is fully hidden below 640px in favour of the card list, so no horizontal-scroll mechanism is needed or permitted).
- **Task 3 — Segmented filter, icons, control edges:** A `select`-kind `TableFilter` with 4 or fewer options now renders as a `role="group"` segmented control (`bg-surface-2` track, active segment `bg-surface`/`shadow-xs`/`text-foreground`, each segment `aria-pressed`), calling the exact same `onFilterChange` prop the `<select>` fallback (used for filters with more options) still calls — filters/sort keep reading from and writing to the URL untouched. Added named `lucide-react` imports only (`ArrowDown`, `ArrowUp`, `ArrowUpDown`, `Plus`, `Search`, `X`): `Search` inside the search input, `Plus` beside the create-action label, `X` on the query-chip dismiss button (its `aria-label="Clear all filters"` was already independent of the chip's visible query text and is preserved), and `ArrowUp`/`ArrowDown`/`ArrowUpDown` as `aria-hidden` decoration on sortable column headers (the header's `aria-sort` attribute remains the sole source of sort-state semantics). The search input, the fallback `<select>`, and the segmented control's group container all take `border-input-border`/`rounded-md` at the 38px (input/select) / 32px (segment track) heights UI-SPEC 3.2 specifies.
