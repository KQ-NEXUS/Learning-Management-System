## Decisions Made

See `key-decisions` frontmatter. In short: staff controls/buttons adopt the primitive control role (`px-4 py-2 text-sm`); breadcrumb trail stays 14px per UI-SPEC 4.3; `text-xs` resolves by context (14px body vs 11px eyebrow), not a blanket micro downshift; one 14px `<h2>` promoted to the 16px card-heading role.

## Deviations from Plan

None requiring deviation rules. This is a styling-only class-role sweep exactly as scoped. No bugs, missing functionality, blocking issues, or architectural changes were encountered. Locked exceptions D-21 (`gap-5` in auth files) and D-23 (learner-shell header padding) are in other files and were not touched.

One in-scope judgement worth flagging for the verifier: `StaffAccountForm`'s "Staff account created" `<h2>` was at `text-sm` (14px), which is a valid size but the wrong *role* for a card/section heading. It was promoted to `text-base` (16px) to match every sibling `<h2>`. This changes rendered size of one heading not strictly flagged by the mechanical grader.

## Threat Flags

None. No new network endpoints, auth paths, file-access patterns, or schema/trust-boundary changes. All server actions, bound IDs, permission checks, `fieldError` wiring, and ConfirmModal reason gating are byte-for-byte unchanged (className attributes only).
