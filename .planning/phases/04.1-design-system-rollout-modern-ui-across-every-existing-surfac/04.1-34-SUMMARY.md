# Phase 04.1 Plan 34: WR-02 / WR-03 Gap Closure Summary

**The staff lesson-withdraw modal no longer shows a stale failure alert on reopen, and a denied withdrawn-lesson load on the course arrange route now returns the same existence-hiding 404 as a missing course instead of a 500.**

## Performance

- **Duration:** ~25 min
- **Started:** 2026-09-07T12:26:00Z (approx)
- **Completed:** 2026-09-07T12:33:00Z (approx)
- **Tasks:** 2 (both TDD: RED + GREEN)
- **Files modified:** 4 (2 source, 2 new tests)

## Accomplishments

- **WR-02** — `LessonEditorClient`'s withdraw trigger `onClick` and the `ConfirmModal`'s `onCancel` now call `setWithdrawError(null)` before toggling `withdrawOpen`. `ConfirmModal` unmounts its body when closed, so the previously-set `withdrawError` was re-rendered as an "Action not applied" alert the moment the dialog reopened, accusing the user of a failure they had not retried. The `confirmWithdraw` success path, the `withdrawing` lifecycle, all copy and all class strings are unchanged; no new `ConfirmModal` prop.
- **WR-03** — the `for (const meta of moduleMeta)` loop calling `listWithdrawnLessons` in `arrange/page.tsx` is now wrapped in its own `try/catch` that maps `AuthorizationError` to `notFound()` and rethrows everything else, mirroring the comment and shape of the `courseService.get / loadCourseTree / listWithdrawnModules` block above it. `if (!course || !tree) notFound()` stays outside every `catch`; service call order, the `withdrawnLessons` shape, `structureKey` and the rendered markup are untouched.
