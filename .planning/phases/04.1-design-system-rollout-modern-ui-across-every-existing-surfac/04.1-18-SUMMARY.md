# Phase 04.1 Plan 18: Publish confirmation and catalogue action recovery Summary

**PublishDialog is now keyboard-operable with an immutable in-flight payload, and the course/programme detail action bars recover from unexpected Server Action rejection instead of stranding disabled controls or claiming false success.**

## Performance

- **Duration:** ~32 min
- **Started:** 2026-09-06T21:38:00Z
- **Completed:** 2026-09-06T21:58:00Z
- **Tasks:** 3
- **Files modified:** 3 modified, 3 test files created

## Accomplishments

- PublishDialog: focus moves into the dialog on open and returns to the opener on close; Tab / Shift+Tab wrap inside it; Escape cancels only while idle and is suppressed while a publish is in flight.
- PublishDialog: every cohort migration checkbox and the reason textarea are disabled while pending, and the toggle/submit handlers are guarded so a mid-flight interaction cannot change the confirmed `{ migrateCohortIds, reason, expectedUpdatedAt }` payload. No bulk "select all" control was added (D-06).
- CourseDetailActions: `runListing`, `runPublish` and `runReasoned` wrapped in try/catch/finally — busy key cleared in `finally`, generic retryable message on unexpected rejection, dialog/modal + typed reason retained for a deliberate user retry, no auto-repeat.
- ProgrammeDetailClient: same try/catch/finally lifecycle applied to listing, publish and reasoned (unpublish/archive/un-archive) mutations.
- Existing resolved-failure branches (COHORTS_RUNNING, NOT_READY, DENIED, etc.) and all authorization/action contracts are unchanged; the server gate remains authoritative.

## Decisions Made

- Reused the `ConfirmModal` focus-trap + focus-return pattern directly in `PublishDialog` rather than extracting a shared drawer primitive — the plan explicitly forbids a fifth primitive and names ConfirmModal as the local precedent.
- Catch branches render fixed generic copy and never interpolate the caught error, satisfying threat T-04.1-G18-02 (no repudiation / no raw disclosure) and T-04.1-G18-01 (never assert success after a rejected mutation).
- `finally` (not an inline `setBusy(null)` before the result check) owns busy-clearing so a thrown rejection can never leave a control disabled.
