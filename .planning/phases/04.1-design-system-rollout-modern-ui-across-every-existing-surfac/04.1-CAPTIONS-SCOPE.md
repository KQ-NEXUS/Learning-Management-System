# Captions scope decision — UNRESOLVED (CR-11 / NFR-09 accessible media)

Status: **OPEN — requires user scope approval.** Plan 04.1-23 delivered only
partial remediation. This does NOT close CR-11 and NFR-09 remains **pending**.

## What plan 04.1-23 changed

`src/components/catalogue/LessonMediaPlayer.tsx` no longer emits a
`<track kind="captions">` element. That element had **no `src`**: the browser
rendered a "captions" entry in the native player menu that resolved to nothing.
Removing it stops the player advertising an accessibility feature that does not
exist. Native `<video>` controls, the authorized presigned `src`, the download
fallback link and the malware-scan gate are all unchanged and still functional
(`tests/components/lesson-content.test.tsx`).

This is honest markup, not accessible media. A learner who needs captions still
has no captions.

## Evidence read from current source (why a styling edit cannot supply real captions)

| Fact | Location |
|---|---|
| `Lesson` has `body`, `embedUrl`, `linkUrl` — **no captions / transcript field** | `prisma/schema.prisma` model `Lesson` |
| `LessonResource` has file metadata + scan status — **no caption/language/track association to a video** | `prisma/schema.prisma` model `LessonResource` |
| VIDEO upload allow-list accepts **only `video/mp4` and `video/webm`** — no `text/vtt` | `src/lib/upload-limits.ts` (`UPLOAD_LIMITS.VIDEO.mimeTypes`) |
| `LessonMediaPlayer` props are **only `src` and `title`** | `src/components/catalogue/LessonMediaPlayer.tsx` |

A lesson `title` or `body` is not a transcript and must not be presented as one.
There is no authorized WebVTT object to point a `<track src>` at.

## Proposed narrow follow-up (needs its own approval — NOT authorized here)

A separately scoped and approved plan could introduce:

1. A **scanned WebVTT resource** associated with a specific video resource
   (same malware-scan gate as every other upload).
2. **Language + label metadata** on that caption resource.
3. **Authorized delivery** of the `.vtt` through the existing short-lived
   presigned-URL download path.
4. **Staff authoring**: selecting/uploading a caption file for a video lesson.
5. A **publication-readiness** policy decision — whether a VIDEO lesson may
   publish without captions, or is warned/blocked.

This changes the **upload allow-list and the data model** (new fields and/or a
new relation, likely a schema migration). It is therefore **outside the phase
04.1 locked "no new route, data model, permission, bulk mutation or export"
boundary** (see `04.1-GAP-COVERAGE.md`). Exact schema shape and backwards
compatibility must be planned only after scope approval.

## Explicitly rejected non-options

- Hiding or disabling working video to claim an accessibility win — removes an
  existing capability, prohibited by the locked boundary and D-26.
- Fabricating captions/transcripts from the lesson title or body.
- Claiming CR-11 closed or NFR-09 met on the strength of the track removal.

## Carry-forward

Plan 04.1-29 must report this decision as unresolved and keep NFR-09 (accessible
media alternatives) **pending**. Phase 04.1 must not be marked complete on the
basis of plan count.
