# Phase 04.1 Plan 19: Form summaries and rich-editor error associations Summary

The create/edit error summary no longer offers links that go nowhere: a summary entry
becomes a link only when a matching `field-<name>` control is present in that form, and
cross-field / form-level failures render as plain alert text. The rich lesson-body editor
now carries the same error wiring as an ordinary field, so a server `body` error is a real
summary target and is announced when the editor takes focus.

## What changed

- **`src/components/primitives/ResourceForm.tsx`**
  - Added a `formRef` and a `linkableNames` set recomputed after every commit (via an
    isomorphic `useLayoutEffect` — synchronous before paint client-side, `useEffect` on the
    server where there is nothing to measure). It collects the `id`s present inside this
    form and keeps only the error names whose `field-<name>` control actually exists.
  - The summary list renders an `<a href="#field-<name>">` only for names in that set;
    every other message renders as a plain `<span>` inside the same `role="alert"` region.
  - Heading copy changed from "N fields need attention" to "N issues need attention" so it
    stays accurate when some entries are form-level, not field-level. The "…before this can
    be saved" phrasing is retained.
  - `FieldError` doc comment updated; the type shape (`name`, `message`) and the `FormField`
    render-prop API are unchanged. Summary focus-on-appearance and failed-submit value
    retention are unchanged.

- **`src/components/catalogue/RichTextEditor.tsx`**
  - New optional props `id`, `aria-invalid`, `aria-describedby`. They are assembled (with a
    fixed `aria-label: "Lesson body"`) into a memoised `editorProps.attributes` object keyed
    on those three values and passed to `useEditor`, so Tiptap applies them to the ProseMirror
    editable node on creation and re-applies them (new object identity) whenever the wiring
    changes. The D-29 extension allow-list, sanitisation pipeline, toolbar and inline link
    editor are untouched.

- **`src/components/catalogue/LessonFormFields.tsx`**
  - `BodyEditor` now passes `id="field-body"` to `RichTextEditor` always, and
    `aria-invalid` / `aria-describedby="body-error"` when a `body` error is present. The
    error paragraph carries `id="body-error"`. Hidden submitted `body` field, the controlled
    `useState` body value, sanitisation, and the D-25 empty-editor placeholder hint are
    unchanged. QUIZ / ASSIGNMENT still expose only the disabled Phase 10 assessment picker.

- **`tests/components/resource-form.test.tsx`** — 3 new cases: form-level errors render as
  plain alert text not links; only errors with a real control in the form become links
  (absent-field mixed case); every rendered summary link resolves to a document element.

- **`tests/components/rich-text-editor.test.tsx`** — 3 new cases: id / aria-invalid /
  aria-describedby forward to the `[contenteditable='true']` node; the association updates
  when props change; the attributes are omitted when no error props are given. Local
  `RichTextEditorProps` type extended.

- **`tests/components/lesson-form-fields.test.tsx`** — mock `RichTextEditor` updated to
  forward `id` / `aria-invalid` / `aria-describedby`; new cases assert the body error is
  wired to the editor and resolves a description for TEXT / FILE / IMAGE / VIDEO / EMBED /
  LINK, that no invalid association exists without an error, and that QUIZ / ASSIGNMENT
  expose no body editor even with a `body` error present.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 - Bug] Error-summary anchor appeared one render late under the initial `useEffect` approach**
- **Found during:** Task 1
- **Issue:** Resolving link targets in a plain `useEffect` left the first commit rendering
  the message as a `<span>`, then swapping to an `<a>` on the next tick. The existing
  regression test (`a non-empty errors array renders a summary … linking to each offending
  field`) read the link synchronously and failed.
- **Fix:** Switched to an isomorphic `useLayoutEffect` (falls back to `useEffect` on the
  server) so the link/text decision is applied before paint, in the same commit cycle. No
  visible flash; existing test passes unmodified.
- **Files modified:** `src/components/primitives/ResourceForm.tsx`
- **Commit:** 119d9dd
