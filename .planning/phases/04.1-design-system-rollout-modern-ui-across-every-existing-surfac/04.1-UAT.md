# Phase 04.1 — User Acceptance / Visual Walkthrough (PASS)

Status: **PASS** — phase-owner walkthrough completed 2026-09-07. One issue
(staff sidebar scroll) found and fixed pre-sign-off; captions and security
advisory decisions recorded. See section D for the outcome and the two recorded

## Ground rules (read before starting)

- **No human result may be inferred from jsdom component tests or source scans.**
  `04.1-GAP-VALIDATION.md` records green automated gates (full suite, design
  contract, lint, types, build). Those grade DOM semantics and class strings, not
  rendered geometry. Every row below still needs a human eye in a browser.
- **D-26 stands: no visual-regression tooling this phase.** Baselines captured
  after the redesign would prove nothing about the redesign itself, and the
  Playwright MCP server was unavailable. Visual judgement on a redesign is human.
- **Accessible media / captions is an OPEN scope decision** — see
  `04.1-CAPTIONS-SCOPE.md`. No captions authoring, no WebVTT data model, no
  caption delivery has been authorized or implemented. Plan 23 only removed a
  source-less `<track>` element. **NFR-09 remains PENDING.** A learner who needs
  captions still has none.
- **Scope decision required at handoff:** the person running this walkthrough (or
  the phase owner) must decide whether to approve the narrow captions follow-up
  proposed in `04.1-CAPTIONS-SCOPE.md` (new upload/data contract, likely a schema
  migration — outside the phase 04.1 locked boundary) or to keep video lessons
  shipping without captions and carry NFR-09 as an accepted known gap. **Do not
  manufacture user acceptance; this decision is the user's.**
- **Five low-severity security advisories** (`T-04.1-05, 09, 14, 17, 22` in
  `04.1-SECURITY.md`) remain advisory-open. No high-severity threat is open.
  Prior plans' `accept` disposition is not user acceptance; leave them open unless
  the user explicitly accepts.
- Reference: `04.1-MOCKUP-SOURCE.html` (the design contract), `04.1-UI-SPEC.md`
  §7 (per-shell prose + state coverage), `04.1-CONTEXT.md` D-01..D-26.

## Environment for the walkthrough

- `npm run build && npm start` (or `npm run dev`) against seeded data
  (`npm run db:seed`). Build is confirmed green (`04.1-GAP-VALIDATION.md` gate 5).
- Browsers: at minimum one Chromium-based + one Firefox. Windows required for the
  High Contrast and Segoe UI Variable checks.
- Viewports to exercise on every screen: **360px, 768px, 1024px, 1440px**, plus a
  **short-height** window (≈ 600px tall) for the auth split panel and every
  dialog.

### Backstop rows — must survive the migration (14)

Each is "preserve-through-migration"; an unwired backstop routes to
`human_needed`, not a silent pass.

1. ☐ **ResourceTable / long-text** — long cell values and long `noun` strings do not break the <640px card layout or force horizontal scroll.
2. ☐ **ResourceForm / overflow** — error summary with many simultaneous field errors stays readable and does not push submit off-screen under the new card/shadow.
3. ☐ **ResourceForm / long-text** — long field labels and long validation messages wrap, not clip, with the darkened `--input-border` (D-15).
4. ☐ **DetailLayout / overflow** — tabbed mode with many sections does not overflow the tab strip at narrow widths; the 2px active-underline does not clip.
5. ☐ **DetailLayout / long-text** — long record title / breadcrumb / `DetailFacts` value wraps without breaking the header or facts grid under the new type scale (§4.3).
6. ☐ **ConfirmModal / overflow** — long `description` + long typed reason keeps confirm/cancel reachable with `shadow-card` + 16px radius.
7. ☐ **ConfirmModal / long-text** — long `title` / `confirmLabel` does not break the dialog header or button row.
8. ☐ **Auth / loading** — each of the 6 screens keeps its submit-pending state inside the new split-panel `layout.tsx`.
9. ☐ **Auth / overflow** — 378px stack still centres at short viewport height; left-panel headline/subcopy does not collide with the locale footer at short height.
10. ☐ **Auth / long-text** — long error and hint copy does not overflow the 378px column.
11. ☐ **Public catalogue / partial** — a published item missing an optional field (no description / price / image) renders without a hole in the grid.
12. ☐ **Public catalogue / overflow** — 2-col grid reflows to 1 col at narrow width with no horizontal scroll.
13. ☐ **Public catalogue / zero-one-many + long-text** — a single published course does not read as a broken grid at 1080px max; a long title does not break card alignment.
14. ☐ **Account / overflow + long-text** — 2-col `1fr 300px` grid collapses to one column without breaking the marketing-toggle / sessions cards; a long display name / email does not break the wide header.

## C. Cross-cutting checks (all screens)

- ☐ **Keyboard menu** — mobile staff sidebar: closed drawer is `inert` / out of the tab order; opening moves focus into the drawer; closing restores focus to the menu trigger (CR-04).
- ☐ **Keyboard dialog focus** — `ConfirmModal`, `PublishDialog`, `AssignmentDrawer`: initial focus set, Tab/Shift+Tab wrap inside, Escape closes only when not pending, focus returns to the opener (CR-06, CR-07).
- ☐ **Mobile bulk selection** — `ResourceTable` card mode <640px renders a labelled checkbox per card using the same `selectedIds` / `onChange`; bulk actions are reachable (CR-03).
- ☐ **Mobile audit** — `/staff/audit` at 360px: semantic cards, complete details, nothing clipped (CR-12).
- ☐ **Failed action retry** — trigger a server-action failure (offline the network) on `CourseDetailActions`, `ProgrammeDetailClient`, `RoleDetailPanels`, `AssignmentsPanel`, `PublishDialog`, `ModuleComposer`, scope searches: a generic retryable error shows and the control does not stay stuck disabled (WR-05, WR-06, CR-08).
- ☐ **Upload scan polling** — start an upload, interrupt the scan-status endpoint once, restore it: polling recovers and the resource reaches CLEAN; a permanently-failing endpoint shows the terminal "reload the page" message and stops (CR-08).
- ☐ **Actual loaded font stack (D-05)** — on Windows, body/UI text renders in **Segoe UI Variable**; on macOS/Linux/Android it falls through to **Plus Jakarta Sans** (loaded via `next/font/google`). Tabular figures / mono eyebrows / the auth locale footer render in **IBM Plex Mono** (D-06). Confirm no Geist fallback leaks through. Accept that Windows and non-Windows users see different faces (D-05, known and accepted).
- ☐ **Windows High Contrast Mode** — enable WHCM: focus outlines remain visible, status pills stay distinguishable, the navy sidebar and split panel do not disappear, form control borders are still perceivable (D-15).
- ☐ **404 recovery copy** — `src/app/not-found.tsx` and `src/app/(public)/not-found.tsx` show the approved UI-SPEC §6.2 recovery copy verbatim (plan 26 restored this) and render on the correct shell.
- ☐ **Long content** — paste a very long lesson body, a very long course title, a very long typed confirm reason: layouts wrap/scroll locally, nothing clips or pushes primary actions off-screen.
- ☐ **Locked spacing exceptions** — confirm by eye that the auth form-stack gap is **20px** (D-21) and the learner header padding is **14px / 28px** (D-23); everything else sits on the 4/8/16/24/32/48 grid.
- ☐ **60/30/10 colour balance** — neutral ground dominates, blue is the brand accent, teal appears only as state (progress/pass/grade) and never on a button/link/focus ring/active nav (D-08, D-09), green stays distinct for success (D-10), danger is `#b42318` on `#fdf3f2` (D-11).
- ☐ **48px depth model on dense staff tables** — check the `honest` annotation risk: shadows do not visually stack into mud where staff list/table cards sit close together (D-18 — dense surfaces use `--shadow-xs`, not `--shadow-card`).
- ☐ **RBAC-06 denial parity** — a denied record and a nonexistent record render identical copy (no count/title/id leak); the visual restyle introduced no distinguishing cue.
