# Phase 04.1 Plan 23: Resilient Upload Polling and Truthful Lesson Previews Summary

Closed the three source-confirmed gaps for wave 1: scan-status polling now
recovers from a transient failure instead of stranding scanning resources; the
learner-view lesson preview rejects a cross-course context before loading any
resources while still previewing authorized withdrawn lessons; and the video
player no longer advertises a captions track that has no source. Real caption
delivery is recorded as an explicitly unresolved scope decision.

## What shipped

### Task 1 — Resilient scan-status polling (`fix(04.1-23)` adf386f)
- `UploadPanel` replaced its dependency-triggered one-shot poll (which never
  re-ran after a rejected fetch, because a failed poll changed no state — CR-08)
  with a **recursive bounded timer** that reschedules itself from `finally`
  while mounted and while pending resources remain.
- A rejected attempt still spends one unit of the finite poll budget, so a
  permanently failing endpoint cannot spin forever.
- Only one request is ever in flight (`inFlight` guard + scheduling only from
  `finally`); the timer is cleared on unmount or once nothing is pending.
- Two distinct messages: a transient "trying again" notice vs. the terminal
  "reload the page" instruction once the budget is spent.
- Budget restarts on a fresh upload or manual retry via a `pollEpoch` state
  counter (a boolean `hasPending` would not change and would leave the loop
  stranded on a spent budget).
- Regressions added: transient-rejection-then-CLEAN recovery, repeated
  exhaustion, no-overlap, unmount cancellation.

### Task 2 — Validate lesson parent before loading preview resources (02d1e6d)
- New `resolveCourseIdForLesson(lessonId)` in `lesson-service.ts`: resolves
  `Lesson -> Module -> Course` through the real relation, **including withdrawn
  lessons and modules**. No permission wrapper, in the documented spirit of
  `getLessonTypeById` — the only caller authorizes `courses.view` on both the
  route course and the lesson's own parent first.
- The learner-view preview page now calls it after existing course + lesson
  authorization and **before** `loadCourseTree` / `listLessonResources`; a
  mismatch, a missing lesson, or a null parent all take the same `notFound()`
  path (CR-10, T-04.1-26).
- `loadCourseTree` membership is deliberately **not** used as the check: that
  query filters `withdrawnAt: null`, and an authorized withdrawn lesson must
  stay previewable.
- New `tests/lesson-preview-route.test.ts` (node project): same-course active
  and withdrawn previews load resources; cross-course id and unknown id are
  rejected with `listLessonResources`/`loadCourseTree` never called;
  authorization-denial parity.

### Task 3 — Remove false captions affordance, record open scope (5746856)
- `LessonMediaPlayer` no longer emits `<track kind="captions">` — it had no
  `src` and rendered a dead "captions" entry in the native menu (CR-11).
- Native controls, authorized `src`, download fallback and the scan gate are
  unchanged; a CLEAN video stays rendered and playable.
- `lesson-content` test now asserts **no emitted `<track>` lacks a real
  source** and that a CLEAN video still renders.
- `04.1-CAPTIONS-SCOPE.md` records the concrete source evidence (no captions
  field on `Lesson`/`LessonResource`, VIDEO allow-list is mp4/webm only, player
  props are `src`/`title` only) and proposes a narrow, separately-approved
  follow-up (scanned WebVTT resource + language metadata + authorized delivery
  + authoring + publication policy). That follow-up changes upload/data
  contracts and is **outside** the locked phase boundary.
