# Phase 04.1 Plan 20: Readable Mobile Audit History Summary

**Below sm the staff audit log now renders one semantic card per event with an expand-in-place detail that shows the same actor, scope, outcome, reason and before/after diff as the desktop table, with long identifiers wrapping instead of forcing a horizontal scroll.**

## Performance

- **Duration:** ~24 min
- **Started:** 2026-09-06T21:40:00Z
- **Completed:** 2026-09-06T21:52:00Z
- **Tasks:** 2 (both TDD)
- **Files modified:** 2 (1 created, 1 modified)

## Accomplishments

- Desktop table is hidden below `sm`; a `ul[aria-label="Audit history"]` card list takes over so nothing scrolls sideways (D-04).
- Each mobile card is a single expand toggle carrying `aria-expanded` / `aria-controls`, exposing actor, actor email, action, target type + full target id, and timestamp.
- Extracted `EventDetail` so the revealed evidence (scope, outcome, reason, field-level diff or the explicit "no field-level changes recorded" note) is identical for the desktop expand-in-place row and the mobile card.
- `min-w-0` + `[overflow-wrap:anywhere]` on actor / action / target and the preformatted diff container; the inner monospace target-id span also wraps.
- Desktop and mobile expansion controls for the same event now carry distinct, unique ids (`audit-row-detail-<id>` vs `audit-card-detail-<id>`).
- New `tests/components/audit-table.test.tsx`: 11 passing assertions + 1 skipped manual gate.

## Decisions Made

- The single `expandedId` state is deliberately shared by both representations; only one detail is ever open. Tests exercise the desktop and mobile toggles independently rather than asserting both open at once.
- Kept the desktop `shortenId` truncation for the target column; the mobile card shows the full id (a mobile reader has no hover or wide column to fall back on).
- No pagination branch was added - `auditReadService.list` returns an unpaginated set today and the plan's "preserve pagination" note has nothing to preserve.
