# Phase 04.1 Plan 07: Shared Learner Shell for the Public Catalogue and /account Summary

**One `LearnerShell` component now backs both the guard-free public catalogue and the single-guarded `/account`, which widened off its narrow auth-style column onto a 1fr/300px grid with a restyled toggle switch for the marketing preference.**

## Performance

- **Duration:** ~60 min
- **Tasks:** 3
- **Files modified:** 4 (plus 1 new file)

## Accomplishments

- Built `src/components/shell/LearnerShell.tsx` — a client component owning only chrome (white top bar, gradient brand tile, active-underline nav, caller-supplied right slot, 1080px body container on `bg-surface-2`) with zero actor lookups and zero redirects; the sub-640px nav collapses behind an accessible menu button (`aria-expanded`, `aria-controls`, Escape-to-close, focus return) using the same CSS-display-toggle precedent StaffShell established.
- Rewrote `src/app/(public)/layout.tsx` to instantiate `LearnerShell` with the Courses/Programmes nav and a "Sign in" outline button, keeping its plain non-async, guard-free function signature exactly as before.
- Rewrote `src/app/account/layout.tsx` to keep its single `getCurrentActor()` + `redirect("/signin")` guard (no staff check) verbatim, delete the narrow `max-w-sm` centred wrapper entirely (taking the repo-wide occurrence count of that duplicated string to zero), and instantiate `LearnerShell` with the Catalogue/Account nav and a 30px teal-gradient avatar whose initials derive from the display name or, absent one, the email local-part — with an accessible label naming the signed-in account.
- Rebuilt `/account`'s page and form: a `1fr 300px` grid (main column: Your details + Email address cards; right rail: Marketing emails card) that collapses to one column below the `sm` breakpoint, renamed section headings and approved subcopy from UI-SPEC 6.2, and the marketing `<input type="checkbox" name="marketingOptIn">` restyled as a 38×22px pill-track/18px-knob switch via `peer`/`peer-checked`/`peer-focus-visible` CSS — the underlying checkbox, its server-controlled `checked`, its `disabled`-while-pending state, and the form's `onChange`-triggered `requestSubmit()` are all unchanged.
