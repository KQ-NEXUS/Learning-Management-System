# Phase 04.1: Design System Rollout Verification Report

**Phase Goal:** Every surface already built — public catalogue, auth, account and the whole staff console — moves onto one approved design system, so Phase 5 onward is built to it rather than retrofitted.
**Verified:** 2026-09-06T08:04:52Z
**Status:** gaps_found

## Goal Achievement

The common token, shell, layout, and primitive foundations are present, and all automated build and regression gates pass. The phase goal is nevertheless not achieved yet: source inspection found shipped controls that cannot complete their advertised tasks, mobile behavior loss, keyboard-focus failures, unnamed filters, inaccessible media, and widespread mechanical drift from the approved spacing and typography contract. Those defects directly contradict the requirement that core public, learner, and staff journeys align with WCAG 2.2 AA.

## Gaps

### G-04.1-01 — Restore complete task behavior on staff surfaces

- Wire, explicitly disable with explanation, or remove the four visible no-op controls in `CoursesTable.tsx`.
- Preserve row selection and bulk actions in `ResourceTable` mobile cards.
- Add the omitted `outcomes` field to `ProgrammeForm`.
- Make audit history readable at 360px without clipping.
- Add interaction/responsive tests for each corrected behavior.

### G-04.1-02 — Close keyboard, semantics, and error-identification failures

- Give shared search/select filters programmatic accessible names.
- Make the closed mobile staff drawer inert and manage focus on open/close.
- Give `AssignmentDrawer` and `PublishDialog` a complete modal focus lifecycle.
- Render assignment form/authorization errors and correctly associate rich-editor errors.
- Add keyboard and accessible-name regression tests.

### G-04.1-03 — Close media, route-integrity, and resilience gaps

- Supply a real authorized captions source for video or prevent inaccessible video publication.
- Reject lesson-preview URLs whose lesson does not belong to the course in the URL.
- Continue bounded upload scan polling after transient failures.
- Ensure imperative async action handlers recover from rejected calls and clear busy state.

### G-04.1-04 — Reconcile implementation with the approved visual contract

- Replace blank gradient brand tiles with the approved mark.
- Enforce the approved typography scale and spacing grid across the rolled-out surfaces.
- Add mechanical gates for the enforceable typography/spacing rules and perform rendered visual verification at required viewports.

## Human Verification

Human visual and browser testing remains necessary after the gaps above are fixed, especially at 360px and for keyboard-only modal/navigation flows. It cannot convert the current verdict to `human_needed`, because the present source-confirmed functional and accessibility failures must be corrected first.

## Verdict

**GAPS FOUND.** Phase 04.1 has a strong shared design-system foundation and clean automated regression results, but it does not yet meet its stated end-to-end rollout goal or NFR-09. Create and execute focused gap-closure plans, then re-run verification before marking the phase complete.
