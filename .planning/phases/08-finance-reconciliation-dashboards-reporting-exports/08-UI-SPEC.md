# Phase 08 — UI Design Contract

> Visual and interaction contract for Finance Reconciliation, Dashboards & Reporting Exports. Generated by gsd-ui-researcher for verification by gsd-ui-checker.

---

## 0. Grounding and Scope

This phase adds staff-only finance and reporting surfaces inside the existing KQ NEXUS workspace. It extends the Phase 7 payments presentation; it does not create a second payment ledger, modify learner checkout, or introduce learning, assessment, certificate, or support workflows that belong to later phases.

The visual hierarchy must communicate trust before decoration:

1. unresolved financial exceptions and their risk are immediately visible;
2. totals always state currency, filters, business-date basis, and `as of` time;
3. every metric offers a row-level reconciliation path when the dataset is available;
4. zero, unavailable, pending, expired, failed, and not-applicable are distinct states;
5. no UI control implies that resolving an investigation changes money, enrolment, refund, or settlement records.

All D-01 through D-24 decisions in `08-CONTEXT.md` are binding. The user's 2026-09-15 design-system checkpoint additionally locks continued use of the existing KQ NEXUS Tailwind v4 system; shadcn must not be initialized or introduced.

### 0.1 Surface inventory

| Surface | Route contract | Purpose |
|---------|----------------|---------|
| Reconciliation queue | `/staff/reconciliation` | Exception-first queue, provider tabs, summary totals, bulk assignment, and link to the full payment ledger |
| Reconciliation detail | `/staff/reconciliation/[caseId]` | Evidence, expected/actual values, assignment, append-only history, corrective links, and individual resolution |
| Reports hub | `/staff/reports` | Concise headline overview and navigation to the ten fixed dashboards |
| Fixed report | `/staff/reports/[dataset]` | Definition, date basis, filters, metrics, accessible breakdown, drill-down rows, refresh, and export |
| Export history | `/staff/reports/exports` | Permitted asynchronous jobs, lifecycle status, downloads, retries, reruns, and expiry |
| Audit export extension | `/staff/audit` | Existing audit view plus permission-gated export using its active filters |

The fixed dataset identifiers are registrations, payments, enrolments, attendance, progress, submissions, grades, completion, certificates, and support. They are not user-created report definitions.

## 5. Navigation and Page Framework

Add `Reconciliation` and `Reports` to the existing staff navigation as real route links. Do not add a separate top-level `Exports` item: Export History is reachable from the Reports hub and from every successful export confirmation. On the Reports route family, the staff-shell breadcrumb current section is `Reports`; page-level breadcrumbs distinguish a dataset or Export History.

All list/report filters are URL-backed. Navigation, metric drill-down, manual refresh, pagination, and browser Back/Forward preserve the normalized query string. The page may use a small client island to update URL parameters, but the data projection is rendered from a server-authorized request. Following the installed Next.js 16 guides, financial/report reads are uncached request-time Server Component work unless explicitly designed otherwise; mutation actions are untrusted endpoints and must return only safe UI projections.

Each page header follows this order:

1. breadcrumb;
2. 25px page title and one-sentence purpose;
3. last-refreshed and `as of` timestamps where data is shown;
4. actions aligned right on wide screens and stacked full-width below 640px;
5. URL-backed filters;
6. primary content.

Use one explicit `Refresh data` button. Do not auto-refresh dashboard figures while staff review them. Refresh preserves filters and visibly updates both timestamps after the replacement data is committed to the view.

## 6. Reconciliation Workspace

### 6.1 Queue (`/staff/reconciliation`)

The queue is exception-first in both DOM and visual order:

1. title, description, `as of`, and `Refresh data`;
2. provider tabs: All, Stripe, Paystack, Manual;
3. unresolved exception queue;
4. separate-currency summary cards;
5. secondary `View all transactions` link to the existing payment ledger with equivalent filters.

Provider tabs use the existing segmented-control treatment, `aria-current` or `aria-pressed`, and a text label. Tabs wrap on narrow screens rather than creating page-level horizontal scroll.

Queue columns:

| Column | Contract |
|--------|----------|
| Risk | Text label and severity `StatusPill`: Captured money, Settlement difference, or Missing provider data |
| Case | Case reference in mono; subtitle is order reference; link opens the dedicated case page |
| Learner / offer | Learner name; cohort/programme subtitle; sensitive identity appears only when permitted |
| Provider | Paystack, Stripe, or Manual as plain text, plus explicit NGN/USD currency |
| Difference / issue | Signed currency value when applicable; otherwise a short safe issue label, never fabricated zero |
| Owner | Assigned Finance staff name or `Unassigned` |
| Age | Human-readable age plus exact opened timestamp available to assistive technology/title |

Default ordering is risk category then age: captured-money problems first, settlement differences second, missing provider data third; oldest first within each group. Staff may change visible sort, but a `Reset priority order` control restores this default.

Checkboxes appear only for unresolved visible rows when assignment is permitted. The selection bar says `{N} selected` and offers only `Assign cases`; there is no bulk Resolve action. Assignment opens one accessible dialog with `Assign to` (permitted Finance users only), an `Unassigned` option, `Keep current assignments`, and `Assign cases`. Success clears selection and refreshes the affected rows. Failure retains selection and chosen assignee, shows `Cases not assigned. Your selection and current assignments are unchanged.`, and offers `Try assignment again` plus `Keep current assignments`.

Summary cards appear below the queue and never displace it. Show payment/refund totals grouped first by currency and then provider; NGN and USD are separate cards/rows with no combined grand total. Each card states its definition and links to the matching filtered transaction rows.

### 6.2 Case detail (`/staff/reconciliation/[caseId]`)

Use `DetailLayout` in stacked mode. The page title is `Reconciliation case`; the case reference is the mono identifier. Badges show Open/Resolved/Reopened, risk category, provider, and currency using text-bearing pills.

Sections, in order:

1. **Investigation summary** — safe exception description, opened time, priority, owner, and a prominent reopened notice when applicable. High-risk captured-money cases use danger treatment; settlement/missing-evidence cases use warning treatment.
2. **Order and learner** — order reference, offer, learner identity if permitted, learner charge, payment state, enrolment state, provider, currency, and provider reference.
3. **Expected and actual settlement** — paired fields for base price, KQ platform fee, estimated/actual gateway fee, learner total, expected/actual school settlement, KQ gross, and KQ net. Values come from the existing immutable/payment evidence projection, not UI arithmetic.
4. **Evidence and payment history** — chronological provider/manual/refund evidence with source, correlation, timestamp, and safe context.
5. **Investigation history** — append-only Opened, Assigned, Evidence changed, Resolved, and Reopened events. Previous resolution category/note remain readable after reopening.
6. **Corrective paths** — links to the existing payment/order/refund/enrolment workflow only when currently authorized. Copy states that corrections occur there, not in this case.

For manual payments, gateway fee and provider-settlement fields render the full phrase `Not applicable`; use neither `0`, an em dash, nor `Pending`. Unknown online actuals render `— (pending reconciliation)`, preserving Phase 7's null-versus-zero rule.

Actions are `Assign case`, `Assign to me`, and `Resolve exception` while open. `Resolve exception` opens a focus-trapped integrity dialog with a required resolution-category select, required case note, live validation, and the explicit reassurance: `This closes the investigation only. It does not change the payment, refund, settlement, or enrolment.` Submit label is `Resolve exception`; the secondary action is `Keep exception open`. On failure, preserve the category and note, show `Exception not resolved. Nothing in the investigation or payment record was changed.`, and offer `Try resolving again` plus `Keep exception open`. On success, move focus to the updated status heading and retain the resolution in history.

A materially contradictory evidence update automatically produces a warning banner: `This exception was reopened because new provider evidence no longer matches the previous resolution.` The earlier resolution remains below in history.

## 7. Reports Hub and Fixed Dashboards

### 7.1 Reports hub (`/staff/reports`)

The hub is a concise overview, not a wall of ten full dashboards. Its content order is:

1. headline metrics: registrations, active enrolments, unresolved payment exceptions, NGN confirmed payments, and USD confirmed payments;
2. global report context: current date range, permission/scope summary, last-refreshed, and `as of`;
3. three report groups;
4. `View export history` secondary action.

Headline metrics are buttons/links, not inert cards. Their accessible names include the metric and destination, for example `View 12 unresolved payment exceptions`. Clicking opens the matching filtered rows and preserves the date, programme, cohort, provider/currency, and other applicable filters.

Group cards:

| Group | Dashboards |
|-------|------------|
| Admissions & Finance | Registrations, Payments, Enrolments |
| Learning Delivery | Attendance, Progress, Submissions, Grades |
| Outcomes & Support | Completion, Certificates, Support |

Each dashboard link includes a one-sentence definition and an availability pill. At Phase 8 launch, registrations, payments, enrolments, and attendance are available. Progress, submissions, grades, completion, certificates, and support render `Not available yet` until their producing phase activates them. A database table existing without an operational producer is not sufficient to change availability.

### 7.2 Fixed dashboard (`/staff/reports/[dataset]`)

Every available dashboard has the same trust frame:

- title and plain-language metric definition;
- labelled business-date basis;
- applied scope statement;
- `Last refreshed` and `Data as of` timestamps;
- filters;
- 2–5 metric cards;
- at most one simple breakdown visualization where useful;
- a drill-down table produced from the same normalized request;
- `Refresh data` and primary `Export CSV` actions.

No chart library is introduced for Phase 8. Prefer metric cards and simple CSS horizontal bars/segmented counts. Every segment is a real link/button with a visible text label and value, keyboard focus, and equivalent table rows. Charts never rely on hover, color, or geometry alone and never replace the drill-down table.

Common filters are Date from, Date to, Programme, and Cohort. Add Provider, Currency, Payment state, Enrolment state, Attendance state, or other dataset-specific filters only where defined. Filter option lists are themselves scope-filtered; an out-of-scope programme/cohort must not appear even as an option. Filters wrap into one column below 640px and retain 38px control height.

| Dashboard | Business-date label | Required initial metrics |
|-----------|---------------------|--------------------------|
| Registrations | `Registration date` | Total registrations; verified; awaiting verification; matching registration rows |
| Payments | `Payment confirmation date` | Confirmed count; NGN learner total; USD learner total; refunds; exceptions; provider/status breakdown |
| Enrolments | `Enrolment activation/transition date` | Active; pending payment; withdrawn/cancelled; matching enrolment rows |
| Attendance | `Session date` | Sessions in range; recorded; missing registers; present/late/absent/excused breakdown |
| Progress | `Progress event date` | Not available until Phase 9 activates the dataset |
| Submissions | `Submission date` | Not available until Phase 10 activates the dataset |
| Grades | `Grade release date` | Not available until Phase 10 activates the dataset |
| Completion | `Completion date` | Not available until Phase 9/11 activates the authoritative completion dataset |
| Certificates | `Certificate issue date` | Not available until Phase 11 activates the dataset |
| Support | `Ticket creation date` | Not available until Phase 12 activates the dataset |

A genuine zero uses the value `0` and copy `No {dataset} match these filters` only after the available query has completed. An unavailable dashboard keeps its title/definition/date-basis explanation but replaces metrics and table with one neutral panel: `Not available yet` / `This report will become available when {owning capability} starts collecting authoritative data.` It has no Refresh or Export CTA.

When dashboard sections fail independently, keep successfully loaded context/sections visible. The failed panel says `Could not load {section}. The other report sections are unchanged.` and offers `Retry {section}`. Never convert a failed aggregate into zero.

## 8. CSV Export Journey

### 8.1 Requesting an export

`Export CSV` is the single primary CTA on a fixed available report. It submits the normalized active filters and request-time `as of` value. It does not wait for a file response and never changes filters.

Default activation queues the stable safe-column set immediately. Show an inline `role="status"` confirmation: `Export queued. You can leave this page and follow its progress in Export History.` Include `View export history` as a link.

If the request fails, retain the active filters and every export-option choice, show `Export not queued. Your report and choices are unchanged.`, and offer `Try queuing export` plus `Keep editing export options`. Never show a success banner or create a download affordance until a queued job is confirmed.

Where the actor has the additional sensitive-field authorization, an adjacent secondary `Export options` action opens a dialog listing only permitted sensitive columns. They are unchecked by default. Selecting any one reveals a required `Operational reason` textarea and the notice `Sensitive-field access is audited.` Submit remains `Queue export`. If authorization is absent, neither the sensitive fields nor a disabled/teasing control appears.

No raw filter JSON is shown. The confirmation and history use human-readable chips such as `Programme: Leadership`, `Provider: Paystack`, `Date: 1–30 Sep 2026`, and `Currency: NGN`. The frozen `as of` timestamp is always visible.

### 8.2 Export History (`/staff/reports/exports`)

Use `ResourceTable` behavior with URL-backed Dataset, Status, Requested date, and search filters. Default sort is newest request first. Rows are permission- and scope-filtered.

Columns:

| Column | Contract |
|--------|----------|
| Dataset | Human label; subtitle is dataset version |
| Requested | Request timestamp; requester name only when permitted |
| As of | Frozen dataset timestamp |
| Rows | Snapshot row count when known; `Pending` while not yet established, never zero unless genuinely zero |
| Status | Queued, Processing, Succeeded, Failed, or Expired via text-bearing `StatusPill` |
| File availability | `Available until {time}`, safe failure summary, or `Expired` |
| Action | Download, Retry, Rerun export, or no action according to state and current authorization |

Status/action rules:

| Status | Presentation | Allowed action |
|--------|--------------|----------------|
| Queued | Neutral pill; requested time | None; `Refresh status` remains available at page level |
| Processing | Neutral non-success pill plus sr-only `Processing export` | None |
| Succeeded | Success pill, row count, completion time, and expiry | `Download CSV` while authorized and unexpired |
| Failed | Danger pill and safe error description; never stack traces/provider secrets | `Retry export`, creating a linked new row |
| Expired | Neutral pill, original completion and expiry retained | `Rerun export`, creating a new request using recorded configuration and a new request-time snapshot |

Retry never overwrites the failed row. The detail/expanded evidence shows `Retry of {reference}` / `Retried by {reference}` links. Rerun after expiry clearly states that it captures current data and therefore receives a new `as of` value; it is not represented as the same frozen export.

`Download CSV` is an ordinary authorized route navigation. The visible action does not expose a storage key or signed URL. An unavailable download shows `Download unavailable. The file may have expired or your access may have changed.` and `Return to Export History`; only a confirmed expired row additionally offers `Rerun export`. No denial copy confirms the existence or contents of an out-of-scope job.

The page does not poll automatically. `Refresh status` preserves filters and focus; after refresh, announce changed job statuses in a polite live region. This follows the phase's deliberate/manual refresh language while still allowing staff to leave and return later.

### 8.3 Audit export

Add `Export audit CSV` to `/staff/audit` only when both audit-view and audit-export permissions hold. It uses the existing actor/action/target/date filters, frozen request-time snapshot, safe columns, and the same asynchronous history/download lifecycle. Audit export retains correlation identifiers and redacted investigative context; secrets and credential material are never selectable sensitive columns.

## 10. Responsive and Accessibility Contract

- At 1024px and above, use the existing 228px staff sidebar. Below it, keep the established accessible off-canvas navigation.
- Use multi-column headline/report cards at wide widths, two columns where space allows, and one column below 640px.
- Below 640px, all data tables render semantic cards carrying the same fields/actions; never require horizontal page scrolling.
- Provider tabs and status filters wrap. Do not clip a label or require a horizontal swipe to discover a provider.
- Filter and action clusters preserve at least 8px gaps; controls remain 38px high and gain a larger combined pointer area where icon-only.
- Every metric/segment link has a textual name/value and visible focus. Equivalent drill-down rows are available without perceiving color or chart shape.
- Status is always text-bearing. Risk, provider, currency, availability, and job status never depend on color alone.
- Loading uses stable-dimension skeletons with a polite screen-reader announcement. `prefers-reduced-motion` suppresses pulsing/transition motion through the existing global rule.
- Dialogs trap focus, close with Escape only when submission is not in flight, return focus to their trigger, identify validation errors, and keep entered values after failure.
- Error/denied copy never exposes whether an out-of-scope record, case, job, programme, cohort, learner, or filter option exists.
- Long notes, learner names, provider references, failure summaries, and filter labels wrap. Money/currency pairs and status labels remain intact.
- Timestamps show local Africa/Lagos-friendly display plus an exact machine-readable `dateTime`; exports also include their request-time zone in metadata.
- Export history and reconciliation history expose ordered semantic lists/tables, not visually positioned divs alone.
