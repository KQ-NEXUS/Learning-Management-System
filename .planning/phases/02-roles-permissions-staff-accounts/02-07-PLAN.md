<objective>
Put the staff-account service behind a working screen: a Users list reachable from the workspace
nav, and a combined create form that provisions the account and its first scoped role in one
submission.

Purpose: IAM-04's create half is the point where D-22's atomicity requirement becomes visible to a
person. A form that creates the account and then separately assigns a role would satisfy the letter
of the requirement and defeat its intent — this plan keeps the one-payload, one-action, one-
transaction shape all the way from the browser to the database.

Output: `/staff/users`, `/staff/users/new`, `UsersTable`, `StaffAccountForm`, the Server Actions,
and the nav link.
</objective>

`src/app/staff/users/actions.ts` (new). `"use server"`. Export `createStaffAccountAction(prev,
formData)` returning a state object of shape `{ errors: FieldError[]; created: { name: string;
email: string; temporaryPassword: string; userId: string } | null }`. Read name, email, an optional
administrator-supplied temporary password, roleId, scopeType, scopeId and an optional endsAt, and
call `staffAccountService.create` exactly once with all of them together — one call, so plan 06's
single transaction stays intact and no intermediate zero-access account can exist (D-22). Map
`DuplicateStaffEmailError` to an `email` field error, `ScopeError` to a `scopeType` field error
naming the global-only conflict, `AuthorizationError` to a form-level error, and a missing role or
scope to the corresponding field errors. On success return the created state carrying the plaintext
temporary password and do not redirect — a redirect would either lose the value or force it into a
query string, and it must never enter the URL. Call `revalidatePath` for `/staff/users`.

Also export `searchScopeTargetsAction(scopeType, query)`, which dispatches to
`scopeLookupService.programmes`, `.courses` or `.cohorts` and returns a `ScopeTarget` array, or an
empty array for GLOBAL. It requires only `roles.manage`, inherited from the service (D-41).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → createStaffAccountAction | Name, email, optional password, role, scope type and scope target all cross here untrusted; the form's own disabled-until-valid rule has no authority. |
| createStaffAccountAction → staff-account-service | The authorization choke point and the atomic transaction boundary. |
| create result → staff browser | The plaintext temporary password crosses back exactly once, inside the action's returned state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-08 | Information Disclosure | temporary password display | high | mitigate | The value travels only in the Server Action's returned state and is rendered once; the success path performs no redirect, so it never enters a URL, and the component touches no storage API or console. |
| T-02-23 | Tampering | non-atomic combined create | high | mitigate | One action invocation makes exactly one service call carrying both the account fields and the first role plus scope, preserving plan 06's single transaction; the form offers no role-less submit path. |
| T-02-02 | Elevation of Privilege | first assignment scope | high | mitigate | Scope validity is enforced server-side by `assertScopeAllowed` inside the service; `ScopeError` is surfaced as a scope field error rather than being swallowed. |
| T-02-18 | Information Disclosure | scope-target lookup from the browser | medium | mitigate | `searchScopeTargetsAction` delegates to `scopeLookupService`, which is gated on `roles.manage` at global scope and projects three identity fields (D-41). |
| T-02-24 | Information Disclosure | `/staff/users` denial path | low | mitigate | The list page renders `UsersTable` in its `denied` state with identical copy whether or not accounts exist, copying the Courses precedent. |
| T-02-SC | Tampering | npm/pip/cargo installs | low | accept | No package-manager install task exists in this phase; 02-RESEARCH.md's "Package Legitimacy Audit" records "Not applicable this phase — no new external packages are introduced." |
