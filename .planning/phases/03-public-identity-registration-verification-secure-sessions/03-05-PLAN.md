<objective>
Give a verified Learner their first authenticated page: an account screen where they maintain their
approved profile fields and their single communication preference, under the validation and consent
rules IAM-05 requires. This is also the phase's only ownership-authorized surface — every other
protected operation in this codebase runs through `withPermission`, and this one deliberately does not.

Purpose: `/account` is the redirect target a newly verified Learner lands on, and the email-change flow
it contains is the one place in the phase where a hijacked session could become a permanent account
takeover. D-10 rates the step-up confirmation as costly to retrofit precisely because bolting an extra
password prompt onto an already-shipped edit flow is far harder than shipping it from the start.
Output: one new service, a Learner route group with its own minimal shell, and the email-change
confirmation landing.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated browser -> `/account` server actions | A session-bearing but otherwise untrusted request crosses here and mutates identity fields. |
| session actor -> the `User` row being edited | The ownership comparison is the only thing confining an edit to the caller's own record. |
| anonymous browser -> `/confirm-email-change?token=` | An attacker-controlled token crosses here and, if honoured, changes the sign-in identifier of an account. |
| `profile-service` -> the outbound confirmation email | The confirmation is sent to a caller-supplied address, so the endpoint is an outbound-send trigger. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan | Status |
|-----------|----------|-----------|----------|-------------|-----------------|--------|
| T-03-31 | Spoofing | email change from a hijacked session | critical | mitigate | D-10's step-up: `verifyPassword` against the current password before anything is written, plus confirmation of the new address before it takes effect. Without both halves, a stolen session becomes a permanent takeover. | planned |
| T-03-32 | Elevation of Privilege | editing another learner's record | high | mitigate | No entry point accepts a target user id; the target is derived from `actor.userId`. A signature that cannot name another record cannot be tricked into editing one. Pinned by reading each signature. | planned |
| T-03-33 | Tampering | `User.email` changed before verification | high | mitigate | The request path writes only `pendingEmail`; `email` and `emailVerified` are untouched until the token is claimed. Pinned by a test asserting both are unchanged after a request. | planned |
| T-03-34 | Information Disclosure | email-change collision as an existence oracle | high | mitigate | The collision branch, the same-address branch and the happy path return one frozen shared value; the confirmation panel renders no address on the failure path. | planned |
| T-03-35 | Tampering | address claimed between request and confirmation | medium | mitigate | The uniqueness re-check runs inside the claim transaction, producing a clean refusal rather than a constraint rejection surfacing as an error page. | planned |
| T-03-36 | Denial of Service | email change as an outbound-send vector | medium | mitigate | `issueToken` applies the 60-second per-address cooldown before issuing or sending (D-05), and the step-up gate means an attacker needs the current password to trigger a send at all. | planned |
| T-03-37 | Repudiation | consent and profile change attribution | medium | mitigate | Four distinct audit actions written through `recordAudit` with the learner as actor and before/after rows; the sink already redacts `passwordHash` and `token`. | planned |

| T-03-39 | Information Disclosure | step-up failure message | medium | mitigate | A wrong current password renders the generic error banner rather than a message naming the password, so the form is not a password oracle for a session an attacker already holds. | planned |
