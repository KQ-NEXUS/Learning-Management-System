# Phase 15 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds **no learner-facing features**. It reuses the design system that is already in place (the Phase 04.1 redesign plus the 2026-10-05 UI review fixes merged to `develop` at `9599060`). It does **not** add a new system, new tokens or a new type scale. Every new surface is built from the existing tokens in `src/app/globals.css`, the shared class constants in `src/components/primitives/controls.ts`, and the shared components listed under Component Inventory. New source files must pass `tests/unit/design-contract.test.ts`: font sizes from the permitted scale, weights 400/500/600/700 only, spacing on the 4px grid (0 to 64), and no class list with two unconditional `text-`/`bg-`/`border-` colour roles.

### UI surfaces in scope

| ID | Surface | Source decision | New or changed |
|----|---------|-----------------|----------------|
| S1 | Staff **Operations status** page `/staff/operations` (failed jobs, payment exceptions, email failures, integrity checks) | D-18, NFR-07, NFR-13 | New page + one nav item |

## Spacing Scale

Declared values (all multiples of 4; the design-contract test allows every multiple of 4 from 0 to 64):

| Token | Value | Tailwind | Usage on this phase's surfaces |
|-------|-------|----------|--------------------------------|
| xs | 4px | `gap-1` | Icon-to-text gap inside links ("Open order →") |
| sm | 8px | `gap-2` | Label-to-control gap (`FIELD`), pill dot gap, between a status pill and its detail line |
| sm+ | 12px | `px-3`, `gap-3` | Table cell horizontal padding (`TH`/`TD`), heading-to-alert-dot gap |
| md | 16px | `py-4`, `gap-4` | Row vertical padding in lists and tables, form field stack, alert inner padding (`px-4`) |
| lg | 24px | `gap-6`, `gap-x-6` | Between band figures, between blocks inside a section |
| xl | 32px | `gap-8`, `pt-8` | Between sections below 1024px; top padding of the danger-zone section |
| 2xl | 48px | `gap-12` | Between sections at 1024px and wider |
| 3xl | 64px | — | Not used by new surfaces in this phase |

Exceptions:
- 12px (`px-3`, `gap-3`) is inherited from the shared `TH`/`TD` constants in `controls.ts` (table cell padding) and from the Overview section head (heading-to-dot gap). It is on the 4px grid and allowed by the design-contract test; new surfaces use it only in those two places.
- Every new class list uses grid utilities only. In particular, new S3 markup uses `px-5` (20px) for button padding, not the `px-[18px]` found inside the shared `BTN`/`BTN_PRIMARY` constants. Those constants are consumed as they are and not re-authored.
- Control heights are **sizing**, not spacing: buttons 46px (`BTN`, `BTN_PRIMARY`), on-navy buttons 40px (`BTN_ON_NAVY`), inputs 48px (`CONTROL`, `h-12`). Every interactive target on S1–S3 is at least 44×44px except inline text links inside sentences (WCAG 2.5.8 inline exception), which are at least 24px tall (`inline-block py-1`).
- `PageHeader`'s negative margins (`-mx-[25px]`, `-mt-[37px]`, `lg:-mx-[41px]`) and band padding (`pt-[10px] pb-[56px]`) are inherited from the shared component and are not re-authored.
- Locked exceptions D-21 (auth form gap `gap-5`) and D-23 (learner shell header `py-3.5 px-7`) stay exactly as they are; S4/S5 add no new spacing to the auth forms (messages render in the existing alert slot).

- S1 band figures: 36px JetBrains Mono, weight 500, line-height 1.15, copied exactly from `src/app/staff/page.tsx`'s Overview figure markup so the two dashboards match. This is the only use of the Display row, so 500 is inherited, not authored.

### S6 — Dates and times (D-17)

| Kind | Format | Example |
|------|--------|---------|
| Date and time | `day month-short year, HH:mm WAT` in `Africa/Lagos`, 24-hour, literal " WAT" suffix | "5 Oct 2026, 14:30 WAT" |
| Date and time with seconds (only `/staff/audit` rows) | same plus seconds | "5 Oct 2026, 14:30:12 WAT" |
| Date only | `day month-short year`, computed in `Africa/Lagos`, no zone label | "5 Oct 2026" |
| Public certificate issue date | Keeps its formal long month, computed in `Africa/Lagos` | "5 October 2026" |
| Session schedules and calendars | The cohort's own zone with its label (the default cohort zone is Lagos, so it reads "WAT") | "5 Oct 2026, 14:30 WAT" |

Rules:
- One shared pure formatter module (RESEARCH A9: `en-GB`, `timeZone: "Africa/Lagos"`, `hourCycle: "h23"`, literal " WAT"; never `timeZoneName`, which prints "GMT+1"). Server and client output must be byte-identical (no hydration mismatch).
- Every rendered timestamp is wrapped in `<time dateTime="{ISO 8601 UTC}">`.
- A missing (null) or invalid timestamp renders "—" (em dash) as plain text with no `<time>` element, matching `DetailFacts`. The formatter never throws and never prints "Invalid Date".
- In tables, timestamps use JetBrains Mono 13px with `whitespace-nowrap`. In sentences and cards they use the surrounding sans text and may wrap.

## Screen Contracts

### S1 — Operations status layout

- Server-rendered page; gate with the existing `audit.view` Global permission (RESEARCH A6), no new permission.
- `PageHeader`: title, subtitle, `meta` = overall status pill, `actions` = "Refresh status", `band` = three figures in the Overview figure layout (`grid grid-cols-2 gap-x-6 gap-y-8`, three columns at `lg`, hairline dividers `lg:border-l lg:border-sidebar-line lg:pl-6`) plus the "Checked …" line in `text-sm text-sidebar-soft`.
- Body: sections stacked in one column (`flex flex-col gap-8 lg:gap-12`), in this order: Scheduled jobs, Failed and stuck work, Payment exceptions, Email failures, Data integrity checks. One column at every width: the page is read top to bottom by severity, and a single column reflows cleanly at 320px and 200% zoom.
- Section head: the Overview `SectionHead` pattern — h2 20px/600 with `.alert-dot` after the text when the section has at least one failure, and a right-aligned count in `text-sm text-muted-foreground` ("3 open"). Content starts on a `border-t border-foreground` rule; it becomes `border-t-2 border-danger` when the section has failures (same as Overview "Needs attention").
- Rows from 768px: a table using `TH`/`TD` (`w-full table-fixed`). Below 768px: each row becomes a stacked card (`border-b border-border py-4`): title line 14px/600, detail line 13px muted, status pill, then the link on its own line. No horizontal scroll at any width.
- Each list shows at most 10 rows, newest first, then the footer link to the owning workspace. Row links are text links with a trailing `ArrowRight` icon (`size-3.5`, `aria-hidden`), at least 44px tall in the card layout.
- Section failure is isolated: one section's load error shows its own `NOTE_DANGER` message; the other sections still render.
- Loading: the existing `src/app/staff/loading.tsx` skeleton covers navigation. No client polling.

### S2 — Learner privacy lookup layout

- `PageHeader` (title, subtitle). Body: one `<form method="get">` with the field (`FIELD` label, `CONTROL` input, `w-full max-w-md`, `type="text"`, `autoComplete="off"`, `spellCheck={false}`) and the "Find learner" `BTN_PRIMARY` beside it from 640px, under it below 640px.
- The search value is not echoed into the URL after a match: a match redirects to `/staff/privacy/[userId]`; a no-match re-renders the form with the value refilled and the message in `NOTE_DANGER` (`role="alert"`, focus moves to it).
- No list of learners, no partial-match results, no autocomplete: the tool works on one known person at a time (threat "mass export of personal data", RESEARCH Security Domain).

### S3 — Learner privacy record layout

- `PageHeader` with breadcrumbs, title, identifier, status pill.
- Body column `max-w-[760px]`, `flex flex-col gap-8 lg:gap-12`, three sections in order: Learner details (`DetailFacts`), Export data, Anonymise account.
- Export data: body text, then the latest export for this learner (status pill, time, link or retry), then "Prepare data export" (`BTN_PRIMARY`). Disabled with a visible reason while an export is Queued or Processing.
- Anonymise account (danger zone): `border-t-2 border-danger pt-8`; heading; body; two lists side by side from 768px (`grid md:grid-cols-2 gap-6`), stacked below; deletion note in `NOTE_WARNING`; export-first advice; typed check field (`CONTROL`, `w-full max-w-md`, `autoComplete="off"`, paste allowed); then the danger button (`inline-flex min-h-[46px] items-center justify-center rounded-md bg-danger px-5 text-sm font-semibold text-white hover:opacity-90 disabled:opacity-50` — `px-5` (20px) sits on the 4px grid, and the list has one colour role per property, so it passes both the spacing and colour-conflict checks in `tests/unit/design-contract.test.ts`).
- The email comparison is case-insensitive and trims spaces. The server re-checks the target id and the reason; the typed check is a guard against the wrong record, not a security control.
- After success the page re-renders from the server (new status, the "anonymised on … by …" line, the success note). Focus moves to the success note.

### S4/S5 — Existing auth, certificate and ticket screens

- The certificate check's fourth branch keeps the page's "no shared structure between outcomes" rule: it renders its own icon and heading block and no `<dl>`; the design-contract and DOM-shape tests for that page are extended to cover it.
