<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → publish/listing actions | The migrate list, the reason and the order token are all client-supplied. |
| rendered controls → authority | A hidden button is not an access control; the server must refuse regardless. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-53 | Elevation of Privilege | listing action invoked by a caller who cannot see the button | mitigate | `setPublicListing` is `withPermission("programmes.publish", ...)`; the hidden control is explicitly documented as courtesy; checkpoint step 11 exercises the direct call |
| T-04-54 | Tampering | readiness bypassed by posting the publish/listing action directly | mitigate | The action re-runs `blockingFailures` server-side inside `publish-service`; the panel's props are never the decision |
| T-04-55 | Tampering | bulk cohort migration | mitigate | No "select all" control exists (grep-asserted); `defaultChecked` absent; reason required on any tick |
| T-04-56 | Information Disclosure | publish dialog leaking cohorts outside the actor's scope | mitigate | `blockingCohorts` is called from inside the `withPermission`-wrapped service, scoped to the course the actor may already reach |
| T-04-57 | Repudiation | unreasoned archive or migration | mitigate | `ConfirmModal` `minReasonLength` client-side and a mandatory non-blank reason enforced server-side in `publish-service` |
</threat_model>
