## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → programme actions | Membership ids, order arrays and the order token are client-supplied. |
| programme index → existence disclosure | A differing denial message would confirm that Programmes exist in a scope the caller cannot reach. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-58 | Information Disclosure | denial copy differing from empty-state copy | mitigate | The index mirrors `src/app/staff/courses/page.tsx` exactly, rendering the table's `denied` state with identical copy regardless of whether records exist |
| T-04-59 | Elevation of Privilege | composing a Programme the actor cannot reach | mitigate | Every action delegates to `programmeService` / `reorder-service`, both `withPermission`-wrapped at `programmeScope(programmeId)`; the candidate-course picker is populated through the actor's own scoped `courseService.list` |
| T-04-60 | Tampering | lost update between concurrent composition edits | mitigate | The same `updatedAt` order token and `StaleOrderError` refusal as the course arrange screen |
| T-04-61 | Tampering | removing a Course silently altering a published Programme version | mitigate | Membership writes touch `ProgrammeCourse` only; `ProgrammePublication.payload` is insert-only (plan 04-08) and covered by an integration case there; checkpoint steps 8 and 9 confirm it by hand |
</threat_model>
