<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff Server Action → publish | The publish payload names which cohorts to migrate. A forged list changes other learners' obligations. |
| publish permission → sale | `courses.publish` is granted to scoped Instructors. If it also listed publicly, an Instructor could put a course on sale. |
| published version → learner obligations | An update to a publication row is a retroactive, invisible change to what people owe. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-30 | Elevation of Privilege | Instructor listing a course for public sale | mitigate | `setPublicListing` gated on `programmes.publish`, `publishCourse` on `courses.publish`; test asserts a `courses.publish`-only caller is denied listing (D-09) |
| T-04-31 | Tampering | retroactive change to a published version | mitigate | `CoursePublication` is insert-only; no `.update` call exists (grep-asserted); `@@unique([courseId, version])` plus integration case 1 comparing payload bytes across a later publish |
| T-04-32 | Tampering | mass cohort migration hidden in a boolean | mitigate | Per-cohort `migrateCohortIds` array, empty by default, mandatory non-blank reason; no `migrateAll` parameter exists (grep-asserted) |
| T-04-33 | Tampering | publishing a stale arrangement | mitigate | Conditional `updateMany` on `updatedAt` inside the publish transaction, sharing `StaleOrderError` with the reorder service; integration case 9 asserts no publication row is written |
| T-04-34 | Denial of Service | pulling content from learners mid-study | mitigate | `assertNoRunningCohorts` on unpublish and archive, refusal names the cohorts; listing-off is always permitted so sales can stop without disrupting study (D-12) |
| T-04-35 | Information Disclosure | archived record breaking history | accept | D-15 deliberately preserves read access for anyone with a completion record or enrolment; archive sets `publiclyListed: false` so it leaves new-sale flows |
| T-04-36 | Repudiation | unattributed publish | mitigate | `publishedById` from `ctx.actor.userId` inside the transaction; audit rows for publish, listing, archive, unarchive and slug override |
</threat_model>
