Build the anonymous, read-only public catalogue: an index and a detail page for Courses and Programmes,

<planner_decisions>
**Prerendering (RESEARCH Pitfall 3): choose explicitly, per route, and write the choice down.**
The existing staff pages are dynamic only by accident — `getCurrentActor()` calls `cookies()`, which opts
them out of prerendering. The public pages have no such call, so with the default `dynamic = 'auto'` they
would prerender at build and never notice a listing toggle, and `next build` would start requiring a live
database.

Adopt **ISR plus on-demand revalidation**: `export const revalidate = 300` on all four public routes, with
`revalidatePath` called from the publish/listing/archive actions. Anonymous reads stay fast, which is the
NFR-02 argument, and correctness is restored within one action round trip. If the executor finds during
implementation that the build cannot reach a database in this environment, fall back to
`export const dynamic = 'force-dynamic'` on all four routes and record the substitution in the SUMMARY —
correctness first, caching second.
</planner_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous internet → public routes | No actor, no session, no authorization. The query's `where` clause is the only access control. |
| slug → existence | Any difference between "unlisted", "archived" and "never existed" is an enumeration oracle. |
| staff listing action → cached public page | A stale cache serves content the business has withdrawn from sale. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-67 | Information Disclosure | unlisted or archived record exposed by direct URL | mitigate | Single `PUBLIC_VISIBILITY_WHERE` filter used by all four queries; existence check as a top-level `await` before any `<Suspense>` so the status is a real 404; `forbidden()` explicitly not used |
| T-04-68 | Information Disclosure | enumeration via differing responses | mitigate | Unlisted, archived and non-existent slugs all resolve to `null` and render the identical `not-found.tsx`; checkpoint step 5 verifies indistinguishability by hand |
| T-04-69 | Information Disclosure | over-selection leaking internal columns | mitigate | Explicit field lists in every public query; test asserts `completionRule` is absent from the returned shape |
| T-04-70 | Tampering | stale prerendered page serving withdrawn content | mitigate | Explicit `revalidate = 300` plus `revalidatePath` (with the required `type` argument) from every listing/publish/archive action; checkpoint step 7 verifies against a production build |
| T-04-71 | Denial of Service | anonymous traffic hitting the database on every request | accept | ISR with a 300s window bounds it; falling back to `force-dynamic` would trade this for guaranteed freshness, and the SUMMARY records which was chosen |
</threat_model>
