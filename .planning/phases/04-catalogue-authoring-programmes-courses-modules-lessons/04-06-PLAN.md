<design_notes>
Both modules are PURE. Neither imports `@prisma/client`, `@/server/db`, or `withPermission`. They take
a plain aggregate in and return a value out. That is what lets plan 04-08 call them inside an
authorized transaction and plan 04-12 call them inside a Server Component, from one implementation.

Because they are pure, they declare their own minimal structural input types rather than importing
`LoadedCourseTree` from plan 04-04. `loadCourseTree`'s return value satisfies them structurally.

**D-02 is the whole specification of the payload.**
FROZEN: which lessons exist, their order, `required`, the attached `assessmentId`, the completion rule.
LIVE: titles, body text, files, images, embeds, links.
If a field is not in the FROZEN list, it must not appear in the payload — a title in the payload would
make a typo fix a requirement change, which is exactly what D-01 rejects.
</design_notes>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live catalogue data → frozen obligations | Once a payload is written, it defines what enrolled learners owe. A non-deterministic builder would produce spurious version churn; a leaky one would freeze prose. |
| readiness result → public listing gate | The same array both informs staff and refuses the action. A UI-only evaluator would leave the server ungated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-20 | Tampering | client-supplied snapshot content | mitigate | Payloads are built server-side from loaded rows only; `buildCourseObligationTree` takes an aggregate, never a request body, and nothing here ever `JSON.parse`s client input |
| T-04-21 | Spoofing | readiness bypassed by calling the listing action directly | mitigate | The evaluator is pure and re-run server-side inside `setPublicListing` (plan 04-08); the panel's result is never trusted as the decision |
| T-04-22 | Tampering | prototype pollution via a crafted `completionRule` JSON | mitigate | The rule is copied by value into the payload and never merged into an object with spread over untrusted keys; `payload` carries an explicit `schema` marker checked by the `jsonb_typeof` CHECK from plan 04-02 |
</threat_model>
