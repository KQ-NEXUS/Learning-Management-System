<objective>
Build the course structure screen: Module creation and renaming, drag-and-drop with a first-class keyboard
path, an explicit Save order commit, an unsaved-changes guard, and a collapsed Withdrawn section with
Restore.

**This plan owns the only Module creation surface in the phase.** `moduleService` and `createModule` are
built in plan 04-04, but a service with no caller is not a delivered requirement — CAT-03 says Modules
"can be created". Without this, a fresh Course has no Module, plan 04-11's lesson-create form has no
`moduleId` to be handed, and the human checkpoints in this plan, 04-11 and 04-14 are all unreachable.

Purpose: CAT-03's "ordering is stable after save" is only half a server problem. The other half is that
staff must be able to express the arrangement they want — including with a keyboard, because WCAG 2.2 AA
(NFR-09) is a locked constraint, not a nice-to-have.
Output: two reusable components, a module composer, one staff route, one server action module, one
component test file.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → arrange Server Action | The arrangement array, the order token, and the item ids are all attacker-controllable. |
| assistive technology → arrange UI | An inaccessible reorder is not a cosmetic defect here; NFR-09 makes it a failed requirement. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-36b | Tampering | client-supplied `position` on module creation | mitigate | `createModuleAction`'s zod schema has no `position` field and `createModule` computes it inside the insert transaction (plan 04-04 `<position_rule>`) |
| T-04-37 | Tampering | forged arrangement payload | mitigate | Actions validate with `zod` then delegate to `reorder-service`, which re-verifies ownership and completeness inside the transaction; the client is never the authority |
| T-04-38 | Elevation of Privilege | Server Action invoked directly by POST | mitigate | Every action delegates to a `withPermission`-wrapped service operation; the framework's Origin/Host CSRF check is not treated as authorization |
| T-04-39 | Tampering | lost update between two staff tabs | mitigate | Order token carried in the page and refused server-side on mismatch; checkpoint step 8 exercises it manually as well as the integration test in plan 04-05 |
| T-04-40 | Denial of Service | accidental unrecoverable withdrawal | mitigate | Withdrawn section with Restore (D-34); withdrawal is `withdrawnAt`, never a delete |
</threat_model>
