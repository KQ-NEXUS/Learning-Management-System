<planner_decisions>
**D-33 is locked: one image, two entrypoints.** The `app` and `worker` Compose services build from the
same `Dockerfile` and differ only in `command`. Two images would mean two dependency trees drifting apart.

**`worker/` sits OUTSIDE `src/`.** The ESLint boundary rule's `files` glob is `src/**/*.{ts,tsx}`. A worker
under `src/` that imported `@prisma/client` would be blocked; a worker under `src/server/services/` would
blur what "services are authorized entry points" means. At the repository root, the rule's meaning stays
intact — and Task 2 extends `tests/boundary.test.ts` so the exemption is explicit and tested rather than
accidental.

**Transactional enqueue is not available** (pg-boss `fromPrisma` needs Prisma v7+; this project pins
6.19.3). The reconciliation cron is therefore not belt-and-braces, it is the mechanism. Do not remove it.

**The worker calls the `*AsSystem` operations, never the `withPermission`-wrapped ones.** VERIFIED:
`src/server/permissions/index.ts:15` binds `getActor: getCurrentActor`, and
`src/server/auth/current-actor.ts:15` calls `cookies()` from `next/headers`. This process has no request,
no cookie jar and no Next.js runtime, so any authorized service call throws on the first job and every
upload stalls at PENDING. Plan 04-07 therefore exposes `markScanResultAsSystem` and
`findStuckPendingAsSystem` from `src/server/services/scan-system-service.ts` — narrow, unauthorized by
design, audited with `actorId: null, actorType: "SYSTEM"`. Task 2 adds the boundary test that keeps that
honest in both directions.

**Storage is environment-driven (D-35).** MinIO stays in Compose for local development and CI so the stack
runs offline with no cloud credentials; production points the same `S3_*` variables at Cloudflare R2.
Nothing in the Dockerfile, the Compose file or the worker may hardcode either backend.
</planner_decisions>
