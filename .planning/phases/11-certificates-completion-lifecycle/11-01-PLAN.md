## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application → database | Concurrent transactions may both observe "no ACTIVE certificate" and both insert; only a DB-level constraint arbitrates |
| migration tooling → production-shaped data | A destructive push would discard existing enrolment/completion history |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | `Certificate` row creation under concurrency | mitigate | Hand-written partial unique index `certificate_one_active_per_enrolment_scope ON ("enrolmentId","scope") WHERE status = 'ACTIVE'` in the migration's raw-SQL trailer (Task 2); consuming code catches P2002 as a no-op (plan 11-07) |
| T-11-02 | Denial of Service / data loss | Prisma migration application | mitigate | `migrate dev --create-only` then `migrate dev`/`migrate deploy`; `db push --accept-data-loss` is explicitly forbidden in Task 2's action |
| T-11-03 | Elevation of Privilege | Default `certificateIssuanceMode` | mitigate | Defaults to `MANUAL` on both Course and Programme so no pre-existing row starts auto-issuing credentials without a staff decision (Task 1) |
| T-11-04 | Tampering | `Enrolment.status` state machine | mitigate | Only `COMPLETED: ["ACTIVE"]` is added; Task 3's acceptance criteria assert `WITHDRAWN`/`TRANSFERRED`/`CANCELLED` remain empty arrays, so no other terminal escape is opened |
| T-11-SC | Tampering | npm installs | mitigate | No package installed by this plan — `grep -c '"pdf' package.json` must remain at its pre-plan value; the PDF-library legitimacy gate lives in plan 11-02 |
</threat_model>
