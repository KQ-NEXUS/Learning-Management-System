<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → template layout persistence | Arbitrary client-assembled JSON reaches a server action |
| archived template → editing surface | An archived layout conceptually backs already-issued credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-05 | Elevation of Privilege | Template authoring authorization | mitigate | Every action calls the permission-gated `certificate-template-service.ts`, whose identifier is the human's 11-DECISIONS.md choice; the actions themselves add no bypass path |
| T-11-12 | Tampering | Client-assembled layout JSON | mitigate | `saveTemplateLayoutAction` passes the layout as `z.unknown()` to the service, where `parseCertificateTemplateLayout` allow-lists it — one validation definition, not a drifting zod duplicate |
| T-11-37 | Tampering | Editing an archived template that issued certificates were rendered from | mitigate | `[id]/page.tsx` passes `readOnly` for archived templates and the shell renders no palette, header inputs or save control; the list offers "View" not "Edit" (Pitfall 5) |
| T-11-38 | Information Disclosure | Raw service/Prisma error text reaching a staff browser | mitigate | Acceptance criteria assert zero `error.message` pass-through; auth failures map to a fixed role message, everything else to a generic retry message |
| T-11-39 | Denial of Service | Archiving the only default template leaving issuance with no fallback | mitigate | `DefaultTemplateRequiredError` from plan 11-05 surfaces as a specific, actionable message rather than a silent failure |
| T-11-SC | Tampering | npm installs | mitigate | This plan installs nothing — no drag-and-drop or canvas library is added; `git diff package.json` must be empty |
</threat_model>
