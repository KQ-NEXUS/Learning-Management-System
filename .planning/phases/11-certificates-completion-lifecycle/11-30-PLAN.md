<objective>
Fix CR-01(b): guarantee that a certificate render or storage failure can never roll back or fail the caller's lesson-progress or attendance write.

The mechanism (decided here, stated explicitly): TWO-PHASE ISSUANCE.
Phase A, inside the caller's transaction (D-03 preserved): everything that is a database fact: the eligibility/revocation/idempotency checks, the certificate row created with `storageKey: null`, the COMPLETED transition, the audit row and the domain event. No PDF work, no object-store call, no layout parsing.
Phase B, after the caller's transaction has committed: render the PDF from the row's own snapshotted facts (learnerName, awardTitle, issuedAt, verificationRef), store it, and set `storageKey` with a compare-and-set (`storageKey IS NULL`). Phase B is best effort: it catches everything, logs only the certificate id and error name (never a learner name), is bounded by a timeout, and can never throw to the caller. If it does not complete, the row exists without a file and the file is produced lazily on demand (plan 11-31 wires the download route), idempotently.

Why not "catch inside the transaction": a slow object store or large logo can exceed Prisma's default 5 s interactive-transaction timeout (P2028), which rolls the caller's write back regardless of any try/catch. Only moving the work out of the transaction gives the guarantee. This also fixes WR-01 (render/S3 inside the caller's transaction, and orphaned objects on rollback), which the plan states explicitly as the natural part of CR-01. The service layer must not import `next/*`, so Next's `after()` is not used; instead the composition roots (plan 11-31) await the settle step with a bounded wait.

This plan builds the mechanism (file service + issuance refactor). Plan 11-31 wires the composition roots and the download route.

Honesty note on D-07: the certificate row is now committed before its file exists. A learner can briefly see an issued certificate whose download is being finalised; the download route (11-31) produces the file on demand so the link works.

Output: certificate-file-service.ts, the refactored issuance service, updated and new tests (including an invariant that keeps render work out of the issuance module).
</objective>
