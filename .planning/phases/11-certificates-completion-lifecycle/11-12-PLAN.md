<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → object store | A direct browser PUT to a presigned URL bypasses the application server |
| client-claimed content-type → stored asset | The browser's declared MIME type is attacker-controllable |
| canvas element values → persisted layout | Client-computed coordinates and colours become server-rendered PDF content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-11 | Tampering | Template asset upload as an XSS or path-traversal vector | mitigate | Reuses the existing three-step staged-upload flow verbatim: randomUUID-keyed staged path, server-side inspect of real content-type and byte length, then promote. `image/svg+xml` stays excluded via the shared `upload-limits.ts` allow-list; no parallel looser path is created |
| T-11-55 | Tampering | Out-of-range or malformed element values reaching the persisted layout | mitigate | The inspector clamps at the input boundary and the field-type switch clears the inapplicable field; `parseCertificateTemplateLayout` remains the authoritative server-side gate (plan 11-05), so a hand-crafted save is still rejected |
| T-11-56 | Elevation of Privilege | Upload actions reachable without template-authoring authority | mitigate | Both actions are gated by the identifier recorded in 11-DECISIONS.md, the same one guarding template writes |
| T-11-57 | Information Disclosure | Raw action/storage errors reaching the staff browser | mitigate | `{ ok: false, message }` mapping with no `error.message` pass-through, asserted |
| T-11-58 | Denial of Service | Oversized image asset | mitigate | The existing `upload-limits.ts` byte cap applies unchanged; the inspect step verifies actual size, not the claimed one |
| T-11-NFR09 | Accessibility (NFR-09) | Pointer-only canvas with no keyboard path | mitigate | Every element is focusable with an accessible name; arrow/Shift-arrow nudge and Delete are asserted by keyboard-only tests; position changes are announced. UI-SPEC §0.4 makes this a locked contract, not an optional enhancement |
| T-11-SC | Tampering | npm installs | mitigate | No drag, canvas or DnD library is added — asserted by grep and by an empty `git diff package.json` |
</threat_model>
