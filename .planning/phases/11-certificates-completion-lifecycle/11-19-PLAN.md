<objective>
Close UAT test 11 (MAJOR): the downloaded PDF is vertically mirrored relative to the template editor and the logo is
stretched into an ellipse.

Root cause (verified in the source): `drawTextElement` passes `element.y` to pdf-lib as the text baseline
(`certificate-pdf-renderer.ts` ~L103) and `drawImageElement` passes `element.y` as the image's bottom edge (~L125).
The editor's y is top-origin (`TemplateCanvas.tsx`: `top: y / pageHeight`); pdf-lib's origin is bottom-left. `drawImage`
also stretches to width x height whereas the editor preview uses `object-contain`.

Purpose: CRD-03 requires a certificate that matches the design staff built. The renderer tests all asserted "the text is
present", never "the text is where it was placed", so a fully mirrored layout passed every test.

Output: A renderer that converts coordinates and fits images, and a position-reading test helper plus tests that fail
against the current renderer.

Scope note (disclose in the SUMMARY, do not fix here): certificates issued BEFORE this fix keep their stored, mirrored
PDF (`Certificate.storageKey` is written once at issuance). Only certificates issued or reissued after this plan get the
corrected layout. Regenerating stored PDFs is a new capability (it touches an issued credential) and is deliberately not
planned; it needs the user's decision.
</objective>

<!-- Facts verified by running pdf-lib 1.17.1 in this repo. Use directly. -->

Layout units: `CertificateElementV1` x/y/width/height are PDF points, top-origin (y measured down from the top page edge). Page size comes from `pageDimensionsFor(pageSize, orientation)`: A4 portrait 595.28x841.89, LETTER 612x792, swapped for landscape.

The editor's text box (TemplateCanvas.tsx) is positioned at top = y, left = x, sized width x height, `text-align` per element, font size `fontSize` in page units, Tailwind `leading-tight` (line-height 1.25 x font size), text starting at the top of the box.

pdf-lib output, after inflating each Flate content stream (the existing tests already do this with `zlib.inflateSync`):
- drawText produces: `BT`, `/Helvetica-... <size> Tf`, `24 TL`, then `1 0 0 1 <x> <y> Tm`, then `<HEXWINANSI> Tj`, `T*`, `ET`. <x>,<y> is the baseline origin.
- drawImage produces: `q`, `1 0 0 1 <x> <y> cm`, `1 0 0 1 0 0 cm`, `<width> 0 0 <height> 0 0 cm`, `1 0 0 1 0 0 cm`, `/Image-... Do`, `Q`. <x>,<y> is the image's bottom-left corner.
- `font.heightAtSize(size, { descender: false })` returns the ascent (0.718 x size for Helvetica); `font.heightAtSize(size)` returns ascent plus descent (0.925 x size).
- `PDFImage` (from `embedPng`/`embedJpg`) exposes `.width` and `.height` in source pixels.
- The borders draw as `re`-less path rectangles (`0 0 m ... S`) under a translate `cm`; borders are symmetric about the page and need no conversion.

Existing exports to keep: `formatCertificateIssuedDate`, `renderCertificatePdf({ layout, fields, resolveAsset })`, types `CertificateRenderFields`, `CertificateAssetResolver`.
Invariant to keep: pdf-lib is imported ONLY by this file (tests/certificate-phase-invariants.test.ts invariant 1). The new test helper must NOT import pdf-lib as a value dependency of `src/`; a test may import pdf-lib (the existing renderer test already does).
