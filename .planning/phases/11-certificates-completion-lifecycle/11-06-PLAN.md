<objective>
Build CRD-04 end to end: a public, unauthenticated verification surface that resolves a reference to
exactly one of three outcomes and discloses nothing beyond the approved minimal facts.

Purpose: This is the phase's only deliberately-unauthenticated surface and its largest information-
disclosure risk. It ships before issuance exists precisely so its disclosure contract is settled and
tested in isolation rather than bolted onto a working issuance flow.
Output: One lookup function with a closed three-outcome return type, a standalone route group with its
own minimal layout, a result page, and a reference-entry page.
</objective>

  <behavior>
    - A reference matching an `ACTIVE` certificate returns `{ status: "active", learnerName, awardTitle, issuedAt }` and nothing else.
    - A reference matching a `REVOKED` certificate returns `{ status: "revoked", learnerName, awardTitle, issuedAt }` and nothing else — no `revocationReason`, no `revokedById`, no `revokedAt`.
    - A reference matching a `SUPERSEDED` certificate returns the `revoked` shape (a superseded credential is not the current credential of record and must not read as valid).
    - A reference matching nothing returns exactly `{ status: "not_found" }` with no other key present.
    - An empty string, a whitespace-only string, a 5000-character string, and a string containing SQL/regex metacharacters each return `{ status: "not_found" }` without throwing.
    - A certificate with `reviewFlaggedAt` set but `status: "ACTIVE"` still returns `active` — CRD-06's flag is a staff-internal review signal, not a public invalidation, and leaking it would disclose that a correction occurred.
    - If the database read throws, the function throws — it does not swallow the error into `not_found`, because a masked outage would silently report real credentials as unverifiable.
  </behavior>
  <action>
    Create `src/server/services/certificate-verification-service.ts` exporting:

    `type CertificateVerificationResult = { status: "active"; learnerName: string; awardTitle: string; issuedAt: Date } | { status: "revoked"; learnerName: string; awardTitle: string; issuedAt: Date } | { status: "not_found" }`

    and `async function verifyCertificateByRef(verificationRef: string): Promise<CertificateVerificationResult>`.

    Implementation requirements:
    - Query with an explicit Prisma `select` naming only `status`, `learnerName`, `awardTitle`, `issuedAt`.
      Do not select the whole row and then pick fields — a future `select`-less refactor would silently
      widen the disclosure surface. The `select` clause IS the disclosure contract.
    - `findUnique` on the `verificationRef` unique index.
    - Trim the input and return `not_found` for an empty result rather than querying with an empty string.
    - Build the three returns as object literals; never spread the database row.
    - Deliberately unauthenticated: this module does NOT import `withPermission` or the permission choke
      point. Add a header comment saying so explicitly, and saying why the omission is intentional
      (CRD-04), so a future reader does not "fix" it — and equally, so nobody adds a second unauthorized
      export to this file later.
    - Do not wrap anything here in a `'use cache'` helper and do not export `revalidate`/`dynamic` from
      this module (Pitfall 6).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous internet → verification lookup | Fully unauthenticated; the only such surface in this phase |
| URL path segment → server component | `verificationRef` is attacker-controlled input echoed back to the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-08 | Information Disclosure | `verificationRef` enumeration | mitigate | ≥128-bit reference entropy from plan 11-03; combined with the minimal four-field `select` here, a successful guess discloses only name + title + date. No rate limiter exists in this codebase (Pitfall 2) and this phase does not build one — entropy is the accepted primary control |
| T-11-21 | Information Disclosure | Response-shape oracle distinguishing "never issued" from "exists" | mitigate | The not-found branch renders no `<dl>` at all and the service returns an object whose only key is `status`; both are asserted, not assumed (Pitfall 3) |
| T-11-22 | Information Disclosure | Revocation reason or staff identity leaking publicly | mitigate | The Prisma `select` names only four fields; acceptance criteria grep for `revocationReason`/`revokedById`/`storageKey`/`userId`/`enrolmentId` returning 0 in both the service and the page |
| T-11-23 | Information Disclosure | `reviewFlaggedAt` leaking that a correction occurred | mitigate | Flagged-but-active certificates return `active`; a dedicated test case asserts it |
| T-11-24 | Spoofing | Stale cached "valid" verdict served after revocation | mitigate | No `dynamic`/`revalidate`/`'use cache'` anywhere in the segment; the Prisma read defers to request time per the Next 16 route-handler docs read in Task 2 (Pitfall 6) |
| T-11-25 | Tampering | Attacker-controlled path segment used to build a redirect or markup | mitigate | The reference is rendered as text only and `encodeURIComponent`-ed when the entry form builds a path; no `searchParams` lookup path exists |
| T-11-26 | Information Disclosure | A superseded credential reading as valid | mitigate | `SUPERSEDED` maps to the `revoked` outcome, with its own test case |
| T-11-SC | Tampering | npm installs | mitigate | This plan installs nothing; `git diff package.json` must be empty |
</threat_model>
