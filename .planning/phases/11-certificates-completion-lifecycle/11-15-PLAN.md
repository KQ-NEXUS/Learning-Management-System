<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → credential invalidation | Revocation immediately changes a credential's public status |
| staff-internal detail page → public-facing facts | This page shows the revocation reason; the public page must never |
| client-side reason validation → server enforcement | `minReasonLength` is a browser convenience, not a control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-47 | Elevation of Privilege | Revocation without `certificates.revoke` | mitigate | The action delegates to `revokeCertificate`, permission-gated with the enrolment's cohort scope; the `.strict()` schema and the service re-validate independently of what the UI rendered |
| T-11-49 | Repudiation | Revocation or reissue with no recorded justification | mitigate | `z.string().trim().min(10)` in the action schema AND the service's own `RevocationReasonRequiredError`; a test asserts the schema rejects a 9-character reason independently of the UI |
| T-11-50 | Information Disclosure | Revocation reason leaking to the public verify page | mitigate | The reason renders only on this staff detail page; acceptance criteria assert `revocationReason` appears here and returns 0 across `src/app/verify/` |
| T-11-67 | Tampering | Two staff revoking the same certificate simultaneously | mitigate | `CertificateChangedError` from the service's compare-and-set surfaces as a specific reload message rather than a silent second revocation |
| T-11-68 | Tampering | CRD-06 flags silently cleared | mitigate | No "Clear flag"/"Dismiss" control exists; asserted by grep. A flag is resolved by revoking or by a deliberate no-action, both leaving an audit trail or an intact historical fact |
| T-11-69 | Information Disclosure | A flagged certificate reading as plainly valid to staff | mitigate | `certificateDisplayStatus` drives the pill, with a dedicated test asserting flagged-but-ACTIVE never renders `success` "Active" (UI-SPEC §5's rendering contract) |
| T-11-38 | Information Disclosure | Raw service errors reaching the browser | mitigate | Fixed message mapping per error class, zero `error.message` pass-through, asserted by grep |
| T-11-SC | Tampering | npm installs | mitigate | This plan installs nothing; `git diff package.json` must be empty |
</threat_model>
