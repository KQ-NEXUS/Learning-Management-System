<objective>
Close review findings CR-03 and CR-04 in the issuance decision logic.

CR-03: `issueCertificateForEnrolment` (certificate-issuance-service.ts) runs `assertTransition(status, "COMPLETED")` for any enrolment status. Attendance
marking only excludes TRANSFERRED/CANCELLED, so a WITHDRAWN or PENDING_PAYMENT enrolment that satisfies an AUTOMATIC award's rule makes the staff attendance
write throw IllegalTransitionError. `computePendingIssuance` (certificate-service.ts) also lists such enrolments in the manual queue, where Issue always fails.

CR-04 (user decision, fixed input): a REVOKED certificate must NEVER be followed by an automatic re-issue for the same enrolment + scope. Only the staff
Reissue action creates a replacement (CRD-05). Today the ACTIVE-only pre-check and partial unique index let undo-then-redo of a lesson produce a brand-new
certificate and move the enrolment back to COMPLETED, defeating the revocation.

Decisions made here (CR-03 asked to "decide explicitly for WITHDRAWN"): only ACTIVE and COMPLETED enrolments are certificate-eligible. WITHDRAWN,
PENDING_PAYMENT, TRANSFERRED and CANCELLED learners are not. COMPLETED stays eligible because staff Reissue delegates to the same function for an enrolment
that never left COMPLETED (existing idempotent branch). The revoked-blocked rule applies to manual queue issuance too: staff replace a revoked credential
through Reissue, not through the queue. This plan adds no second writer of Enrolment COMPLETED (D-05, invariant 7).

Purpose: automation can never fail a caller's write over an ineligible enrolment, and can never silently undo a staff revocation.
Output: two new typed outcomes, the queue filters, the action messages, and tests that fail against the pre-fix behaviour.
</objective>

certificate-service.ts (current):
- `PendingIssuanceCompletionRecordRow = { enrolmentId; scope; completedAt; enrolment: { userId; user: { name }; cohort: {...} } }` (the enrolment status is not in the row type; the Prisma `include` already returns the full enrolment row).
- `computePendingIssuance()` reads `completionRecord.findMany({ where: { supersededAt: null }, include })`, then `certificate.findMany({ where: { status: "ACTIVE" } })` into an `alreadyIssued` set keyed `${enrolmentId}:${scope}`.
- `issueCertificateManually` re-checks the completion record then delegates to `issueCertificateForEnrolment` with a staff actor.
- `reissueCertificate` first `updateMany`s the old row (status in ACTIVE/REVOKED, `where: { id: before.id, ... }`, must affect exactly 1 row else CertificateChangedError) to SUPERSEDED, then calls `issueCertificateForEnrolment`, and throws a generic Error for any outcome other than `issued`. The tx type's `certificate.updateMany` takes `where: Record<string, unknown>`, so a second `updateMany` keyed on `enrolmentId`/`scope` needs no type change.

certificate-actions.ts: `issueCertificateAction(input)` switch over `outcome.kind` with a fixed string per case; an exhaustive switch (adding union members without cases is a compile error).
