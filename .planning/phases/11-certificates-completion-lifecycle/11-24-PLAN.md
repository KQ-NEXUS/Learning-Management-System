<objective>
Fix the test-18 observation (MINOR, function passes): one attendance correction on a Programme cohort wrote three `certificate.review_flagged`
audit events about 50 ms apart, all actor SYSTEM.

Root cause (verified in the source): `reactToCompletionResults` (`certificate-issuance-service.ts` ~L619-L668) calls `flagCertificateForReview` for EVERY
result whose action is `superseded`. On a Programme cohort a single correction supersedes two COURSE-scope member records and the PROGRAMME record, and
`flagCertificateForReview` is keyed on the enrolment (it flags "the ONE ACTIVE certificate for the enrolment"), so it runs three times. The `created`
branch already skips COURSE-scope results on Programme cohorts (D-01); the `superseded` branch has no equivalent guard. The actor is always SYSTEM,
unlike the grade-override path (plan 11-10), which passes the staff actor.

Purpose: CRD-06 says corrections flag the certificate for review; an auditor reading three near-identical SYSTEM entries cannot tell how many corrections
happened or who made them. This makes one correction produce one attributable entry.

Output: The D-01 guard on the superseded branch, a once-per-call flag, an optional actor threaded from the attendance service, and tests that fail against
the pre-fix behaviour.
</objective>
