<objective>
Wire plan 11-30's post-commit mechanism into every place a transaction can issue a certificate, and make the download route produce a missing file on demand.

Wiring points (verified by grep: only these four modules touch `recalculateCompletionAndIssue` / `issueCertificateForEnrolment`): the lesson-progress composition root (`createPrismaBackedLessonProgressService`, its `runInTransaction` at ~L794), the attendance composition root (~L806), and certificate-service.ts (manual issue and Reissue). The first two are Prisma-backed factories, so each of their `runInTransaction` becomes `runTransactionThenSettleCertificateFiles(<the existing $transaction call>, fn, settle)` with an optional trailing `settle` factory parameter for tests. certificate-service.ts is structurally different and is wired differently: `createCertificateService(deps)` RECEIVES `runInTransaction` as a dependency, and the live `prisma.$transaction` wrapper (~L706) is a module-level binding with no factory to add a parameter to, so the settle wrapper lives INSIDE `createCertificateService` (an optional `settle` member of `CertificateServiceDeps` plus a private `runSettled` helper that wraps the `runInTransaction` it received). Grade override only flags (no issuance) and needs no change.

Retry path: if the post-commit step failed or timed out, the certificate has no `storageKey`. The download route already treats that as a 404; this plan makes it call `ensureCertificateFile(id)` AFTER the existing authorization predicates and only then presign, so the learner's or staff member's first click completes the file. `ensureCertificateFile` never throws, returns the key or null, and is idempotent (compare-and-set), so two clicks or a click racing the settle step converge.

Denial parity is load-bearing (route header): every non-success outcome is the same empty 404, and nothing may become an oracle. The on-demand step runs only for a certificate the caller is already authorized to read, and a failure to produce the file is the same 404.

Output: three composition roots, the route, and tests including the ordering and containment guarantees.
</objective>
