## 3. Superseded or changed since plan time

- Font embedding (T-11-120, 11-29 and 11-32 text): plans describe subset embedding and "3-5 KB" size. Commit `c7d8033` replaced it with whole-font embedding (`subset: false`, `certificate-pdf-renderer.ts:327-330`) after the plan-11-33 visual check found blank glyphs. The size guard test was rewritten to a 200-500 KB window. The control that still holds today is the size bound and single fixed font, not subsetting. Stale wording remains in `certificate-file-service.ts:46-48` ("subset-font one-page PDF"), comments only.
- Template image key confinement (T-11-118 context): added later by `704f79e` (WR-03); strengthens the plan-11-34 control.
- Learner download (T-11-129/130/133 context): `getOwnCertificateForDownload` now returns only the current ACTIVE row (`4c6ee07`, WR-05), so a SUPERSEDED certificate no longer downloads for the owner. Strengthens the plan-11-31 control.
- T-11-127 wording: the audit row is written through the global Prisma client (`audit-service.ts:100-102`), not `tx`. The plan and summary text ("written in the caller's transaction") is inaccurate for the audit row only. Consequence: if the caller's transaction rolls back after `deps.audit` ran, a `certificate.issued` audit row could remain for a certificate that was never committed; conversely no committed certificate lacks an audit row unless the audit insert itself throws (which would abort issuance). This is the project-wide audit-first convention, not introduced by Phase 11, and does not create an unaudited issuance.
- Plan 11-33 was human-only. Deviation recorded in `11-33-SUMMARY.md`: the orchestrator applied the migration to a Neon mirror branch and to the main Neon database on the user's explicit instruction, after a rehearsal, with the preflight diagnostic (0 rows) and post-apply verification recorded. Assessment: the control the plan cared about (a human decides timing and target, a restore point exists, preflight before DDL, no auto data change, per-environment record) all hold; the only thing that changed is who typed the command. The decision was the user's own recorded instruction, so this is judged acceptable and not a gap. The single follow-up is credential hygiene for the shared branch string (above).
