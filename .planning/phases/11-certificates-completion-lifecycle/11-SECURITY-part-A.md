## 2. Open threats

None of the 54 register rows is OPEN. No BLOCKER findings.

Advisories (not blockers, no register row is downgraded because of them):

- A-1 (low) - T-11-15 accepted risk: the layout parser (`certificate-template-layout.ts:109-113`) bounds nothing (element count, font size, box size) and `ensureCertificateFile` is awaited unbounded by the download route (`download/route.ts:86`). A `certificates.manage` holder who calls the server action directly (not through the editor) could save a layout that makes each render slow. Blast radius: that staff member's own certificate output and download requests for rows without a stored file; the learner's lesson/attendance write is no longer affected (post-commit rendering, 6 s settle bound). Next's default server-action body limit also bounds the payload.
- A-2 (low) - T-11-37: the archived-template protection is UI only. The service does not reject `update` for a template with `archivedAt` set. Scenario: a `certificates.manage` holder posts `saveTemplateLayoutAction` for an archived template id; a Course still pointing at that archived template (allowed per RESEARCH Pitfall 5) would render future certificates from the edited layout. The plan's declared mitigation (UI read-only) is present, so this is recorded as an advisory, not an OPEN threat. A one-line `archivedAt` guard in `certificateTemplateService.update` would close it.
- A-3 (info) - `scripts/certificate-pdf-probe.mts` imports `pdf-lib` outside `src/`; invariant 1 scans only `src/`. It is a dev script with no learner data and no runtime path.

## 3. Superseded or changed since plan time

- Issuance is database-only (plans 11-30/11-31). `issueCertificateForEnrolment` creates the row with `storageKey: null`, transitions the enrolment, audits, emits the event and registers the id; it renders and stores nothing (`certificate-issuance-service.ts:9-26,486`; invariant 8). The PDF is produced after the caller's transaction commits (`certificate-file-service.ts:229-287,310-334,368-386`) or lazily by the download route after authorization. Effect on threats: T-11-01 (plan 11-07's "create-first ordering before rendering work" is now trivially true), T-11-32 (no PDF bytes anywhere near the outbox), T-11-16 (the render happens in the file service). All controls still hold.
- T-11-01 consumer: `createMany({ skipDuplicates })` (ON CONFLICT DO NOTHING) replaced create + catch P2002 because a P2002 would abort the caller's Postgres transaction. The partial unique index from 11-01 is unchanged and remains the arbiter. A second guard was added: an enrolment/scope that already holds a REVOKED certificate returns `revoked-blocked` (`certificate-issuance-service.ts:370-375`, CR-04), and the enrolment status must be ACTIVE/COMPLETED (`:229,303-305`, CR-03). The live-enrolment unique index was widened to `('ACTIVE','COMPLETED')` (migration `20260919120000`, CR-06) so a COMPLETED -> ACTIVE reversal cannot collide.
- Renderer font (plan 11-29/11-33): the whole bundled Noto Sans is embedded (`subset: false`) via `@pdf-lib/fontkit` (`certificate-pdf-renderer.ts:321-330`), replacing the WinAnsi-only Helvetica; all text is sanitised (`sanitiseCertificateText`, `:184-200`) so a learner name cannot make rendering throw. The bundled font file is loaded from `assets/fonts/certificate` (`certificate-font.ts`), traced via `next.config.ts`. No new dependency.
- Image handling (CR-02): template asset uploads are PNG/JPEG only (`upload-limits.ts:131-159`), narrower than the plan's "reuse the IMAGE list verbatim" for T-11-11; renderer skips undecodable image bytes rather than throwing (`certificate-pdf-renderer.ts:251-270`), a partial relaxation of T-11-16 confined to images. Resolver/storage failures still throw.
- Asset key confinement (WR-03, this mini-pass): T-11-14's "keys come from the template's own asset records" is realised as "the parser only accepts keys under `certificate-template-assets/` with no traversal" (`certificate-template-layout.ts:157-176`), enforced at write and at render.
