<objective>
Wire plan 11-07's reactive logic into the three live call paths that can change a learner's completion
evidence — lesson progress, attendance, and grade overrides — without changing a line of business logic
in any of them.

Purpose: CRD-06 has two structurally different halves. Attendance and lesson corrections flow through
`recalculateCompletion`; grades do not flow through the completion engine at all (`completionRule` v1 has
no assessment criteria), so they need an independent hook that flags rather than re-derives.
Output: Two composition-root default-parameter swaps, one new injected dependency on
`grade-override-service.ts`, one new flagging function, and an import-closure guard.
</objective>

  <behavior>
    - Overriding a released grade for an enrolment holding an `ACTIVE` certificate sets that certificate's `reviewFlaggedAt`.
    - The certificate's `status`, `verificationRef`, `issuedAt` and `storageKey` are unchanged by the flag.
    - If the enrolment is currently `COMPLETED`, it is moved back to `ACTIVE` through `assertTransition` (D-06 names "flagged for review" as one of the two states that reverts the enrolment). If it is any other status, it is left alone and no error is raised.
    - The certificate itself is NOT revoked and stays publicly verifiable as `active` while the flag is outstanding — D-06 reverts the enrolment's terminal state, it does not invalidate the credential.
    - No `CompletionRecord` is created or superseded by this path.
    - Overriding a grade for an enrolment with no certificate is a no-op that does not throw.
    - Overriding a grade for an enrolment whose certificate is already `REVOKED` does not flag it.
    - A `certificate.review_flagged` domain event and an audit row are written, carrying the reason "grade corrected" and the overriding actor's id — not `SYSTEM`, because a human requested this correction.
    - The flag write happens inside `overrideGrade`'s existing transaction: if the grade update rolls back, the flag rolls back with it.
  </behavior>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| learner-triggered write → credential issuance | Marking a lesson complete now creates a legally significant document as a side effect |
| staff grade correction → credential validity | A grade override now mutates certificate state in the same transaction |
| module import graph → unauthorized webhook surface | Widening one service's closure can drag the permission choke point onto a deliberately unauthorized module |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-11-40 | Elevation of Privilege | Certificate writes reachable from an unauthorized module | mitigate | Task 3's closure assertion proves `checkout-webhook-system-service.ts` does not gain the certificate/PDF closure; the Phase 6 T-06-33 precedent is the reason this is a test and not a review note |
| T-11-41 | Tampering | A grade correction silently altering or revoking a credential | mitigate | `flagCertificatesForGradeCorrection` writes only `reviewFlaggedAt` on the `Certificate`; behaviors assert `status`, `verificationRef`, `issuedAt` and `storageKey` all unchanged. The enrolment revert (D-06) is a separate, audited, `assertTransition`-guarded write that never alters the credential itself (CRD-06) |
| T-11-42 | Repudiation | A flag with no attributable actor | mitigate | The grade-correction flag records the overriding staff actor's id, deliberately not `SYSTEM`, since a human requested the correction |
| T-11-43 | Tampering | A correction that rolls back leaving a stale flag | mitigate | The hook is called inside `overrideGrade`'s existing transaction, after `writeEvent` and before the final read — asserted as a behavior |
