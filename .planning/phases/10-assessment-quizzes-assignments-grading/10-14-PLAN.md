    uploaded" with the body "Nothing was submitted. Check your connection and try again." That body
    string is ASM-04's invariant stated in learner language — it must never be softened into something
    ambiguous about whether the submission landed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| learner browser → submission actions | Filename, declared mime type and size cross here |
| learner browser → object store | Direct presigned PUT; the body never traverses the app server |
| server verification → receipt render | A receipt may only render from a verified completion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-19 | Repudiation | false-success receipt | mitigate | The receipt state renders only from `completeSubmissionUploadAction`'s returned `SubmissionReceipt`; the begin step returns no `receiptId` at all, so an optimistic render is not constructible. Two failure cases assert the absence of receipt text |
| T-10-33 | Tampering | client-fabricated receipt facts | mitigate | The action schemas reject `receiptId`, `isLate`, `enrolmentId` and `storageKey`; all four are derived server-side, so a client cannot backdate lateness or claim another learner's enrolment |
| T-10-02 | Information Disclosure | submission actions | mitigate | Every action resolves the actor with `getCurrentActor` and delegates to the ownership-scoped service; no action accepts an `enrolmentId` |
| T-10-18 | Tampering | declared size and type | mitigate | The service re-validates the declared values against the authored constraints before presigning and against the stored object before promoting; the browser's declaration is never the only check |
| T-10-34 | Cross-site scripting | authored instructions HTML | mitigate | Instructions render through the same double-pass sanitiser `LessonContent`'s `BodyProse` already uses; no second, weaker rendering path for authored HTML is introduced |
| T-10-SC | Tampering | npm installs | accept | No package installs; the upload flow reuses the existing AWS SDK presigning already in `storage-service.ts` |
</threat_model>
