<objective>
Build the first half of the learner quiz attempt state machine: starting or resuming an attempt,
freezing the question set into `Attempt.answers` per D-08, and saving in-progress answers — all under
an ownership comparison, never an RBAC permission check.

Purpose: D-08 makes ASM-01's "learner attempts use the assigned version" real. `QuizQuestion` and
`QuizOption` are plain mutable rows with no version stamp; the only thing that can make a scored
attempt immune to a later question edit is a snapshot frozen at start time. Everything plan 10-06
scores reads from that snapshot.
Output: `attempt-service.ts` (start/resume/save/read) and `tests/attempt-service.test.ts`.
</objective>

The snapshot written into `Attempt.answers` (a `Json?` column) is this exact shape and is the
contract plan 10-06's scoring and plan 10-11's rendering both read:

`{ questionSnapshot: QuestionSnapshot[]; responses: AttemptResponse[]; passMark: number | null; totalMarks: number | null }`

where `QuestionSnapshot` and `AttemptResponse` are the types plan 10-02 exports from
`src/server/services/quiz-scoring.ts`:
- `QuestionSnapshot = { id; position; prompt; type: "SINGLE_CHOICE" | "MULTI_CHOICE" | "TRUE_FALSE"; marks; explanation: string | null; options: Array<{ id; position; label; isCorrect }> }`
- `AttemptResponse = { questionId: string; selectedOptionIds: string[] }`

Existing precedent contracts this plan follows:
- `Actor = { userId: string; isStaff?: boolean }` from `src/server/permissions/with-permission.ts`
- `writeDomainEvent(tx, event)` from `src/server/services/domain-event-service.ts` — always called with the CALLER's tx
- `recordAudit(event: BusinessAuditEvent)` from `src/server/services/audit-service.ts`

**DD-15 discipline (mandatory):** this file must contain ZERO `withPermission`-wrapped exports.
Every function here is ownership-scoped — the enrolment is re-derived from `actor.userId`, never
accepted from the caller. Importing `withPermission` here would pull the permission choke point onto
the learner request closure, which `tests/learning-phase-invariants.test.ts` already gates for
`lesson-progress-service.ts` and plan 10-17 will gate for this file.

  <action>
    Implement four functions inside the factory.

    `startAttempt(actor, input: { assessmentId })`:
    1. Re-derive the enrolment from `actor.userId`: find the actor's enrolment whose cohort's pinned
       course contains the Assessment's `courseId`. Never accept a caller-supplied `enrolmentId` —
       that is the T-10-02 IDOR surface. If none, throw `AttemptNotStartableError` with `"not-found"`,
       identical to the refusal for a non-existent assessment, so the caller learns nothing.
    2. Refuse `"not-a-quiz"` when `Assessment.type !== "QUIZ"` and `"not-published"` when
       `status !== "PUBLISHED"`.
    3. Refuse `"window-not-open"` when `availableFrom` is set and `now()` precedes it; refuse
       `"window-closed"` when `availableUntil` is set and `now()` is past it (per CONTEXT.md's
       Resolved note, `availableUntil` is the hard cutoff for both Assessment types; `dueAt` never
       blocks anything).
    4. Count this enrolment's existing attempts for this assessment. Refuse
       `"attempt-limit-reached"` when `maxAttempts` is a number and the count of non-ABANDONED
       attempts already equals it. A null `maxAttempts` means unlimited.
    5. If an `IN_PROGRESS` attempt already exists for this enrolment+assessment, RESUME it: return it
       unchanged rather than creating a second one. Starting a genuinely new attempt (caller passes an
       explicit `startNew: true`) first flips the prior `IN_PROGRESS` attempt to `ABANDONED` inside
       the same transaction, per UI-SPEC §0.3.
    6. Build the snapshot: read the live `QuizQuestion` rows with their `QuizOption` rows ordered by
       `position`, map them into `QuestionSnapshot[]` (including each option's `isCorrect`), and write
       `{ questionSnapshot, responses: [], passMark, totalMarks }` into `Attempt.answers`. Stamp
       `versionUsed` with the Assessment's current `version` and `attemptNumber` with the highest
       existing attempt number for this enrolment+assessment plus one (the
       `@@unique([assessmentId, enrolmentId, attemptNumber])` constraint is the backstop if two
       requests race — catch the unique-violation and retry once, in the same spirit as
       `PositionContentionError`'s handling in `resource-service.ts`).
       The snapshot INCLUDES `passMark` and `totalMarks` deliberately: 10-RESEARCH.md flags that a
       later `passMark` edit would otherwise retroactively change whether an old attempt reads as
       passed. Freezing them here closes that hole and is this plan's answer to Open Question 1's
       follow-up. Record this choice in the summary.
    7. All writes inside one `runInTransaction`. Write an audit entry after the transaction with
       action `attempt.started`, `targetType: "Attempt"`, `actorId: actor.userId`, `outcome: "SUCCESS"`.
       No domain event at start — the outbox event fires at submit (plan 10-06).

    `saveAttemptAnswers(actor, input: { attemptId; responses: AttemptResponse[] })`:
    Load the attempt, compare its enrolment's user to `actor.userId`, refuse `"not-own"` on a
    mismatch. Refuse `"already-submitted"` unless `status === "IN_PROGRESS"`. Refuse
    `"window-closed"` when `availableUntil` has passed (plan 10-06's submit path handles the lazy
    EXPIRED transition; this path only refuses the write). Merge the supplied responses into the
    payload's `responses` array WITHOUT touching `questionSnapshot`, `passMark` or `totalMarks` — the
    frozen fields are never rewritten after start. Discard any `questionId` not present in the
    snapshot and any `selectedOptionId` not present in that question's snapshot options, so a crafted
    payload cannot inject a phantom question. No audit entry per keystroke-level save; this is
    in-progress scratch state, not a decision.

    `getOwnAttempt(actor, attemptId)`: ownership comparison in `getOwnOrder`'s shape — return `null`
    on a mismatch or a missing row rather than throwing, so "not yours" and "does not exist" are
    indistinguishable.

    `listOwnAttempts(actor, input: { assessmentId })`: the actor's own attempts for one assessment,
    newest `attemptNumber` first, for the attempt-history UI.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| learner client → attempt server action | Caller supplies `assessmentId` / `attemptId` / raw option selections; nothing else is trusted |
| live QuizQuestion rows → a started attempt | Crossed exactly once, at start time, into an immutable snapshot |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-02 | Information Disclosure | `startAttempt`, `saveAttemptAnswers`, `getOwnAttempt` | mitigate | The enrolment is re-derived from `actor.userId`; no exported input type carries an `enrolmentId`. `getOwnAttempt` returns `null` rather than throwing on a mismatch so an attacker cannot distinguish "not yours" from "does not exist" (same T-05-06 class threat `cohort-scope.ts` documents) |
