<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff client → assessment authoring server action | Caller-supplied `assessmentId` crosses here; the scope must be resolved from the row, never asserted by the caller |
| browser → object store (presigned PUT) | The browser holds a time-limited write URL for a staged key |
| staged key → final key | Server-side promote is the only transition; the browser cannot trigger it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-06 | Tampering | `storage-service.ts` submission key builders | mitigate | Staged key embeds `randomUUID()` and is never the final key; `finalSubmissionKeyFor` throws on any prefix other than `submission-uploads/`, and `finalStorageKeyFor` remains Lesson-only — a leaked staged URL cannot address another learner's final object, and no cross-domain promote is expressible |
| T-10-07 | Elevation of Privilege | `assessment-scope.ts` | mitigate | `assessmentCourseScope` reads `courseId` from the Assessment row itself and returns `{}` for a missing row, so a caller-asserted course id can never widen a grant's reach (same T-05-07 class threat `cohort-scope.ts` documents) |
| T-10-SC | Tampering | npm installs | accept | This phase installs no new packages (10-RESEARCH.md Package Legitimacy Audit: not applicable — every dependency is already present and was vetted in prior phases). No install task exists in any Phase 10 plan; if one is later added, the Package Legitimacy Gate applies before it runs |
</threat_model>
