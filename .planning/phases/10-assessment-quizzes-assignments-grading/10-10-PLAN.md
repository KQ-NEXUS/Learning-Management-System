  <action>
    Create `src/components/catalogue/QuestionBuilder.tsx` as a client component taking the current
    `QuestionDraft[]`, the `assessmentId`, and a submit callback.

    Per question block: a prompt field (Display role), a type selector over exactly
    `SINGLE_CHOICE` / `MULTI_CHOICE` / `TRUE_FALSE`, a numeric `marks` field defaulting to 1, an
    optional `explanation` field, and an option list.

    Option list behaviour by type:
    - `SINGLE_CHOICE`: options are freely editable labels; correctness is a radio group, so selecting
      one option's correct marker clears the others. Exactly one correct option is enforceable in the
      UI because the control makes more than one unrepresentable.
    - `TRUE_FALSE`: the option labels are fixed to "True" and "False" and are not editable — the
      builder creates them automatically when the type is chosen, and correctness is the same radio
      group. Changing a question's type to `TRUE_FALSE` replaces its options with this pair.
    - `MULTI_CHOICE`: options are freely editable and correctness is a checkbox per option, so several
      can be correct. Show an inline hint naming D-09's partial-credit rule in plain language so the
      author understands that a learner selecting extra wrong options loses marks — authors otherwise
      have no way to know the scoring behaviour their question will get.

    Correctness indicators use colour plus an icon, never bold weight, per UI-SPEC §4's note that
    correctness is a colour-and-icon fact rather than a typographic one. Native radio and checkbox
    controls are restyled to the 16px / 1.5px `border-input-border` treatment the 04.1 system uses —
    restyle the native control, do not build a custom widget.

    Question-level actions: add question (appends at the end), remove question (with an inline
    confirmation, not a `ConfirmModal` — removing an unsaved draft question is not an audited
    destructive act), and reorder. Reorder MUST support keyboard as well as pointer, reusing
    `ArrangeBoard`'s existing approach including its live-region announcements and its non-colour drag
    outline — accessibility parity with the lesson arranger is the bar here, and a pointer-only
    reorder would regress it.

    Option-level actions: add option, remove option, reorder within the question (keyboard-accessible
    by the same mechanism).

    Dirty state: render the same labelled dirty-state pill `ArrangeBoard` uses, and reuse
    `UnsavedOrderGuard` if its contract fits, so a staff member cannot navigate away from unsaved
    question edits without warning.

    Inline defects: call `evaluateAssessmentReadiness` on the current draft (it is a pure function,
    safe to run client-side) and render the question-scoped blocking items beside the questions they
    name, keyed on the item `id`. This is the same evaluator the server publish gate runs, so the
    panel and the gate cannot drift — that single-evaluator discipline is exactly why
    `readiness-service.ts` exists in its current shape.

    Add the component to `src/components/catalogue/index.ts`'s barrel export alongside its siblings.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → question save action | The whole question/option set, including `isCorrect` flags, crosses here |
| authored answer key → learner-visible content | `isCorrect` must never reach a learner before their attempt is scored |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-07 | Elevation of Privilege | `saveQuizQuestionsAction` | mitigate | Delegates to `saveQuizQuestions`, which is `withPermission("assessments.edit")`-wrapped and scoped via `assessmentCourseScope`; the action itself imports no `@prisma/client` |
| T-10-28 | Tampering | question payload shape | mitigate | `zod` validates every question's type against the three-member union, `marks` as a positive integer, and `prompt` as non-empty before the service is called; the service re-validates and recomputes `totalMarks` itself rather than trusting a client-supplied sum |
| T-10-22 | Information Disclosure | answer key | mitigate | The builder is a staff-only surface under `/staff/*`; `isCorrect` flags reach the learner only through plan 10-06's post-submit `AttemptResultView`, never through the in-progress attempt payload (asserted in plan 10-11) |
| T-10-SC | Tampering | npm installs | accept | No package installs; reorder reuses the existing in-repo `ArrangeBoard` implementation rather than adding a drag-and-drop library |
</threat_model>
