<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → learner browser (RSC payload) | Everything sent here is inspectable; the answer key must not cross during an attempt |
| learner browser → submit action | Only raw option selections are trusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-22 | Information Disclosure | in-progress attempt payload | mitigate | The view builder strips `isCorrect` and `explanation` server-side before the payload leaves; a test asserts on the JSON-stringified payload. Not rendering them client-side is not a defence, because the RSC payload is readable in devtools |
| T-10-01 | Tampering | `submitAttemptAction` | mitigate | The zod schema accepts only `questionId` and `selectedOptionIds`; a `score` field is rejected at the route boundary and is additionally unrepresentable in the service input type |
| T-10-02 | Information Disclosure | attempt actions | mitigate | Every action resolves the actor with `getCurrentActor` and passes it to the ownership-scoped service; no action accepts an `enrolmentId` |
| T-10-29 | Repudiation | raw errors reaching the client | mitigate | Service refusals are mapped to the UI-SPEC copy as typed results; a bare error is never thrown across the client boundary, so a stack trace cannot leak internals |
| T-10-SC | Tampering | npm installs | accept | No package installs; `lucide-react` icons are named imports from the already-vetted package |
</threat_model>
