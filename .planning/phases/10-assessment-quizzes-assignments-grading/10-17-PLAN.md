       choke point onto the learner request closure.
    4. **No caller-asserted enrolment.** No exported function in `attempt-service.ts`,
       `submission-service.ts` or `learner-results-service.ts` declares a parameter whose type includes
       an `enrolmentId` property — the enrolment must always be re-derived from `actor.userId`. Walk
       the exported function signatures via the AST; if the shape makes this impractical to assert
       precisely, assert instead that the string `enrolmentId` appears in no exported input type alias
       in those files, and document the narrowing in a comment.
    5. **Scope resolver isolation.** `assessment-scope.ts` takes no VALUE import from
       `src/server/permissions/**` — only the `ResourceScope` type, via a type-only import. This
       mirrors `cohort-scope.ts`'s own header rule.
    6. **Released-grade write boundary.** `grading-service.ts` contains no write that sets a Grade's
       `score` without first asserting the status is not `RELEASED`. Assert this structurally: the file
       exports a `GradeAlreadyReleasedError` and every Grade-score-writing function references it. If a
       fully structural assertion proves impractical, assert that `grade-override-service.ts` is the
       only file in `src/server/services/` that creates a `GradeOverride` row, and that
       `grading-service.ts` names `GradeAlreadyReleasedError` at least once — and record the narrowing
       in a comment rather than silently weakening the gate.
    7. **Override reason is mandatory in code, not only in UI.** `grade-override-service.ts` names both
       `OverrideReasonRequiredError` and `GradeNotReleasedError`, and both are thrown before any
       `create`/`update` call in its exported override function.
    8. **Route data-access boundary.** No `.ts`/`.tsx` file under
       `src/app/staff/courses/[id]/assessments/`, `src/app/staff/cohorts/[id]/grading/`, or
       `src/app/(learner)/learn/[enrolmentId]/results/` has an import declaration from
       `@prisma/client`.
    9. **Closed permission catalogue untouched.** `src/server/permissions/catalogue.ts` contains no
       identifier matching `assessments.view`, `grades.release` or `grades.batch_release` — the phase
       shipped without a catalogue addition, as 10-RESEARCH.md determined it must.

        no `cutoffAt` field — D-08 resolved versioning with the attempt snapshot, and `availableUntil`
        serves as the hard cutoff for both assessment types.
    11. **Single batch transaction.** `grading-service.ts`'s batch-release function contains exactly
        one transaction call, and no loop in that file invokes a `withPermission`-wrapped release per
        id.
