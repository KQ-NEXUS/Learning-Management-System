## Topic: Authentication decision — no Auth.js
- source: docs/superpowers/plans/2026-09-01-auth-and-courses-slice.md
- Decision: session authentication is written directly against the existing `Session` model — Auth.js is explicitly not used. Rationale given: "PRD IAM-03 requires selective and global session revocation. Auth.js's Credentials provider does not support the database session strategy — it forces JWT, and a signed token cannot be withdrawn before it expires." A sign-in server action verifies a scrypt hash, creates a session row, and sets an httpOnly cookie; `getCurrentActor` reads it.
- Note: this contradicts the file-structure listing in `docs/superpowers/specs/2026-09-01-track-a-foundation-design.md` (SPEC, precedence 2), which places "Auth.js configuration, database sessions" under `src/server/auth/`. Per the manifest precedence (SPEC ranks 2, above this DOC's 3), the foundation-design SPEC's description technically outranks this DOC — however the SPEC itself does not mandate Auth.js as a hard requirement (it only labels the folder's expected contents), and this DOC's stated rationale ties directly to a PRD requirement (IAM-03) that the SPEC does not address. Flagged in INGEST-CONFLICTS.md as an auto-resolved item for downstream awareness rather than left silent.
