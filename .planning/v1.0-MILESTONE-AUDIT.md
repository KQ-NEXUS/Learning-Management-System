# v1.0 Product Audit — 2026-09-25

The audit itself changed no source code. The four "Fix first" items were fixed afterwards on 2026-09-26; see section 1. All findings come from reading the code: no live browser was used and nothing was tested against a deployment. The detailed reports, with file:line evidence for every item, are listed in `detail_reports` above.

**Verdict: gaps found.** The main learner journey is wired end to end in code, from the catalogue through to certificate verification. The earlier critical review bugs in phases 05 and 07 are fixed. At audit time, two features built in these phases didn't work as specified, staff password hashes reached the browser, and error handling across the app was thin. All four are fixed as of 2026-09-26 (section 1). What remains open is the security mediums, the integration warnings, the UX clean-up, and the verification gaps.

## 1. Fix first (blockers and high)

All four items are **fixed as of 2026-09-26**. The fixes are uncommitted on `Khaliddev`, and each was written test-first.

| # | Area | Finding | Requirements | Status |
|---|------|---------|------|--------|
| 1 | Security | **Staff password hashes reach the browser.** The `/staff/users` list sends full `User` rows, including `passwordHash`, `lockedUntil` and `pendingEmail`, to a client component. | IAM-04 | ✓ Fixed |
| 2 | Integration | **Staff can't open a ticket's linked record.** `contextDto` hard-codes `href: null, locked: true`; the resolver that does the fresh permission check exists but is never used. | SUP-05 | ✓ Fixed |
| 3 | Integration | **Grades never feed completion.** The completion rule counts only lessons and attendance, so a certificate can issue with no quiz or assignment passed. Phase 10 deferred this and no later phase took it on. | ASM-05/07, LRN-07, CRD-01/02 | ✓ Fixed |
| 4 | UX | **No `error.tsx` or `global-error.tsx` anywhere**, so any unhandled error shows Next's plain default error page. Only 8 `loading.tsx` files for 77 routes. | NFR (Ph15) | ✓ Fixed |

### How each was fixed

1. **Staff password hashes.** `staffAccountService.list/get` now return a `StaffAccountSummary` with display fields only: id, name, email, status, created and deactivated dates. The `as unknown as` cast on the users page is gone. Tests assert that the hash never appears in either result.

2. **Ticket context links.** `createStaffTicketContextAuthorizer` (`ticket-context-service.ts`) is now wired into staff ticket detail. Each record type is checked against the permission its own staff page uses:

   | Record | Permission | Links to |
   |---|---|---|
   | Course | `courses.view` | course page |
   | Cohort | `cohorts.view` | cohort page |
   | Order | `payments.view` | payment page |
   | Submission | `submissions.view` | grading page |
   | Certificate | `certificates.view` | issued-certificate page |

   Everything else stays locked with "Your role cannot open this record." The target page still re-checks permissions when it opens, and learner views never get a link.

3. **Grades toward completion.** This uses a per-course setting (the product decision made 2026-09-26).
   - **The setting:** completion rule v2 adds `requirePassingAssessments`, shown in the course form as "Learners must pass required assessments". It takes effect on the next publish, so learners already enrolled keep the rules they signed up under. Existing courses stay on v1.
   - **What counts:** every assessment linked from a required pinned lesson needs a released, non-failing result.
     - Quizzes use `selectEffectiveAttempt`, the same helper the results page uses.
     - Assignments use their latest released grade.
     - An assessment with no pass mark counts once its result is released.
     - An assessment archived since publishing is dropped.
   - **When it's re-checked:** after staff release a grade (single or batch), after a quiz auto-releases, and after a grade override. Each runs `recalculateCompletionAndIssue`, so the course can complete and its certificate can auto-issue.
   - **Programmes:** a programme can't complete before its member courses' required assessments are passed.
   - **Dashboard:** it uses the same evidence loader for course cohorts. For programme cohorts, it shows "complete" only once the PROGRAMME completion record exists.

4. **Error and loading boundaries.**
   - `global-error.tsx`, plus an `error.tsx` at the root and in staff, (learner), (lesson), (public), (checkout), (auth) and account.
   - Each uses the shared `RouteErrorPanel`: retry via `retry()`, a link home, and the error digest as a support reference. It never shows `error.message`.
   - `loading.tsx` added for staff, (learner) and (lesson).

### Batch 1, fixed 2026-09-27

- **F-07 — grant ceiling.** Assigning a role, including a new staff account's first role, now requires the actor to hold every permission in that role at a scope covering the target. Nobody can assign a role to themselves, admins included. Global administrators hold everything, so they can still assign any role to anyone else. Refusals show as form errors that name the missing permissions.
- **F-05 — assessment-course scope.** Assessment-bound staff work is now checked against the assessment's own course, not the whole cohort, using `narrowScopeToCourse`. That covers grading detail, draft grade, release, batch release, the queue, overrides and ticket submission links. The cohort grading summary lists only assessments the grant covers. PROGRAMME and COHORT grants are unchanged.
- **F-09 — baseline headers.** The CSP sets `frame-ancestors 'none'; object-src 'none'; base-uri 'self'`. Also added: `X-Frame-Options: DENY`, `nosniff`, `strict-origin-when-cross-origin`, HSTS and a Permissions-Policy. `X-Powered-By` is removed. A full `script-src` CSP needs per-request nonces from the proxy, so it's a separate decision.
- **F-11 — contested registrations.** A second registration for a still-unverified email wipes the stored password. Verifying such an account sends the verifier to "Set your password" with a fresh reset token. Verification emails now tell anyone who didn't register to ignore them.
- **Verified:** full suite 279 files and 3,812 tests passed (1 skipped); `tsc` and `eslint` clean. Not pushed.

### Batch 5, fixed 2026-09-27

- **F-04: cohort publish race.** Publishing a cohort, removing a cohort instructor and cancelling a session now take the cohort row lock (`lockCohort`) before they re-read readiness. So a concurrent change waits, then is seen. Integration tests hold the lock from outside and prove each operation waited. The publish test archives the course while publish is waiting, and publish then refuses.
- **F-03: reconciliation starvation.** When a payment row fails reconciliation, the failure is recorded (`reconcileAttempts`) and the row's next try is pushed back (`nextReconcileAt`): 15 minutes, doubling each time, capped at 24 hours. So failing rows can no longer fill the batch. On the 5th failure the row is escalated as a `MISSING_PROVIDER_DATA` reconciliation case. Settlement columns are still never partly written. Migration: `20260927140000_reconcile_backoff`.
- **F-15: quiz answers.** An `ON_RELEASE` quiz now holds back the correct answers and explanations until its window closes. With no closing date, they're held until the learner has no attempts left; with unlimited attempts and no closing date, they're never shown. Learners still see their score and a right/wrong mark for each question. The answers are stripped on the server, so they aren't in the page payload either. `NEVER` shows no per-question detail at all, and `IMMEDIATE` is unchanged.
- **F-15: video completion.** Staff can set an optional **Video length** on a VIDEO lesson. When it's set, the server works out the 90% threshold from that length, not from the length the player reports. Without it, the longest length ever reported is kept, so a later tick can't shrink it. Credit is also paced: at most 2× the time since the learner's first tick, plus 30 s of grace, so jumping to the end gives no credit. Migration: `20260927150000_video_watch_pacing`. Existing watch rows are backdated so learners part-way through a video aren't held back.
- **F-10: docker-compose.**
  - Postgres and the MinIO console are published on `127.0.0.1` only.
  - The MinIO S3 port's bind address is configurable with `MINIO_BIND_ADDRESS` (default `127.0.0.1`), because browsers must be able to reach presigned URLs.
  - The app container no longer receives the MinIO root credentials or the Postgres variables. `minio-init` creates the app's own MinIO user with a policy limited to object read, write and delete in the one bucket. It refuses to run if `S3_ACCESS_KEY_ID` is the root user.
  - This was checked live: the app user can put, get and delete objects, but can't create buckets or use admin calls.
  - A one-shot `migrate` service runs `prisma migrate deploy` before the app starts, which closes the "never migrates" gap in section 7.
  - **Action for existing installs:** set `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` in `.env` to values different from the MinIO root user.

## 3. Integration warnings

All worked through 2026-09-27 (decisions: scope-aware nav, refund revokes access, live certificate blocks exits).

- ✓ **Scoped staff can't find their work.** Cohorts, Enrolments and Payments now appear in the sidebar for a grant at any scope, and their lists filter to the caller's scope in the query itself (a GLOBAL grant still sees everything; no grant is refused). The Overview's figures and work queue are filtered the same way; submissions narrow a COURSE grant to the assessment's course (F-05's rule). Catalogue, certificates, support and admin sections still need a GLOBAL grant, as their pages do. (RBAC-04/05, ATT-01, ASM-05)
- ✓ **Paystack retry reuses `order.reference`.** Already fixed by F-02 (batch 2): each attempt sends `<order reference>-<attempt suffix>`. (PAY-03/11)
- ✓ **A refund's "revoke access" decision is stored but never acted on.** REVOKED now withdraws the learner's current enrolment (following transfers) once the provider refund succeeds, audited as `enrolment.withdrawn`. It is checked before any money moves, so a learner with a live certificate refuses the refund. A failed provider refund leaves access alone. (PAY-05/13)
- ✓ **A flagged certificate can outlive its enrolment.** Withdraw, cancel (single or whole-cohort) and transfer are refused while the enrolment holds an ACTIVE certificate, with a message naming it; staff with revoke permission decide the certificate first. (COH-05, CRD-05/06)
- ✓ **Completed learners lose their results.** Results stay readable after completion on the dashboard and at `/learn/[id]/results`; quizzes and assignments stay closed to new work (G-01, visible not operable). (ASM-07)
- ✓ **The "Flagged certificates" overview link ignores `?status=flagged`.** The issued list now starts on the filter in the URL. (CRD-06)
- ✓ **REQUIREMENTS.md traceability is out of date.** The IAM-03 note is corrected (password reset is built). Built phases' rows now read "Built — verification pending" rather than "Pending"; checkboxes are ticked only after formal verification (section 5).
- ✓ **Staff can't open a ticket's linked record** (SUP-05, from the integration report). Already fixed: the context resolver is in use.

## 7. Unused infrastructure (noted 2026-09-27)

The running local Docker stack includes containers that the current `docker-compose.yml` no longer defines. They're leftovers from an older version of the file, still running from old images. None of them has been removed; each one needs a decision.

| Container | What it is | Evidence it is unused |
|---|---|---|
| `learning-management-system-clamav-1` (`clamav/clamav:stable`) | Virus scanner for uploads | No code references ClamAV or scanning. Upload scanning was replaced by `uploadStatus` (migration `20260910120000_replace_scan_status_with_upload_status`), and uploads go straight to private storage through presigned URLs. |
| `learning-management-system-worker-1` | Background worker running `npx tsx worker/index.ts` | There's no `worker/` directory any more. Scheduled work (hold release, exports, reconciliation, ticket auto-close, upload clean-up) runs as Netlify scheduled functions under `netlify/functions`. |

To remove them: `docker compose up -d --remove-orphans` stops and deletes containers that aren't in the compose file. Volumes are untouched.

**Gap this exposes:** `docker-compose.yml` describes itself as the self-hosted deployment, but the scheduled jobs exist only as Netlify functions (`netlify/functions/`: `release-expired-holds`, `reconcile-payments`, `dispatch-export-jobs`, `process-export-jobs-background`, `expire-export-jobs`, `close-resolved-tickets`, `cleanup-stale-uploads`). A self-hosted Docker install therefore runs **none** of them:
- seat holds never release;
- large exports never process or expire;
- payments never reconcile;
- resolved tickets never auto-close;
- stale uploads are never cleaned up.

**Decided 2026-09-27: production is Netlify-only** (with Cloudflare R2), so the scheduled jobs run as Netlify functions and the Docker stack is for local use. No scheduler container is needed. Originally: before a self-hosted launch this would need a scheduler service in the compose file (for example a small cron container calling the `src/server/scheduled/*-task.ts` entry points), or a decision that production is Netlify-only.

**Second gap (closed by F-10, 2026-09-27): the Docker stack never migrated the database.** The image's command is just `next start`, and nothing in `docker-compose.yml` runs `prisma migrate deploy`. On 2026-09-27 the local Docker database had only 6 of 18 migrations applied (last: `20260905003936`), so every feature built since 5 September would have failed there. A self-hosted install needs a migrate step, for example a one-shot `migrate` service that the app `depends_on`, or a migrate-then-start entrypoint.
